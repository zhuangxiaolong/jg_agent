# 精工 Agent 0.9.3 专业能力体系交付验证

2026-11-21，目标分支 `develop/desktop-poc`。源码基线为 `4c6f688`，版本号已是 0.9.3，数据库为 v17。基线已调整自动子任务策略，与设计文档引用的 0.9.2 行为有差异。本次使用当前分支的 Runtime 和任务治理实现。

## 运行路径

```text
本轮用户输入、项目系统、会话选择
  → 本地确定性路由（工程研发或项目交付 → 岗位或家族通用视角）
  → 角色工作流、产品范围、现有知识候选、可用 Skill 元数据
  → getRuntime 中的共享会话上下文（含预算优化及兼容回退路径）
  → 当前会话的 Codex、精工、Claude 或 Grok 适配器
  → 当前轮次运行记录、来源定位和反馈
```

工程研发覆盖需求分析（范围和验收）、后端（事务、接口和验证）、前端（状态与交互）、全栈（两端契约与联调）、测试质量（覆盖与执行证据）。项目交付覆盖总监（组合经营与资源）、经理（计划与里程碑）、实施工程师（产品操作与现场排查）。家族锁定、岗位锁定、普通 Agent 和单轮显式角色均由本机解析；产品选择仅影响会话。

手册复用本地索引、版本冲突提示和实际切片定位。项目资料沿用项目上下文，字典复用当前会话可用的资料和只读工具。专业记录区分检索候选、字典实际读取和已加载 Skill；检索到的候选不能证明模型引用了它。精工 Runtime 的 Skill 标签进入现有 Matcher，实际加载仍检查会话范围、信任与兼容状态。专家层不创建子任务或工作区。

## 评测与使用

聊天输入框上方打开“专家设置”，选择自动路由或锁定岗位，设置独立的产品知识范围。发送任务后可展开对应运行，核对角色、原因、版本、来源与运行状态并评价回答。设置 → 专家中心支持复制档案、编辑工作流和指定默认专家。

设置 → 专家中心 → 评测工作台，选择案例与已配置模型的会话，运行普通 Agent 和专家对照。首批为根据需求场景编写的匿名样例，每条记录含产品、输入、预期岗位、关键点及参考说明。需求 8、后端 6、前端 5、全栈 4、总监 5、经理 5、实施 5、质量 2。普通组与专家组串行使用同一输入、模型、推理强度和资料快照，七项人工评分后可分岗位与配置查看或导出。

40/40 条本地角色路由断言通过。双组请求、结果持久化、人工评分和重启读回使用模型替身验证。40 条真实模型输出与人工业务评分均未执行，引用准确率、内容完整率及对普通 Agent 的提升待评审。四个聊天适配器的接入按源码与现有回归验证，未逐一连接真实中转站。受控对照目前支持 Codex 与精工 Runtime，Claude 与 Grok 仅支持普通会话中的专家功能。
