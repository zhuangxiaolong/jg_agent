## 1. 项目背景

精工 Agent 目前已经具备初步的本地记忆能力，但还不是一个完整的、可持续积累的记忆系统。

基于当前仓库代码与文档核对，现状如下：

1. 桌面主进程已有 `apps/desktop/src/main/session-memory.ts`，在会话完成后提取记忆。
2. 记忆已经保存在本机 SQLite 的 `memories` 表中，`LocalStore` 提供 `listMemories/saveMemory/deleteMemory`。
3. 设置页已经有“记忆”管理界面，支持查看、手动新增、删除、导入和导出。
4. 普通会话与 Agent 子任务已经会把记忆交给 `buildDeveloperContext()`，再通过 Runtime 的 `developerInstructions` 传入模型。
5. 项目上下文已经有独立的 `ProjectFact`、`ProjectDecision`、`ProjectResourceLink` 和 `ProjectContextSnapshot`，不应再重复造一套项目知识库。
6. 当前 `sessionMemories()` 主要按项目筛选最近记忆，相关性排序和上下文预算控制不足；`buildDeveloperContext()` 可能把较多记忆全部注入。
7. 当前自动记忆在没有提取到稳定偏好时，会回退保存本轮用户任务和模型回答。这会造成普通任务、未经核实的模型结论进入长期记忆；现有测试还覆盖了凭据样例进入记忆的情况。该行为必须在 0.8.1 修正。

因此，0.8.1 的目标不是新增一个简单的“记忆列表”，而是把现有能力升级成独立、模型无关、可治理、可检索、可控成本的 Memory Engine。

## 2. 产品目标

### 2.1 核心目标

让精工 Agent 在长期使用中逐步积累用户明确表达的偏好、工作习惯和稳定约束，并结合当前项目的事实、决策和已验证经验，在每次任务开始时选取真正相关的信息。

用户希望获得的长期效果：

- **越来越懂用户**：理解用户稳定的沟通偏好、工作习惯、技术选择和明确约束，不必在每次会话重复说明。
- **越来越懂项目**：知道当前项目使用什么技术栈、有哪些确认过的业务事实、技术决策和历史限制，不重复从头探索。
- **越来越会处理任务**：复用被确认或经构建/测试验证过的方法，减少重复试错。
- **整体任务效率逐步提高**：减少重复读取、重复解释和无关上下文，降低部分任务的总耗时和 Token 消耗。
- **模型无关**：切换 Codex、精工 Runtime、Claude、Grok 或中转站，不丢失本地记忆。

### 2.2 成功标准

0.8.1 完成后，应达到：

1. 用户在新会话中不再重复说明已保存的稳定偏好，Agent 能正确参考。
2. 同一项目切换会话或 Runtime 后，仍能读取该项目确认过的事实与决策。
3. 不同项目之间严格隔离项目记忆，不发生跨项目上下文污染。
4. 自动记忆只保留有复用价值、来源明确的用户信息，不保存整段聊天、模型回答或普通任务内容。
5. 记忆检索不依赖模型 API，不增加一次额外推理请求。
6. 记忆注入有固定预算，不能因为记忆数量增加而无限扩大 Prompt。
7. 用户能查看、编辑、删除、停用和导入/导出记忆，并能控制自动学习。

### 2.3 对“越来越聪明、越来越快”的准确边界

Memory Engine 不训练 GPT，也不改变底层模型参数，因此不能承诺模型本身智力持续增长，也不能改变中转站线路、模型 TTFT 或 Token/s。

它能提高的是 Agent 的系统级表现：减少重复背景调查、上下文准备、重复试错和无关输入，使部分任务更快、更稳定。具体提升必须通过同类任务的基准测试验证，不得在产品文案中承诺“每次一定更快”。

6. 不改变现有 Codex Runtime、精工 Runtime、Claude SDK、Grok ACP 的执行协议与任务权限。
7. 不重构现有项目知识模块；项目事实和决策继续使用现有项目上下文能力。

## 4. 记忆分层与职责

采用三层结构，职责不能混淆。

### 4.1 第一层：用户长期记忆（User Memory）

跨项目生效，记录用户明确表达、长期有效且可以复用的信息。

允许类别：

- `preference`：表达偏好，例如回答风格、语言、内容组织方式。
- `working_style`：工作习惯，例如先核对仓库现状、先给结论、偏好可执行方案。
- `constraint`：稳定约束，例如技术选型边界、禁止事项、预算或交付边界。
- `tool_preference`：工具选择偏好，例如指定开发 Runtime、模型调用方式。
- `role_context`：用户主动明确的工作职责与长期工作背景。
- `reusable_experience`：跨项目可复用、来源经过用户确认或验证的经验。
- `other`：其他明确要求长期保留的信息。

用户全局记忆不应包含单一客户项目的临时数据、未确认假设、客户密码、API Key、数据库连接串等。

### 4.2 第二层：项目记忆（Project Knowledge）

复用当前仓库已有的项目上下文模块：

- `ProjectWorkspaceContext`
- `ProjectFact`
- `ProjectDecision`
- `ProjectResourceLink`
- `ProjectContextSnapshot`

项目级事实和决策继续通过现有项目上下文界面与数据表管理。不得把这些信息重复复制成全局用户记忆。

每次开发任务只加载当前 `projectId` 对应的有效事实、决策和关联资料。项目 A 的事实不能进入项目 B 的上下文。

### 4.3 第三层：会话工作上下文（Session Context）

当前会话的聊天历史、当前任务、附件、Jira 内容和工具执行结果属于短期工作上下文，不是长期记忆。

会话结束后可以生成会话标题、任务摘要或验证记录，但不能自动把整段任务和模型答复保存为长期记忆。

只有满足长期记忆提取规则的信息，才进入 User Memory；项目事实和决策按现有项目模块写入。

## 5. 自动学习规则

### 5.1 触发时机

- 仅在一次会话任务正常完成后执行自动记忆候选提取。
- `failed`、`interrupted`、取消、运行中和无用户输入的任务不得自动产生长期记忆。
- 提取过程不得阻塞主会话 UI，不得额外调用模型 API。
- 当前会话的自动提取必须准确限定在本轮用户消息，不得把会话全部历史重复处理。

### 5.2 可以提取的表达

高置信度触发词或明确语义：

- “记住：……”、“请长期记住……”
- “以后都……”、“今后……”、“后续统一……”
- “每次都……”、“始终……”、“默认……”
- 用户清晰陈述的长期职责、固定技术约束和稳定偏好。
- 用户明确纠正旧规则，例如“之前那条规则已经变更，以后改为……”。

普通的“帮我分析一下”“这次项目使用……”等任务描述不是长期记忆。

### 5.3 不能提取的内容

- 模型回答、模型推断、模型建议、模型自己总结的用户属性。
- 普通任务指令、临时安排、当前轮待办事项。
- 引用内容、Markdown 代码块、附件正文、粘贴的客户资料和日志。
- 假设、问题、建议、尚待确认或待验证的信息。
- 密码、Token、API Key、连接字符串、私钥、Cookie、认证头等凭据。
- 健康、宗教、政治、性取向等敏感个人属性，不得由自动学习推断或保存。
- 任何缺少清晰来源或语义不确定的信息。

### 5.4 置信度与状态

- `active`：来源明确、表达明确，可直接参与检索。
- `pending_review`：可能有复用价值但置信度不足，默认不注入模型。
- `superseded`：被用户明确更新的新记忆替代，不再注入。
- `archived`：用户停用，保留记录但不注入。
- `blocked_sensitive`：检测到敏感凭据或高风险内容，不允许注入和默认导出。

自动提取只允许高置信度规则直接创建 `active`。中低置信度候选可以进入待复核列表，不能自动变成生效记忆。用户明确说“记住”可将清晰内容直接创建为 `active`，但凭据扫描仍必须通过。

### 5.5 冲突处理

1. 完全重复：合并到同一条记忆，更新 `updatedAt` 和证据引用，不新增重复行。
2. 明确纠正：若用户表达“之前错误/改为/不再适用”，将旧记忆标记为 `superseded`，新增或更新新记忆，并保留关联关系。
3. 可能冲突但无法确认：进入 `pending_review`，不能直接覆盖旧记忆。
4. 当前用户本轮明确指令始终高于历史记忆。历史记忆不得否定用户本轮的新要求。

## 6. 记忆检索与上下文注入

### 6.1 检索时机

在每次新任务提交前，根据以下内容构造本轮检索条件：

- 当前用户输入（去除附件正文与代码块后用于关键词提取）。
- 当前项目 ID、系统类型和项目版本（若存在）。
- 当前 Runtime、模型及任务类型（仅作为排序条件，不作为权限来源）。
- 当前已启用的用户长期记忆、项目事实和项目决策。

### 6.2 检索原则

- 全局记忆只在用户全局作用域中读取。
- 项目资料只读取当前项目有效内容。
- 待复核、归档、被替代、敏感拦截的记忆不参与注入。
- 不相关的记忆不因为“最近”就自动注入。
- 用户偏好可作为少量基础上下文；其他记忆必须与当前任务相关。
- 不同 Runtime 不允许自行实现不同的记忆策略。

### 6.3 上下文预算

初始预算建议：

| 内容 | 建议最大字符数 |
|---|---:|
| 用户稳定偏好与工作方式 | 2,000 |
| 与当前任务相关的用户约束/工具偏好 | 2,000 |
| 当前项目事实与决策 | 5,000 |
| 跨项目已验证经验 | 1,000 |
| **合计** | **10,000** |

- 预算按字符数计算，作为初版可复现的控制指标。
- 单轮最多注入 20 条记忆记录；同一类按相关性排序。
- 不得静默截断单条记忆正文；超预算时整条跳过，并在检索诊断中标记原因。
- 现有强制开发要求和数据字典的预算机制保持原样，不得被记忆预算挤占或删减。
- 所有记忆必须被明确标记为“参考上下文”，不得覆盖系统规则、开发规范和用户本轮指令。

## 7. 用户交互需求

### 7.1 设置页记忆管理

保留当前“设置 > 记忆”入口，升级为记忆中心。

列表至少展示：

- 标题与内容摘要。
- 记忆类别。
- 作用域（全局/项目名称）。
- 来源（用户明确表达/手动新增/历史导入/验证经验）。
- 状态（生效/待复核/已替代/已归档/敏感拦截）。
- 创建时间、最近更新时间。

支持：

- 搜索、按类别/作用域/状态筛选。
- 新增、编辑、删除、停用、恢复生效。
- 查看来源证据（会话和消息定位；若来源已不存在，展示来源不可用）。
- 查看最近一次注入状态。
- 导出、导入记忆；导出前再执行敏感内容检查。

### 7.2 自动学习控制

增加设置项：

- 自动学习：开/关，默认开（与当前已有自动记忆功能兼容）。
- 全局记忆注入：开/关，默认开。
- 项目上下文注入：开/关，默认开；不替代现有项目上下文的独立启用状态。

关闭自动学习只停止新增自动记忆，不删除历史记忆；关闭注入只停止把对应范围的记忆发给模型，不删除本地数据。

### 7.3 明确记忆操作

支持用户在对话中用自然语言明确提出“记住：……”生成记忆候选。设置页中可确认候选、编辑内容和作用域。

本期不要求增加复杂的消息气泡按钮；可以先通过文本约定和设置页管理实现。

## 8. 安全与隐私要求

1. 记忆数据默认只保存在 `%LOCALAPPDATA%\\JinggongAgent` 下的本机 SQLite。
2. 不得把 Memory Engine 数据上传到独立云端服务。
3. 任何记忆在自动保存、手动保存、导入、导出和注入前都必须经过统一安全检查。
4. 严禁持久化或注入明显的 API Key、Bearer Token、密码、Cookie、私钥、连接串等凭据。
5. 发现敏感内容时，不能只在 UI 隐藏；检索层必须拒绝注入，日志不能写入原文。
6. 自动提取必须只处理用户消息，不处理模型输出。
7. 引用、代码块和附件不作为记忆来源。
8. 记忆正文作为数据参考，不具备覆盖系统提示、开发规则或当前任务的指令优先级。
9. 删除操作应同时清理对应记忆的检索缓存；不得在缓存中继续注入已删除记忆。
10. 分享导出默认不带凭据；无法确认安全的记录应跳过并向用户说明数量。

## 9. 性能需求

- 记忆提取与检索必须是本地操作，不调用模型 API。
- 以 500 条记忆作为本期性能目标数据规模。
- 500 条记忆的典型本地检索耗时目标：P95 不超过 50 ms（开发机基准，单次检索，不含 SQLite 首次初始化）。
- 记忆上下文最多 10,000 字符，正常情况下建议低于 6,000 字符。
- 记忆增加后，模型输入上下文大小不能随记忆总量线性增长。
- 记忆管理 UI 不允许每次输入检索都全量刷新整个应用。
- 不使用向量计算或网络请求作为本期记忆检索前置条件。

## 10. 验收标准

### 10.1 自动学习

- 用户说“以后回答先给结论，再给分析”，完成会话后能生成一条全局 `preference/working_style` 记忆。
- 用户说“帮我检查一下这个 SQL”，不得产生长期记忆。
- 用户只提出问题或假设，不得生成长期记忆。
- 模型回答中出现“用户喜欢……”不得生成用户记忆。
- 代码块、附件、引用文本中的“记住”不得触发记忆。
- 没有有效记忆候选时，记忆条数不增加。
- 失败和中断的会话不生成自动记忆。

### 10.2 安全

- `password=...`、`Bearer ...`、常见 API Key、连接字符串和私钥样例不得进入生效记忆。
- 旧自动记忆包含敏感内容时，不能注入模型。
- 删除记忆后下一次任务立即不再注入。
- 导出时对敏感记忆阻止导出或脱敏，并有可理解提示。

### 10.3 检索与隔离

- 全局偏好能跨项目生效。
- 项目 A 的事实和决策不得进入项目 B 会话。
- 与当前任务无关的记忆不应大量注入。
- Codex、精工 Runtime、Claude、Grok 同一任务检索结果应一致（允许各 Runtime 在协议层封装不同，但内容与边界一致）。
- 记忆预算超限时整条跳过，不破坏强制开发要求和数据字典注入。

### 10.4 可管理性

- 用户可编辑、删除、停用和恢复记忆。
- 自动学习关闭后不再自动新增记忆，手动记忆功能仍可使用。
- 旧版本数据库升级后，原有项目、会话、附件、凭据和记忆不丢失。

### 10.5 性能

- 用 500 条随机生成的本地测试记忆进行基准，检索 P95 ≤ 50 ms。
