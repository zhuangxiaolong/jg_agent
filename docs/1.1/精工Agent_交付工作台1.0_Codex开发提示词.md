# Codex 开发提示词：精工 Agent 交付工作台 1.0

你现在负责在精工 Agent 现有代码库中实现“交付工作台 1.0”。请严格按照以下要求执行，不要只输出建议或示例代码，要在当前仓库中完成可运行的代码修改、测试和验证。

## 一、开始前必须读取的资料

1. 仓库根目录 `AGENTS.md`。
2. 仓库根目录 `README.md` 和 `package.json`。
3. 完整阅读本需求文档：`精工Agent_交付工作台1.0_需求规格说明.md`。
4. 完整阅读本技术文档：`精工Agent_交付工作台1.0_技术方案.md`。
5. 检查当前 Git 分支、HEAD、`git status` 和未提交改动。
6. 检查现有 `Project`、`ProjectWorkspaceContext`、`DeliveryPanel`、`delivery-ipc.ts`、`iteration-ipc.ts`、`LocalStore`、Preload `DesktopApi`、`App.tsx` 导航、`MappingJob` 和现有 Runtime/Session 创建发送流程。
7. 对准备修改的每一类代码，先检查至少 2–3 个最接近的同类实现，遵循仓库当前写法。

目标分支预期为 `develop/desktop-poc`。如果当前分支不同，不要擅自切换分支；先报告当前分支并基于用户当前工作区继续，除非切换会造成数据或代码风险。

## 二、任务目标

新增一个独立一级入口“交付工作台”，面向 MES5/MES6/WMS 项目经理、实施工程师和交付负责人。实现客户交付项目管理、项目执行数据、风险巡检和 AI 草稿辅助。

必须坚持：

- 现有开发工作台继续正常工作，不要用交付工作台替换它。
- 现有 `Project` 是本地 Git 代码项目，不是客户交付项目。新增独立 `DeliveryProject` 领域和独立存储，不能混用 ID 语义。
- 现有 `delivery:*` IPC 和 `window.jinggong.delivery` 是研发交付证据包能力。新功能用 `delivery-workbench:*` IPC 和 `window.jinggong.deliveryWorkbench`，不得覆盖或改坏旧 API。
- 复用现有 LocalStore SQLite、Migration、Zod、Electron IPC、Preload、React 组件、主题样式和现有 Runtime/Knowledge/Mapping 能力。
- 不要新建模型中转配置，不要直接调用 OpenAI/Claude/Gemini HTTP API，不要重新实现 Agent Runtime。
- 不要重新开发 Excel 解析和字段映射引擎，复用当前 `packages/second-iteration` 的能力。
- 不要重新建设 MES/WMS 产品手册知识库，复用当前 `operation-manuals` / `knowledge`。
- 1.0 是本机 Windows 单机工作台。不要声称支持多台电脑实时共享，不要把 SQLite 放在 NAS/共享盘做并发写入。
- AI 输出不得未经用户确认直接修改任务、里程碑、问题或项目事实。

## 三、开发执行方式

### 第一步：现状盘点和实施计划

先检查当前工作区实际代码，重点确认：

1. `SCHEMA_VERSION` 当前值，以及迁移链是否已有更高版本；技术文档基线为 21，但以当前代码为准。
2. `LocalStore` 当前的 table、迁移事务、自动备份、序列化和查询方法风格。
3. `DesktopApi` 类型定义与 Preload bridge 如何新增命名空间。
4. `App.tsx` 的一级入口/导航和页面切换状态如何组织。
5. Runtime 当前是否支持无本地代码仓库的独立会话、Agent Task 和只读上下文；不能为了 AI 把客户交付项目绑定到无关 Git 项目。
6. MappingJob 当前 `projectId` 的实际语义，不能把 DeliveryProject ID 错填到代码 Project ID。
7. 文件导入和文档读取现有安全边界。

先形成一个简短实施清单（写到 `docs/交付工作台1.0-实施记录.md` 或合适文档位置），明确每个阶段修改哪些文件、对应测试是什么。盘点完成后立即实施，不要停下来等待用户确认；遇到真正会破坏数据或需要产品决定的风险时，选择最保守且兼容的方案，并在最终报告中说明。

### 第二步：先完成领域和数据底座

1. 在 `packages/domain` 新增独立交付工作台实体和 API 类型。
2. 至少实现 DeliveryProject、Milestone、Task、Issue/Risk、Meeting、Document、Report、Activity、SourceRef 等类型。
3. 在纯领域模块中实现字段校验、状态流转、逾期统计、项目健康规则和上下文哈希等可单测函数。
4. Store 新增交付项目表和必要索引；数据库版本使用当前版本 + 1，不得覆盖已有 migration version。
5. 沿用现有迁移前备份流程；迁移事务失败必须回滚，不得损坏旧数据。
6. 增加 CRUD、列表筛选和活动日志 Store 方法；Activity 采用追加式记录。
7. 不开放普通用户直接物理删除项目；项目归档优先。

### 第三步：主进程 API 与安全

1. 新增 `delivery-workbench:*` IPC 注册模块。
2. 新增 Preload `window.jinggong.deliveryWorkbench`，类型从 domain 引用。
3. 所有 IPC 使用 Zod 严格校验。
4. 主进程对每条子记录验证 `deliveryProjectId` 归属；跨项目 task/milestone/issue/meeting 关联必须拒绝。
5. 资料导入必须由主进程打开文件选择器；文件复制到应用管理目录；保存 SHA256、大小、类别和相对路径。
6. 严格处理路径穿越、符号链接、受管目录边界、文件大小、文件哈希变化。
7. 每个写入与项目动态日志应保证一致性；优先同一数据库事务完成。
8. API 不返回不必要的绝对路径、密钥或凭据。

### 第四步：Renderer 交付工作台

至少实现以下可用页面，不允许只放一个静态首页或一堆不能点击的按钮：

1. 交付总览：进行中项目、逾期任务、高优先级未关闭问题、临近/逾期里程碑、需关注项目、最近动态。
2. 项目列表：搜索、筛选、新建、编辑、归档。
3. 项目概览：基本信息、执行状态、风险项、里程碑、任务、最近动态。
4. 项目任务/里程碑列表：新增、编辑、状态变更、筛选。
5. 问题与风险：新增、编辑、优先级、状态和责任人。
6. 会议记录：新增和查看 Markdown 纪要。
7. 项目资料：导入、类别、校验、打开/定位。
8. 报告/AI 助手：生成周报和风险摘要草稿、编辑、保存、导出 Markdown。

界面应沿用现有精工 Agent 的主题、字号、按钮、输入框、弹窗和布局风格，保持桌面端信息层级。不能把所有功能塞进单个超长页面。现有开发工作台、Inspector 和 DeliveryPanel 不得回归。

### 第五步：AI 功能接入

1. 周报和风险摘要必须复用当前 Runtime/Session/Agent 执行流程。
2. 如果现有 Session 强制绑定本地代码 Project 或具有过宽文件权限，优先实现受限的交付项目临时上下文/只读会话；不得把客户项目冒充代码项目，也不得给 AI 任意本机文件访问权限。
3. 先实现确定性项目数据快照和哈希，再将其交给现有 Runtime。
4. 周报按指定时间范围筛选数据。若无历史变更流水，必须说明无法还原过去状态，不能猜测周期内完成了什么。
5. 模型输出必须区分事实、规则风险、AI 建议和数据不足。
6. 任务/计划/会议行动项等结构化建议必须进入待确认草稿；只有用户明确勾选和确认后才能入库。
7. 草稿确认前重新检查项目及来源快照是否变化；变化则要求重新生成或重新确认。
8. 生成失败、Runtime 不可用、模型返回无法解析时，显示清楚错误，不要用静态假数据兜底冒充 AI 成功。

如果某项 AI 接入必须重构现有 Runtime 才能实现，先完成项目管理 P0 功能，保留清晰的 AI API 接口和明确的未完成状态，不要为了追求 AI 演示而破坏 Runtime。

### 第六步：复用既有能力

1. 从项目工作区提供现有 Excel 数据映射工作流入口，预填系统类型和可用版本信息。
2. 如果现有 `MappingJob.projectId` 指向本地代码项目，不能传入交付项目 ID；采用独立 `deliveryProjectId` 关联或保存映射产物关联记录。
3. 操作手册问答优先调用已有 `operation-manuals`/`knowledge` 管道，回答展示原始依据；找不到依据要明确说不知道。
4. Jira 只保留项目关联字段/链接，除非现有 API 已有明确能力且本任务需求明确，不要扩展双向同步。
5. 现有开发交付 ZIP/Jira 回写功能保持原样。

- 项目总览和详情。

不得将 P1 静态占位伪装成已实现。

## 五、测试与质量要求

新增测试至少覆盖：

- Domain 校验、状态转换、风险规则、统计口径、日期时区边界。
- Store 迁移、CRUD、关联约束、事务回滚、归档保留数据。
- IPC 错误项目归属、非法入参、错误引用、路径穿越、文件哈希不匹配、AI draft 过期。
- UI 项目创建、任务编辑、问题流转、报告保存等关键流程。

完成后执行：

```powershell
npm run build
npm test
npm run test:desktop
```

如某个命令因环境缺少依赖或 Windows 专属条件无法运行，必须写明真实原因和未执行范围，不得报告为通过。修复本任务引起的测试失败，不要随意修改无关测试去消除失败。
