# 精工 Agent 交付工作台 1.0 需求规格说明

> 文档类型：产品需求规格说明（PRD）  
> 产品：精工 Agent Windows 桌面端  
> 版本：1.0.0  
> 状态：待开发  
> 适用分支：`develop/desktop-poc`  
> 编写日期：2026-11-24

---

## 1. 项目背景

精工 Agent 当前主要围绕研发人员的开发工作设计，已具备多 Runtime 会话、专家中心、Jira 任务处理、Git 变更分析、代码验证、产品操作手册知识库、项目资料上下文、数据字典及 Excel 字段映射转换等能力。

但 MES/WMS 项目交付工作还包含大量非开发任务：项目启动、实施计划、里程碑跟踪、客户会议、任务分派、现场问题处理、风险识别、周报、上线准备、验收资料准备等。项目经理和实施工程师目前仍需在 Excel、Word、Jira、聊天记录和本地文件之间切换，项目资料与执行过程分散，重复整理较多。

本版本在不破坏现有研发工作台的前提下，新增独立的“交付工作台”，使项目经理和实施工程师也能在精工 Agent 中完成日常交付管理，并通过现有 Agent Runtime 和知识能力辅助整理、分析及生成交付成果。

## 2. 产品定位

**精工 Agent 交付工作台是面向 MES5、MES6、WMS 项目交付团队的项目执行与 AI 助手工作区。**

目标岗位：

- 项目经理：负责项目计划、里程碑、任务、问题、会议、周报和交付风险。
- 实施工程师：负责现场执行、问题记录、知识查询、基础数据准备、上线检查和进度反馈。
- 项目组长/交付负责人：查看项目组合状态、逾期事项和高优先级风险，开展项目巡检。

产品原则：

1. 项目交付数据有明确结构，不依赖聊天记录作为唯一数据源。
2. AI 帮助分析和起草，最终项目状态和正式记录由人员确认。
3. 尽可能复用精工 Agent 已有产品知识库、数据映射、Jira、任务和 Runtime 能力。
4. 新增“客户交付项目”领域，不将已有本地 Git 代码项目直接当作客户交付项目。
5. 所有 AI 结论应区分客观数据、规则判断和模型建议，并显示依据。

## 3. 1.0 目标与非目标

### 3.1 1.0 目标

| 目标 | 说明 | 验收方式 |
|---|---|---|
| 建立客户交付项目台账 | 可独立创建和管理客户 MES/WMS 项目 | 可新增、编辑、归档、搜索项目 |
| 结构化管理执行过程 | 统一管理里程碑、任务、问题/风险、会议纪要和项目资料 | 数据可保存、查询、编辑并按项目隔离 |
| 支持项目经理常用工作 | 生成项目周报、项目风险摘要和实施计划草稿 | AI 输出可编辑、可保存，引用数据可追溯 |
| 支持实施工程师常用工作 | 项目知识入口、现场问题记录、Excel 数据转换入口、上线检查清单 | 能从项目工作区进入现有能力，不重复造轮子 |
| 建立交付过程留痕 | 关键新增、修改、状态变更有活动记录 | 活动记录可按项目查看 |
| 不影响现有研发能力 | 现有会话、专家中心、Jira、数据字典、交付证据包功能正常 | 现有构建、测试和桌面冒烟通过 |

### 3.2 1.0 非目标

以下事项不纳入 1.0，避免一次性扩大范围：

- 不建设云端服务端、中心化数据库或跨电脑实时协同。
- 不把本机 SQLite 数据库放到 NAS/共享盘上做多用户并发写入。
- 不建设完整 ERP/CRM、工时薪酬、项目成本核算或利润核算系统。
- 不实现完整甘特图、自动资源排程或复杂项目组合投资管理。
- 不做 Jira 与交付台账的全面双向同步；1.0 可保留 Jira Key/链接作为关联信息，具体同步另行评估。
- 不重新开发 Excel 解析、字段映射、数据校验和导出引擎，复用现有映射工作流。
- 不重复建设 MES5/MES6/WMS 操作手册知识库或新的向量检索系统。
- 不允许 AI 未经确认自动变更项目计划、任务负责人、问题状态或客户承诺。
- 不允许 AI 自动操作客户生产环境 MES/WMS。
- 不在 1.0 引入复杂的组织、部门、角色授权体系；当前桌面应用缺少可信的企业统一身份与远程授权基础。

## 4. 关键边界和数据概念

### 4.1 两类“项目”必须分开

当前系统的 `Project` 是本地代码仓库项目，包含仓库路径、分支等研发上下文。新工作台的“客户交付项目”是交付管理对象，包含客户、产品系统、项目经理、实施周期、里程碑、任务和问题。

两者不能共用同一个实体或通过重命名混淆。未来如需要，可为客户交付项目增加可选的本地代码项目关联字段，但两者的生命周期、数据权限和用途仍然独立。

### 4.2 角色模式不等于身份权限

1.0 可提供“项目经理视图”“实施工程师视图”“交付负责人视图”作为快捷工作入口和页面布局预设。

当前为本机应用中的个人工作区，不具备可信的组织身份认证和跨设备授权能力。因此不能把视图预设宣传成真正的数据权限控制。负责人、责任人等字段先使用姓名/显示名文本；不要伪造用户账号体系。

### 4.3 本地数据边界

1.0 项目数据默认保存在当前 Windows 用户的精工 Agent 本地数据目录和 SQLite 数据库。不同电脑之间不会自动同步。多电脑共同维护同一项目，需要后续建设服务端 API、中心数据库、身份认证、权限、冲突处理和审计同步机制。

## 5. 信息架构与入口

在现有桌面端增加独立一级入口“交付工作台”，不替换当前研发会话工作区。

建议页面结构：

```text
精工 Agent
├── 开发工作台（现有）
├── 交付工作台（新增）
│   ├── 交付总览
│   ├── 项目列表
│   └── 项目详情
│       ├── 项目概览
│       ├── 里程碑与任务
│       ├── 问题与风险
│       ├── 会议与项目动态
│       ├── 项目资料
│       └── AI 助手
├── 专家中心（现有）
├── 知识/操作手册（现有）
└── 设置（现有）
```

### 5.1 交付总览

显示：

- 当前项目总数、进行中项目数、已归档项目数。
- 未完成任务数、逾期任务数。
- 未关闭高优先级问题/风险数。
- 临近/逾期里程碑数。
- 最近项目动态。
- “新建项目”“查看全部项目”“生成项目周报”等快捷操作。

统计口径必须在 UI 中可解释：

- 未完成任务：状态不属于 `completed`、`cancelled` 的任务。
- 逾期任务：未完成且 `dueDate` 早于本地当天日期的任务。
- 未关闭高优先级问题：状态不属于 `resolved`、`closed`，优先级为 `critical` 或 `high` 的问题/风险。
- 临近里程碑：未完成且计划日期在未来 7 个自然日内；逾期里程碑单独统计。
- 无数据或关键日期缺失时显示“数据不足”，不得按 0 风险解释。

### 5.2 项目列表

支持：

- 新建、编辑、归档、查看项目。
- 按客户名称、项目名称、项目编码搜索。
- 按系统类型、阶段、状态、项目经理筛选。
- 按最近更新、计划结束日期排序。
- 列表显示项目名称、客户、系统类型、阶段、项目经理、计划结束日期、风险提示、最近更新时间。

归档不等于删除。1.0 不提供一键物理删除项目及全部关联数据的入口；可后续按数据治理需求增加二次确认的删除功能。

### 5.3 项目概览

项目首页展示：

- 项目基本信息和项目描述。
- 项目阶段和执行状态。
- 项目经理、核心成员（姓名列表）。
- 计划开始/结束日期。
- 里程碑完成情况。
- 任务完成、待办、逾期情况。
- 未关闭问题与风险。
- 最近会议纪要、项目动态。
- AI 风险摘要和下一步建议（有数据后才展示）。

## 6. 功能需求

优先级说明：P0 为 1.0 必须交付；P1 为 1.0 内有余力交付，或允许在小迭代中补齐；P2 为后续版本。

### 6.1 项目基础管理（P0）

**FR-001 新建交付项目**

字段：

| 字段 | 必填 | 规则 |
|---|---:|---|
| 项目名称 | 是 | 1–160 字 |
| 项目编码 | 否 | 1–80 字；同一数据库内不允许重复（忽略大小写） |
| 客户名称 | 是 | 1–160 字 |
| 系统类型 | 是 | MES5 / MES6 / WMS / OTHER |
| 产品版本 | 否 | 可输入多个版本/模块标签 |
| 当前阶段 | 是 | 售前移交、启动、调研、蓝图、开发配置、联调测试、上线准备、试运行、验收、质保、已归档；允许扩展但需保留原值 |
| 项目状态 | 是 | active / on_hold / completed / archived |
| 项目经理 | 否 | 显示名，不关联系统账号 |
| 项目成员 | 否 | 显示名数组 |
| 计划开始日期 | 否 | `YYYY-MM-DD` |
| 计划结束日期 | 否 | `YYYY-MM-DD`，不能早于计划开始日期 |
| 项目描述/范围 | 否 | 最多 8,000 字 |
| Jira Key | 否 | 校验基础格式，不在 1.0 自动同步 |
| 关联本地代码项目 | 否 | 可选，仅能引用已有本地 Project ID |

**FR-002 编辑项目**

允许修改项目基本字段。关键字段变更应写入项目动态记录，至少记录变更字段、变更前后值、时间和操作者显示名（未登录时使用“本机用户”）。

**FR-003 归档项目**

归档后默认不出现在“进行中项目”列表，但仍可查看和导出。归档不删除任务、问题、资料、会议或报告。

**FR-004 项目详情**

项目所有子记录都必须以 `deliveryProjectId` 归属一个交付项目。读取、修改、删除子记录前，主进程必须确认该记录属于当前项目。

### 6.2 里程碑管理（P0）

**FR-010 里程碑 CRUD**

字段：名称、说明、排序序号、计划日期、实际完成日期、负责人显示名、状态、创建/更新时间。

状态：`not_started`、`in_progress`、`completed`、`blocked`、`cancelled`。

规则：

- 支持手动新增、编辑、调整顺序。
- 完成状态需要记录实际完成日期；如用户未填写，可在明确点击完成时自动填入当天日期，仍可编辑。
- 计划日期已过且未完成时标为逾期，不自动修改状态。
- 可将任务关联到里程碑；删除里程碑时不得级联删除任务，应清空任务关联并记录活动。

### 6.3 任务管理（P0）

**FR-020 任务 CRUD**

字段：任务标题、详细描述、所属阶段/里程碑、负责人显示名、优先级、状态、开始日期、截止日期、完成说明、创建时间、更新时间。

优先级：`low`、`medium`、`high`、`critical`。  
状态：`todo`、`in_progress`、`blocked`、`completed`、`cancelled`。

要求：

- 可从项目概览或任务列表快速新增任务。
- 支持按状态、负责人、优先级、逾期筛选。
- 支持编辑、完成、重新打开（完成任务重开时需二次确认）、取消。
- 截止日期过期只形成逾期标识，不得自动将任务设为失败。
- 任务负责人暂为自由文本，允许为空；风险规则需要识别未分配任务。
- 任务可关联会议记录、问题/风险和里程碑。
- 任务变更写入活动记录。

**FR-021 批量创建任务**

支持人工多行快速录入；AI 生成的任务必须先显示草稿和来源，用户勾选确认后才批量写入。

### 6.4 问题与风险管理（P0）

**FR-030 问题/风险记录**

类型：`issue`（一般问题）、`blocker`（阻塞）、`risk`（风险）、`question`（待确认）、`change`（需求变更）。

字段：标题、描述、类型、优先级、状态、负责人显示名、发现时间、计划解决日期、解决说明、缓解措施、来源引用。

优先级：`low`、`medium`、`high`、`critical`。  
状态：`open`、`in_progress`、`pending_customer`、`resolved`、`closed`。

要求：

- 支持新增、编辑、状态流转、筛选。
- 支持绑定任务、里程碑和会议记录。
- `pending_customer` 状态需可填写客户待确认事项。
- 关闭记录需要解决说明；如暂时无法要求必填，至少在 UI 提示并记录为空的情况。
- 逾期问题、Critical/High 未关闭问题在项目和总览中突出显示。
- AI 可以建议新增问题或风险，但需要人员确认后保存。

### 6.5 会议纪要与项目动态（P0/P1）

**FR-040 会议记录**（P0）

字段：会议主题、时间、参会人、会议内容/纪要、会议类型（内部/客户/现场/远程/其他）、关联里程碑或任务、创建人显示名。

支持手工录入和 Markdown 编辑。

**FR-041 会议纪要 AI 整理**（P1）

用户输入/粘贴原始会议记录后，可请求 AI 整理为：会议结论、客户确认事项、待办任务建议、风险/问题建议、待确认问题。

AI 结果必须在“待确认草稿”区域展示；用户可逐条编辑、勾选后保存。不得自动创建任务或更改项目事实。

**FR-042 项目动态记录**（P0）

自动记录项目、里程碑、任务、问题/风险、会议、资料和 AI 报告的创建及关键变更。动态仅追加，不允许普通界面直接编辑历史事件。禁止在动态日志中记录模型 API Key、访问令牌或原始敏感凭据。

### 6.6 项目资料（P0）

**FR-050 关联项目资料**

支持关联合同摘录、售前移交资料、需求文档、蓝图、操作说明、测试记录、上线材料、验收资料、其他文档。

要求：

- 文件通过 Electron 主进程原生文件选择器导入。
- 复制到应用管理的交付资料目录，数据库只保存元数据、相对路径、SHA256、大小、类型、文件名和导入时间。
- 不允许 Renderer 直接传入任意文件系统路径并由主进程无条件读取。
- 每个文件设置合理大小上限（建议单文件 50 MiB，文本解析上限遵循现有 `knowledge` 限制）。
- 打开或解析前校验文件仍存在、路径位于应用管理目录内、SHA256 与入库值一致。
- 文件变化时提示重新导入，不静默使用已变化版本。
- 支持按类别查看、打开文件所在位置、解除关联；解除关联默认只解除项目关系，不立即物理删除原文件。
- 解析文本可用于 AI 项目上下文，但只注入当前项目已关联且状态有效的资料。

### 6.7 AI 项目助手（P0/P1）

**FR-060 AI 项目上下文**（P0）

调用现有 Runtime/Agent 会话能力时，组装当前交付项目上下文：

- 项目基本信息、系统类型、版本、阶段、项目经理、范围。
- 当前有效里程碑和任务摘要。
- 未关闭问题/风险。
- 最近会议记录和项目动态（按上下文预算裁剪）。
- 当前项目已关联且 SHA256 校验有效的资料摘要。
- 可选的 MES5/MES6/WMS 操作手册知识结果及引用来源。

上下文需标记来源 ID、更新时间和内容摘要/哈希；过期、缺失或无法读取的资料必须显示警告。

**FR-061 项目周报生成**（P0）

输入：项目、报告周期开始日期和结束日期。  
AI 读取该周期内任务变化、里程碑变化、问题/风险、会议纪要、项目动态，并生成可编辑 Markdown 草稿，推荐结构：

1. 项目基本情况与本周总体状态。
2. 本周完成事项（引用任务/里程碑）。
3. 本周进行中事项。
4. 延期和阻塞事项（明确责任人、计划日期、当前状态）。
5. 风险与需客户协调事项。
6. 下周工作计划。
7. 需管理层协调事项。

缺少数据时必须明确标注“未记录/待补充”，不准编造完成事项、客户承诺或日期。

周报支持编辑、保存为草稿、重新生成（产生新版本而不是覆盖旧版）、复制 Markdown、导出 `.md` 文件。

**FR-062 项目风险巡检**（P0）

先基于规则计算客观风险，再让 AI 总结与提出建议。规则结果必须能展开查看具体记录。

默认风险规则（阈值应集中配置，避免散落在 UI 中）：

| 风险等级 | 触发条件 |
|---|---|
| 红色 | 存在未关闭 Critical 问题；或存在 Blocker 且未解除；或存在逾期里程碑 |
| 黄色 | 存在逾期 High 任务；或存在 7 天内到期但未完成的里程碑；或存在未关闭 High 问题；或存在超过 7 天未更新的进行中项目 |
| 绿色 | 具备足够的项目数据，且无红色/黄色规则触发 |
| 灰色/数据不足 | 关键计划日期、任务或里程碑数据缺失，无法可靠评价 |

规则说明：

- 红/黄/绿/灰为可解释的规则状态，不使用没有定义的“AI 评分 87 分”作为健康度。
- AI 可以补充语义风险判断，但需标记为“AI 建议/待确认”，不能直接改变规则计算结果。
- 每条风险必须包含来源记录、触发规则或模型判断依据、建议动作。
- 风险巡检结果可保存为报告，不自动更改任务、里程碑或风险状态。

**FR-063 项目计划草稿**（P1）

根据项目系统类型、项目范围、计划周期，生成标准实施阶段与里程碑/任务草稿。模板须为 MES/WMS 项目通用可配置模板，至少覆盖启动、调研、蓝图确认、系统配置/开发、测试联调、上线准备、试运行、验收交接等阶段。

- AI 生成内容只进入草稿。
- 用户确认后才新增里程碑和任务。
- 不允许 AI 虚构合同范围、天数、客户确认和完成状态。
- 用户可选择不使用 AI，手工建立计划。

### 6.8 实施工程师工作区（P0/P1）

**FR-070 实施快捷入口**（P0）

实施视图优先显示：我的任务（以负责人显示名匹配当前用户输入的显示名）、逾期任务、待客户确认问题、最近现场问题、项目资料、产品手册问答、Excel 数据转换、上线准备清单。

当前没有账号身份时，用户可在本机设置中输入自己的显示名用于过滤；该显示名不是身份凭证。

**FR-071 产品知识/操作手册问答**（P1）

从当前项目推断 MES5/MES6/WMS 产品范围，调用已有操作手册知识库/知识问答能力。回答需显示手册名称、版本、章节或原文片段来源。未找到证据时明确回答“现有知识库没有找到依据”，不得把模型常识伪装成精工产品事实。

**FR-072 Excel 数据转换快捷入口**（P0）

从项目工作区跳转或打开已有字段映射转换工作流，自动带入当前交付项目的系统类型及版本（若现有 MappingJob 支持）。

- 复用现有文件解析、模板匹配、字段映射、规则确认、数据校验、错误报告和 CSV/XLSX 导出能力。
- 不重新实现映射算法和 Excel 解析。
- 转换完成后可将本次转换记录作为项目资料/动态链接；不把客户源数据自动发送到外部服务，除非现有用户明确选择 AI 功能并知悉数据发送范围。

**FR-073 上线准备清单**（P1）

提供可配置检查项，例如基础资料、账号权限、业务流程、关键接口、设备/数采联调、打印标签、备份方案、培训、回退预案、试运行确认等。

- 检查项状态：未检查、通过、不通过、不适用。
- 需支持填写检查说明和证据资料引用。
- 不适用必须填写原因。
- AI 可根据项目资料生成检查建议，但不得代替实际检查。

### 6.9 项目报告与导出（P0）

**FR-080 报告管理**

周报、风险巡检、实施计划等报告统一保存版本，字段至少包括报告类型、周期、标题、正文、状态（draft/final）、来源快照哈希、生成时间、创建人显示名、模型/Runtime 元数据（仅非敏感标识）。

**FR-081 导出**

支持项目基础信息、任务、里程碑、问题/风险、会议记录、报告导出为 Markdown/JSON；项目备份包可作为 P1。

导出前展示包含数据范围和文件列表。客户资料如有包含/排除选项，应默认排除凭据、系统配置和不相关个人文件。

## 7. 主要用户流程

### 7.1 项目经理创建项目并建立计划

1. 打开交付工作台 → 新建项目。
2. 填写客户、项目名称、MES/WMS 类型、版本、项目经理、项目周期和范围。
3. 进入项目详情，选择“生成实施计划草稿”或手工增加里程碑。
4. 检查 AI 草稿，修订阶段、计划日期和负责人。
5. 勾选确认后创建里程碑和任务。
6. 项目概览显示计划和待办。

### 7.2 实施工程师处理现场问题

1. 从实施工程师视图进入目标项目。
2. 新增现场问题，填写现象、出现时间、影响范围、优先级和现场证据。
3. 使用“AI 辅助分析”生成排查建议，显示引用的操作手册/历史项目资料。
4. 实施人员按建议逐项排查，在问题记录中补充结果。
5. 如需开发处理，关联现有 Jira Key 或复制问题摘要到现有开发会话；不自动替代研发任务流。
6. 问题解决后填写解决说明并关闭。

### 7.3 项目经理生成周报

1. 选择项目及统计周期。
2. 系统汇总周期内任务、里程碑、问题、会议及动态数据。
3. AI 生成结构化周报草稿。
4. 用户核查数据、修改表达，确认缺失信息。
5. 保存周报版本并导出 Markdown。

### 7.4 项目风险巡检

1. 从交付总览或项目详情启动巡检。
2. 系统先运行确定性风险规则。
3. Agent 基于规则结果和项目上下文生成风险解释及建议。
4. 页面区分“系统规则触发”和“AI 语义建议”。
5. 用户可将建议转为问题/风险/任务草稿并逐项确认。

## 8. 权限、数据安全和审计要求

1. Renderer 不直接读写 SQLite 或访问任意文件路径；数据通过受控 Preload API 和主进程 IPC 访问。
2. 每个 IPC 输入使用 Zod 严格校验，拒绝未知字段、超长文本、非法日期、非法状态及跨项目关联。
3. 所有更新类 IPC 在主进程校验 `deliveryProjectId` 和记录归属，禁止仅靠 Renderer 传入的项目 ID。
4. 项目资料必须导入到应用管理目录，路径经过 `resolve/realpath` 校验，防止路径穿越和符号链接越权。
5. AI 上下文中不得包含模型密钥、Jira Token、系统密码、客户生产环境凭据或无关项目文件。
6. AI 生成报告和结构化建议须留存来源快照哈希及生成时间，报告保存后不可伪装成实时项目状态。
7. 外发客户资料、上传 Jira 附件、发送通知等外部操作必须显式预览和再次确认；1.0 不自动发送。
8. 关键操作记录活动日志，敏感字段脱敏。
9. 本地 SQLite 数据迁移沿用现有迁移前备份机制；增加迁移回归测试。
10. 删除/归档行为需清晰区分；1.0 优先软归档。

## 9. 非功能要求

| 类别 | 要求 |
|---|---|
| 平台 | Windows x64 桌面端，遵守现有 Electron 主进程/Preload/Renderer 架构 |
| 技术栈 | 沿用仓库当前 React、TypeScript、Electron、SQLite、Zod、现有构建工具；不未经论证增加新框架 |
| 性能 | 项目列表 500 条记录规模下交互保持流畅；列表查询分页或限制返回量；避免每次渲染全量加载全部附件正文 |
| 可靠性 | 数据写入采用事务；失败时明确反馈，不出现 UI 显示成功而数据库未保存 |
| 可追溯性 | 任务、里程碑、问题、报告等记录有稳定 ID、创建/更新时间；关键变更保留动态日志 |
| 可用性 | 支持空状态、加载态、错误态、搜索无结果态、长文本预览和确认提示 |
| 可访问性 | 表单有明确标签，键盘可操作，状态不能只靠颜色表达 |
| 国际化 | 1.0 中文界面；代码中的类型/变量命名遵循现有仓库英文命名风格 |
| 兼容性 | 旧用户数据升级后不丢失现有项目、会话、专家、Runtime 和知识数据 |

## 10. 关键指标

1. 项目经理每周生成并保存的周报数量。
2. 交付项目中，任务负责人和截止日期完整率。
3. 项目逾期任务发现到首次处理的时间。
4. 高优先级问题从创建到关闭的周期。
5. AI 周报草稿被人工修改/接受的比例（用于评估有用性，不作为绩效单一指标）。
6. 实施人员通过知识问答找到有效产品依据的比例。
7. Excel 数据转换工作流的复用次数和错误拦截数量。

1.0 不设没有基线依据的“效率提升 50%”等承诺。试点前后用同一任务类型记录人工耗时、AI 耗时、人工修改时间和结果质量。

## 附录 A：建议 UI 结构

### 交付总览

- 顶栏：交付工作台、当前视图切换、项目搜索、新建项目。
- KPI 区：进行中项目、逾期任务、高优先级风险、临近里程碑。
- 主区：需关注项目表格、近期项目动态、AI 风险摘要。
- 空状态：引导创建首个项目，不展示虚构示例数据。

### 项目详情

- 项目头部：项目名称、客户、系统类型、阶段、状态、项目经理、计划周期。
- 标签页：概览 / 任务与里程碑 / 问题风险 / 会议动态 / 项目资料 / AI 助手。
- 右侧或二级区域：与当前项目相关的快捷操作，不要把所有功能塞在一个巨大聊天框里。

### 视觉原则

- 与精工 Agent 现有深色/浅色主题、字体、间距、按钮和弹窗系统一致。
- 信息密度应适合桌面端 1280×800 及以上窗口；缩小窗口时表格可横向滚动或切换卡片布局。
- 状态用文字+颜色双重表达；避免纯色徽标充当唯一信息。
- 项目风险展示来源，不使用无依据的装饰性仪表盘。
