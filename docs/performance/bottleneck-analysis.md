# 瓶颈证据与差距（2026-11-11）

当前没有同模型、同仓库基线、10 个任务各 3 次的运行样本，不能给出实际前三大耗时排名，也不能声称达到 15%–25% 提速。以下为代码确定的重复工作风险，排序是排查顺序，不是耗时排名。

1. `main/index.ts:getRuntime` 每轮关闭旧 adapter 并执行 checkRuntime，初始化有重复成本；原有事件没有独立时间戳阶段。先增加初始化 span，再考虑有身份/版本校验的健康缓存，避免盲目复用含旧凭据/规范的实例。
2. `project-read-broker.ts:listFiles` 每次递归目录，重复任务没有增量元数据复用。新增受授权根限制的轻量索引，Git ignore 由 Git 原生规则处理，mtime/ctime/size 不变时跳过内容解析；检索取片段时重新校验文件和 hash。索引失败回退原工具。
3. `buildDeveloperContext` 加 Jira JSON/共享上下文/历史摘录没有统一预算和去重。新增只作用于检索代码片段的预算与版本缓存，绝不裁剪原始需求、安全规则和验收内容。token 估算必须标明 estimated。

差距：当前 RuntimeEvent 未提供所有工具 item ID/usage/model span。不能把两个可见文本事件之间的墙钟差值当作模型推理时间，不能根据“命令完成”推算命令实际耗时。新监控保存实际可观测阶段及显式 unavailable；工具 gateway 执行可直接测量。

安全/交付边界：保留现有子任务治理和 VerificationRunService 证据链；测试分级仅使用已登记命令并输出选择原因，不猜测命令、不自动连接生产数据库。性能基线须后续使用真实任务与原生 Runtime 日志采集；本次本地索引/缓存/锁测试只能证明正确性与减少重复解析，不能证明模型端到端提速。
