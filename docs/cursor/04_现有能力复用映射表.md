# 现有能力复用映射表

文档依据：`01_需求规格说明_V1.0.md`、`02_技术方案_V1.0.md`、`03_交互原型说明_V1.0.md`、仓库 `AGENTS.md`、当前分支 `develop/desktop-poc`。

## 一、现状结论

当前仓库是 Electron 45.2.2 + React 19.3.1 + TypeScript 5.9.3 的桌面应用，运行时采用多 Runtime 适配器。Codex 已经通过单一 `CodexRuntime` 实例承载 App Server JSON-RPC，支持 `thread/start`/恢复、`turn/steer`、`turn/interrupt`、审批请求和基础 delta/工具/状态事件。渲染层已有可调整三栏布局、会话消息、Git 变更树、文本 Diff 预览、运行输出和工具活动面板。

因此本次 P0 的技术方案与现有架构兼容，实施重点是“扩展现有事件模型和已有工作区”，而不是重建 Runtime、会话存储或 Electron 页面。当前缺口主要是：Codex 的计划、Turn 聚合 Diff、命令 output delta、item 生命周期和连接状态没有完整归一到 renderer；现有消息区、Git Diff 区、底部活动区也尚未共享同一 Turn 级状态。

## 三、P0 分批实施边界

### 批次 A：事件底座与时间线

1. 在现有 `RuntimeEvent`/`AgentEvent` 上增加安全的 UI 事件归一结构和本地 sequence。
2. 补齐 Codex App Server 的 plan、item 生命周期、命令 output delta、Turn Diff、审批 resolved、连接变化映射。
3. 主进程批量广播，renderer 按 `sessionId + turnId + itemId` 归并；状态、文本、命令日志采用不同刷新策略。
4. 先补单元/协议回放测试，再构建和桌面冒烟。

### 批次 B：开发工作区与中央 Diff

1. 在现有三栏布局上增加项目会话的任务/代码/变更中央视图。
2. 复用 `GitChangesTree`、`DiffPreview` 和现有 Git/Worktree API，加入 Turn Diff 快照与来源标识。
3. 独立会话继续使用聊天布局，不显示空项目文件区。

### 批次 C：底部面板与任务控制

1. 将现有运行输出、工具活动、验证记录和问题聚合到底部面板。
2. 接入停止中的权威状态、Codex steer capability gating 和本地排队控制器。
3. 验证多 Runtime、会话切换、断线恢复、旧 Jira/Git/知识库/记忆入口回归。

## 四、兼容性判断与风险

- **兼容**：目标架构与现有 Electron、React、RuntimeManager、SQLite migration、Git Worktree 设计一致，可增量实施。
- **主要风险**：`RuntimeEvent` 当前载荷较窄，需扩展为安全的结构化事件；必须避免把原始 RPC payload、命令敏感参数或 reasoning 持久化/展示。
- **性能风险**：现有 `App.tsx` 同时消费消息和活动，直接把高频 delta 加入全局 state 会造成重渲染；应采用主进程批处理、renderer 局部 reducer/selector 和命令输出聚合。
- **数据风险**：优先复用 `events`、`settings`、`verification_executions`；只有确有必要才追加迁移版本，禁止重建 SQLite。
- **行为风险**：停止、追加和排队必须绑定当前 session/thread/turn 快照，不能因会话切换把操作发送到其他 Runtime。

## 五、验收证据要求

每个批次必须至少执行：

- `npm run build`
- 与事件/状态/Diff/队列相关的 `npm test` 或定向测试
- `npm run test:desktop`（涉及 renderer/main 或 IPC 时）

报告必须记录实际 HEAD、工作区状态、测试命令及退出码；不把计划、静态检查或模型文字当作真实 Runtime/构建/测试证据。
