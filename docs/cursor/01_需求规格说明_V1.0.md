# 精工 Agent Cursor 级交互体验升级 — 需求规格说明

- 文档版本：V1.0
- 日期：2026-11-16
- 目标产品：精工 Agent Windows 桌面端
- 当前基线：仓库 `zhuangxiaolong/jg_agent`，用户提供的 `develop/desktop-poc` 代码入口
- 产品版本基线：仓库 README 标识 0.7.0；实际实施以 Codex 检出的本地 HEAD 和工作区为准
- 文档用途：交由 Codex 在现有项目中实施，不是新建一套独立 IDE

---

## 1. 项目背景

精工 Agent 已具备多 Runtime 会话、模型与推理强度选择、Jira 任务关联、MES/WMS 开发规范与数据字典、Git 变更审阅、子 Agent、运行输出、独立会话 Worktree、项目/会话侧栏及可调整详情面板等能力。

当前升级重点不是增加更多模型或重新实现 Coding Agent，而是将已有开发能力组织成更完整、实时、可控的桌面开发工作台，达到接近 Cursor 的交互体验：

1. 用户发起任务后，立即看到任务运行状态和执行过程。
2. Agent 输出、任务计划、工具活动、文件变化、终端输出和测试结果能够同步呈现。
3. 用户无需离开当前会话即可查看和审查代码变化。
4. 用户可以停止任务、向当前任务追加指令，或将新任务排队。
5. 用户可以从文件、代码片段和错误日志快速建立任务上下文。
6. 原有 MES/WMS 专业知识、Jira、Git、验证证据和多 Runtime 能力继续保留。

## 2. 产品目标

### 2.1 总目标

将精工 Agent 从以对话为中心的 AI 开发工具升级为“对话 + 代码 + 实时执行 + 结果审查”一体化的专业开发工作台。

### 2.2 具体目标

| 目标 | 描述 | 可验证结果 |
|---|---|---|
| 实时性 | 将 Runtime 事件转换为即时 UI 状态 | Agent 事件到 UI 更新 p95 不超过 150ms（本机、事件已到达主进程后） |
| 可视化 | 集中显示任务计划、执行活动、代码 Diff 和终端输出 | 不需要等待最终回答即可识别当前阶段和已发生的文件变化 |
| 可控性 | 提供停止、追加指令、任务排队和审批入口 | 用户操作能对应到真实 Runtime / Task Controller 动作 |
| 一体化 | 将项目文件、编辑器、Agent 对话和底部输出放到同一工作区 | 常见开发任务无需在独立页面之间反复切换 |
| 可追溯 | 保留会话、Turn、Item、变更文件和真实验证结果的关联 | 任一执行记录可追溯到 threadId / turnId / itemId 或本地验证 RunId |
| 专业化 | 继续注入正确的 MES5/MES6/WMS 规范和知识 | 不因 UI 改造改变既有业务规则和系统识别逻辑 |

### 2.3 非目标

本轮不做以下工作：

- 不重写 Codex、Claude Agent SDK、精工 Runtime 或 Grok Build ACP 的 Agent 执行引擎。
- 不把所有 Runtime 强行改造成 Codex App Server；使用统一 UI 事件模型和各 Runtime 适配器。
- 不更换 Electron 桌面框架，不重建应用启动、安装、自动更新和凭据存储体系。
- 不重新实现 Jira、Git、项目管理、知识库、数据字典、记忆、插件等已有业务功能。
- 不以增加多个子 Agent 数量作为性能优化目标；优先复用已有子 Agent 能力。
- 不在界面中展示模型原始内部推理文本。仅呈现任务计划、状态、工具活动、结果和可展示的摘要。
- 不把模型文字声明当成真实构建或测试证据。
- 不默认实现云端执行、多用户协作、远程容器或浏览器端 IDE。

## 3. 当前能力基线及复用原则

根据当前可读取的仓库 README、`package.json`、`AGENTS.md` 和架构文档，识别到以下基线：

- Windows x64 桌面应用；Electron 45.2.2、React 19.3.1、TypeScript 5.9.3。
- 仓库版本标识 0.7.0，应用源码主要位于 `apps/desktop/`，核心模块位于 `packages/`。
- 当前 Codex 依赖版本固定为 `@openai/codex 0.156.1`（以实际锁文件和 Runtime 构建方式为准）。
- 已有 Codex、Claude Agent SDK、精工 Runtime、Grok Build ACP 等执行路径；会话可选择 Runtime、模型和推理强度。
- 已有项目/会话、独立会话工作区或 Git Worktree、Git 变更审阅、Jira 面板、知识/数据字典、开发规范、子 Agent、运行输出/工具活动、执行监控等能力。
- 已有本地 SQLite 数据、凭据保护、验证报告目录、Windows 构建与桌面冒烟测试流程。

### 3.1 必须遵守的复用原则

1. Codex 开始写代码前，必须检查本地实际分支、HEAD、未提交改动和 `AGENTS.md`。
2. 逐项定位现有会话消息流、Runtime 事件入口、事件持久化、右侧详情面板、代码变更、底部运行输出、Git Worktree、子 Agent 和 SQLite schema。
3. 已有能力优先增强，不得新建第二个 Codex App Server 管理器或重复的会话存储。
4. 不因界面布局变更删除原 Jira、Git、执行监控、子 Agent、知识库、记忆或会话设置入口。
5. 新增数据库结构必须采用现有迁移机制；禁止直接重建 SQLite 数据库或清空用户数据。
6. 不修改 Runtime 权限、安全策略、中转站配置、模型协议或既有执行默认值，除非本需求明确要求且完成单独评审。
7. 文档与源码冲突时，以当前源码为准；先记录差异，再按现有架构实现。

## 4. 用户角色与核心场景

### 4.1 主要用户

MES5、MES6、WMS、前端项目的开发人员、项目经理、技术负责人。用户需要在本机 Windows 环境中对真实代码仓库执行分析、修改、构建和测试。

### 4.2 核心场景

**场景 A：开发任务实时执行**

用户在已关联项目的会话中输入需求。系统立即显示运行态、任务计划、当前工具活动、模型输出和已修改文件。用户可查看中央编辑器中的 Diff，并在执行中补充指令或停止。

**场景 B：审查多文件修改**

Agent 修改多个文件后，用户在同一工作区按文件查看 Diff，定位代码、查看新增/删除内容、查看修改原因和相关任务活动；用户确认后继续构建测试或使用既有 Git 提交流程。

**场景 C：根据代码或日志发起任务**

用户在文件树中选择文件，或在代码编辑器中选择一段代码，添加到输入上下文；也可从终端错误/测试失败项创建排查任务。

**场景 D：运行中控制任务**

用户可以停止当前 Turn；也可以向当前 Turn 追加指令。新任务若选择排队，则在当前 Turn 结束后才开始，不能与“追加当前任务”混为一个动作。

**场景 E：任务恢复**

应用重启或通信中断后，用户重新打开会话，能够从 Runtime 历史或本地状态恢复任务记录；不能把断线误显示为任务已完成。

**场景 F：独立会话**

不关联项目的独立会话继续支持原有聊天能力，不强制展示代码树、编辑器或 Git 工作区。

## 6. 交互与状态要求

### 6.1 任务状态

```text
idle
  └── start ──> running
                  ├── approval request ──> waiting_approval ──> running
                  ├── complete ──> completed
                  ├── failure ──> failed
                  └── interrupt ──> interrupted
```

传输断开不是业务状态，不得直接转换成 completed/failed。增加 `connectionState`（connected/reconnecting/disconnected）独立表达连接状态。

### 6.2 Agent 活动分类

- `thinking_status`：仅展示“正在分析/整理计划”等状态标签，不展示原始内部推理。
- `plan`：展示结构化步骤和 pending/inProgress/completed 状态。
- `agent_message`：按增量显示用户可见消息。
- `file_change`：展示文件路径、变更类型和 Diff。
- `command_execution`：展示命令、工作目录、运行状态、输出、退出码和耗时。
- `tool_call`：展示工具名称、简要参数摘要和结果状态；敏感参数必须脱敏。
- `approval`：展示审批对象、原因、命令或目标主机、可选决策。
- `warning/error`：展示错误类型、信息和可恢复操作。
- `verification`：关联平台真实验证 RunId、命令、退出码和报告路径。

### 6.3 任务时间线规则

1. 以 threadId + turnId + itemId 关联活动；本地事件序列号用于排序和去重。
2. `item/started` 创建活动；delta 事件更新活动内容；`item/completed` 覆盖为最终权威状态。
3. 事件到达顺序可能与 UI 渲染节奏不同；必须先按接收顺序入队，再由 reducer 归并。
4. `turn/diff/updated` 是 Turn 级最新聚合 Diff 快照，直接替换该 Turn 对应快照，不得重复拼接旧 diff。
5. 大量日志采用分批渲染、虚拟列表和最大内存窗口；不能把无限日志放入单个 React state。
6. 历史会话必须支持分页/懒加载；不在应用启动时加载全部长对话。

### 6.4 运行中操作

- 停止：调用当前 Runtime 对应取消接口；Codex Runtime 使用 App Server `turn/interrupt`。
- 追加当前任务指令：Codex Runtime 使用 `turn/steer`，必须带当前 `expectedTurnId`；若 Runtime 不支持则禁用并解释。
- 排队下一任务：本地 Task Queue 管理，不调用 steer；当前任务完成/中断后再启动。
- Runtime/模型/权限/工作目录等会影响 thread 的设置，继续遵循当前已有会话配置规则；运行中不能擅自热切换不支持的参数。

## 7. 页面与信息架构

### 7.1 项目开发工作区

1. 顶部工作区栏：项目名称、分支/工作区、Runtime、模型、推理强度、会话状态、窗口操作。
2. 左侧导航栏：项目/会话切换、文件、搜索、历史、Git 等现有入口。
3. 左侧文件区：项目文件树、文件搜索、修改标识。
4. 中央工作区：任务/代码/变更视图；优先展示最近打开文件或本 Turn Diff。
5. 右侧 Agent 面板：对话消息、任务时间线、计划、子 Agent（若已有）、输入框与控制栏。
6. 底部面板：运行输出、终端活动、测试/验证、问题；复用既有运行输出和验证模块。

### 7.2 独立会话工作区

保留现有聊天主体验，不展示无意义的项目文件树。Agent 面板可扩展为主对话区，运行输出和工具活动仍能查看。

### 7.3 现有辅助面板兼容

Jira、Git、项目上下文、数据字典、开发规范、执行监控、子 Agent 等已有详情面板继续可访问。允许整合为右侧辅助面板 Tab 或可折叠区，但不得删除原操作和数据。

## 8. 安全、数据与兼容性要求

1. 继续遵循当前 Runtime 沙箱、审批策略、Worktree 和主进程文件校验；UI 升级不得放宽权限。
2. 所有文件操作仍在当前会话授权工作区内执行，并复用现有路径校验、敏感文件拦截和 Worktree 隔离。
3. 不将 API Key、Token、密码、Webhook、认证头、完整私密命令参数写入时间线或日志。
4. 审批 UI 必须展示审批对象和可选决策；用户未同意不得模拟成功。
5. 不显示 `reasoning` 原始内容或模型内部推理文本；如 Runtime 提供可面向用户的简短计划/活动信息，可按现有协议展示。
6. SQLite 迁移必须向前兼容，启动前备份策略沿用现有机制；升级失败不得损坏旧数据。
7. 兼容当前 Windows x64、Node.js 24、现有 Electron 打包和自动更新流程。
8. 不能通过在渲染进程直接启动任意 Node 子进程绕过现有主进程权限边界。

## 9. 性能与体验指标

以下指标用于本机验收；测试需记录设备规格、项目规模、Runtime 版本和测试任务，不能单次测试就宣称整体模型速度提升。

| 指标 | 目标 |
|---|---|
| 事件到 UI 状态刷新 | p95 ≤ 150ms（事件已到主进程） |
| 流式文本刷新 | 以 30–60ms 批次刷新；视觉无明显卡顿 |
| 停止按钮反馈 | 点击后 100ms 内显示“正在停止”，随后等待 Runtime 权威结果 |
| 左右面板拖动 | 拖动时无持续明显掉帧；不触发整页重载 |
| 小中型 Diff | 200 个文件以内、单文件变更规模常见场景下交互保持流畅；超大 Diff 异步计算 |
| 大日志 | 采用虚拟化/窗口化，滚动和切换面板不因历史日志明显冻结 |
| 重连 | 断线后展示重连状态；恢复后通过 Runtime 历史或已有会话数据校准状态 |
| 启动性能 | 不在应用启动时同步全量索引整个项目或加载所有历史消息 |

## 10. 验收标准

### 10.1 P0 功能验收

- [ ] 项目会话进入开发工作区，独立会话仍可正常使用。
- [ ] 新任务启动后，任务状态立即变为 running。
- [ ] 计划、Agent 消息、工具活动、命令输出、文件变化和最终结果按时间线展示。
- [ ] 流式输出期间可操作窗口、切换文件、折叠面板，不出现明显卡死。
- [ ] 文件修改事件到达后，文件列表出现新增/修改/删除标识。
- [ ] 点击文件可打开对应 Diff，并能区分新增、修改、删除。
- [ ] 可以停止当前任务；停止后最终状态由 Runtime 事件决定。
- [ ] Codex Runtime 支持时，可以向当前 Turn 追加指令；不能支持时 UI 明确禁用，不假装已发送。
- [ ] 可以排队下一任务，当前任务结束前不会误启动并发 Turn。
- [ ] 断开传输后显示 reconnecting/disconnected；重连后任务状态得到重新校准。
- [ ] 所有现有辅助功能仍然可达且主要流程无回归。
- [ ] 运行时审批仍按原权限策略执行；UI 不绕过审批。
- [ ] 构建、单元测试、桌面冒烟测试通过。

### 10.2 回归验收

- [ ] Codex、Claude Agent SDK、精工 Runtime、Grok Build ACP 原有会话仍能发起、停止和继续任务（按各 Runtime 已支持能力）。
- [ ] Provider/模型/推理强度切换行为不变。
- [ ] Jira 任务查看、关联会话和任务流程不变。
- [ ] Git Diff、提交前检查、验证报告、Worktree 隔离行为不变。
- [ ] 项目外资料、数据字典、开发规范和记忆仍能按原规则加载。
- [ ] 历史会话、SQLite 数据和 DPAPI 凭据不丢失。
