# 精工 Agent 1.6 开发前字段决策记录

2026-11-26 核对。分支 `develop/desktop-poc`，提交 `99cbf4e`，SQLite 版本 25。以下业务口径为待确认草案。样例使用合成数据。

## 需要交付负责人确认的五项口径

| 事项 | 建议采用的口径 | 决策影响 |
| --- | --- | --- |
| 交付组命名 | 项目经理手工选用已有标签，也可录入新标签，去除首尾空格并限制长度 | 同名标签归为一组。若第二战区已有固定字典，应改用该字典 |
| 交付产值 | 以实际验收日期归期，按币种汇总有来源的已确认验收金额。金额不适用的验收项可计件 | 若内部核定产值与客户验收金额不同，需分别登记 |
| 回款 | 一期只维护回款计划和有来源的分笔实际到账，允许超计划并提示复核 | 若需要开票、应收或冲销，须补充相应事实字段及状态 |
| 工时与容量 | 建议成员按工作日以 0.25 小时登记，项目经理按周复核，交付组负责人按人、按周维护可用时数 | 复核角色为流程建议。现有人员字段为姓名标签，同名人员须人工核对 |
| 历史归属 | 建议首次确认验收时保存当时的项目交付组。项目后续转组保留历史归属 | 方案 §4.2 提到记录创建时的组别，§14 提到验收时归属。提前建计划、确认前转组时，两者会产生不同结果 |

## 字段映射和旧数据兼容

| 对象 | 现有数据与拟增字段 | 校验、汇总与缺失显示 |
| --- | --- | --- |
| 项目 | 复用 `DeliveryProject.id` 及经理、成员。仅扩展可选 `deliveryGroupLabel` | 老项目维持原记录，空组显示“未分组” |
| 验收项 | 新增项目、标题、状态、计划日期和金额、实际验收日期和金额、币种、来源、确认人及组别快照 | 仅已确认项贡献实际产值。确认时需日期、金额或明确的“不适用”，以及来源或人工说明。建议单列可选的不适用标记，区分缺金额与明确不适用。金额更正留存前后值 |
| 回款计划 | 新增项目、标题、计划日期和金额、币种、状态、来源和分笔到账数组。每笔有独立 ID、到账日期、金额和来源 | 金额以币种最小单位的整数存储，分笔沿用计划币种。计划额已知时，余额为计划减实收，最低为零。超额同时展示，异币分列，缺计划额时余额显示“无法计算” |
| 工作日志 | 新增项目、可选同项目任务、人员、可选组别、工作日、工时、类别、摘要和来源 | 正工时按 0.25 小时步进。保留人工登记与估算调整的来源区别，计划工时与实耗分开。旧任务缺少剩余估算时显示“缺估算” |
| 周容量 | 新增人员、可选组别、周起始日、可用时数、来源和备注 | 建议按人、周维护一份跨项目容量，对齐 §8.3 模型和 §9.1 接口，避免多项目重复计算。缺记录显示“未维护容量”，显式零显示“本周可用 0 小时”，两者均不计算负荷率 |

来源沿用现有 `DeliverySourceRef`，能关联项目资料时保留文档引用。验收、回款和日志使用同一个交付项目 ID。归档项目的历史记录可读取，写入前复用现有项目归档检查。建议经营记录与活动记录在同一事务落盘，用稳定请求标识处理重试。阶段 1 按 §11 仅安排四类经营记录，§8.4 中的巡检运行表随阶段 3 评估。

代码核对入口包括 `packages/domain/src/delivery-workbench.ts` 的项目、任务、来源类型，`packages/storage/src/index.ts` 的迁移与活动写入，`apps/desktop/src/main/delivery-workbench-ipc.ts` 的项目校验，以及 `apps/desktop/src/preload/index.ts` 的窗口接口。
