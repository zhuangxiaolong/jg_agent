# 精工Agent——企业微信通知功能技术方案 V1.1（无自建应用版）

> 文档类型：技术架构与实施方案  
> 产品：精工Agent（Windows 桌面客户端）  
> 版本：V1.1  
> 状态：供 Codex 研发实施  
> 修订说明：本版本不使用企业微信自建应用消息 API。首期唯一发送通道为企业微信群机器人 Webhook；通过专属通知群和 @ 指定成员实现个人定向提醒体验。

---

## 1. 技术目标与边界

### 1.1 技术目标

在现有精工Agent中新增统一 `WeComNotificationService`，由平台会话终态事件驱动，向一个或多个企业微信群机器人 Webhook 发送通知。

必须满足：
- Windows 桌面端本地运行，不新增服务器、数据库服务器或云函数依赖。
- 不要求企业微信自建应用，不需要 CorpID、AgentId、应用 Secret。
- 通过 HTTPS 调用企业微信群机器人 Webhook。
- 支持普通群通知、专属通知群、@ 指定群成员。
- Codex/Jinggong/Claude Runtime 复用同一个通知服务。
- Webhook 密钥通过 Windows 凭据存储保护。

### 1.2 关键能力边界

企业微信群机器人 Webhook 的发送目标是添加该机器人的群聊，不是个人聊天窗口。因此：
- 可以向个人专属通知群发送消息；
- 可以向多人项目群发送消息；
- 可以在群中 @ 指定成员；
- 不能只凭 Webhook 将消息直接发到某个员工的一对一聊天窗口。

本方案中的 `private_group` 只是精工平台对“专属通知群”的业务分类，不是企业微信官方的私聊消息类型。

### 1.3 不实现

- 企业微信自建应用 token 获取、应用消息发送、通讯录读取。
- OAuth、企业微信账号登录、个人订阅凭据读取。
- 自建通知服务器或中继 API。
- 自动创建企业微信群或群机器人。

## 3. 企业微信群机器人接入

### 3.1 用户配置流程

1. 用户在企业微信客户端新建或选择一个内部群。
2. 如需要个人专属提醒，群内只加入目标接收人及必要成员。
3. 在群设置中添加群机器人，获取 Webhook。
4. 在精工平台“设置 → 通知 → 企业微信”创建目标。
5. 粘贴 Webhook，选择目标类型并配置可选 @ 成员。
6. 点击“发送测试消息”，确认实际群聊收到消息。

如用户没有添加群机器人权限，应联系企业微信管理员或群管理员处理。精工平台不尝试绕过管理限制。

### 3.2 Webhook 接口

典型接口：

```text
POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key={WEBHOOK_KEY}
Content-Type: application/json
```

Webhook URL 中的 `key` 是敏感凭据，不能写入普通数据库或日志。

### 3.3 文本消息示例

未配置 @ 成员：

```json
{
  "msgtype": "text",
  "text": {
    "content": "【精工Agent】\n任务：MES 设备列表增加状态筛选\n状态：已完成\nRuntime：Codex\n工作区：MES 生产系统\n测试：通过"
  }
}
```

@ 指定成员：

```json
{
  "msgtype": "text",
  "text": {
    "content": "【精工Agent】\n设备列表状态筛选功能已完成，请检查。",
    "mentioned_list": ["employee_userid_001"]
  }
}
```

手机号备用方式：

```json
{
  "msgtype": "text",
  "text": {
    "content": "【精工Agent】任务已完成，请查看。",
    "mentioned_mobile_list": ["13800000000"]
  }
}
```

实施注意：
- `mentioned_list` 应填写企业微信内部 UserID，不要填显示昵称。
- `mentioned_mobile_list` 仅作为可选兼容能力；手机号必须由用户主动提供，不能自行从其他数据推断。
- UserID/手机号对应的成员必须在机器人所在群中。
- 不默认 @all。
- 发送前校验消息体大小和字段格式；以企业微信当前接口文档及真实测试为准。

## 4. Runtime 统一事件集成

### 4.1 事件来源

事件统一来自平台 Session Manager，不从 Runtime Adapter 内直接发送通知。

建议统一事件类型：

```ts
export type PlatformSessionEventType =
  | "session.completed"
  | "session.failed"
  | "session.error"
  | "session.cancelled"
  | "session.interrupted";

export interface PlatformSessionTerminalEvent {
  eventId: string;
  platformSessionId: string;
  taskId?: string;
  workspaceId?: string;
  runtimeKind: "codex" | "jinggong" | "claude_agent_sdk";
  eventType: PlatformSessionEventType;
  occurredAt: string;
  title: string;
  summary?: string;
  durationMs?: number;
  repositorySummaries?: RepositoryChangeSummary[];
  testSummary?: TestSummary;
  errorSummary?: string;
  hasUncommittedChanges?: boolean;
}
```

### 4.2 触发规则

- `session.completed`：默认通知。
- `session.failed` / `session.error`：默认通知。
- `session.interrupted`：确认会话没有正常结束且尚未发终态通知时发送。
- `session.cancelled`：默认不通知，可配置。
- `session.needs_approval` 不属于终态，首期不发送；可在后续版本扩展。

Runtime 发生异常但平台会话最终仍处于运行中时，不得错误地发送“任务完成”。由 Session Manager 决定终态。

## 5. 统一通知接口

```ts
export interface NotificationTarget {
  id: string;
  name: string;
  channel: "wecom_group_bot";
  purpose: "private_group" | "team_group";
  enabled: boolean;
  credentialRef: string;
  mentionedUserIds?: string[];
  mentionedMobiles?: string[];
  eventPolicy: NotificationEventPolicy;
}

export interface NotificationEventPolicy {
  onCompleted: boolean;
  onFailed: boolean;
  onError: boolean;
  onCancelled: boolean;
  onInterrupted: boolean;
}

export interface WeComNotificationService {
  sendTest(targetId: string): Promise<NotificationSendResult>;
  notify(event: PlatformSessionTerminalEvent): Promise<NotificationBatchResult>;
  retry(notificationId: string): Promise<NotificationSendResult>;
}
```

如现有项目已有通知抽象，应扩展已有接口，不得新建平行事件总线或第二套任务状态管理。

## 6. 通知目标解析

目标优先级建议：

1. 会话临时通知目标（如现有产品支持）。
2. Workspace 专属通知目标列表。
3. Runtime/全局默认通知目标。

同一个目标从多个层级命中时必须去重。

每次会话终态只解析一次最终目标集合，并把解析结果快照写入通知批次，避免任务执行期间用户修改设置导致重试目标变化。

## 7. 消息模板

### 7.1 成功模板

```text
【精工Agent】任务已完成
任务：{title}
Runtime：{runtimeLabel}
工作区：{workspaceName}
仓库：{repositoryNames}
修改文件：{changedFileCount}
测试：{testStatus}
耗时：{duration}
完成时间：{completedAt}
```

### 7.2 失败模板

```text
【精工Agent】任务执行异常
任务：{title}
Runtime：{runtimeLabel}
工作区：{workspaceName}
失败阶段：{failedStage}
错误摘要：{redactedErrorSummary}
未提交修改：{hasUncommittedChanges}
请打开精工Agent检查任务详情。
```

### 7.3 内容保护

- 不发送完整代码、Diff 内容、Agent 隐藏推理或系统提示词。
- 不发送 API Key、Webhook、Authorization、数据库密码。
- 错误消息先脱敏并截断。
- 不把本机 `file://` 路径或 localhost 地址当作可供手机打开的链接。
- 对任务标题和用户输入进行换行/控制字符处理，防止消息伪造。

## 8. 安全凭据管理

### 8.1 Credential Vault

复用现有 Windows Credential Manager / DPAPI 实现：

```ts
interface CredentialVault {
  setSecret(key: string, value: string): Promise<void>;
  getSecret(key: string): Promise<string | null>;
  deleteSecret(key: string): Promise<void>;
}
```

凭据命名建议：

```text
wecom.webhook.{targetId}
```

SQLite 中只保存 `credentialRef`，不保存 Webhook URL 明文。

### 8.2 防泄漏要求

- UI 显示时掩码 Webhook key。
- 请求异常不可直接打印完整 URL。
- 不把 Webhook 放进命令行参数。
- 不写入崩溃转储诊断文本、遥测或导出文件。
- “复制 Webhook”需用户主动触发并提示其属于敏感凭据。
- 删除目标时同步清理凭据。

- 迁移后验证旧数据库和旧会话可正常打开。

## 11. 错误分类、节流和重试

### 11.1 错误分类

至少区分：
- `NETWORK_TIMEOUT`：网络超时。
- `NETWORK_UNAVAILABLE`：网络不可用。
- `WEBHOOK_INVALID`：Webhook 无效或机器人失效。
- `RATE_LIMITED`：达到机器人频率限制。
- `MESSAGE_INVALID`：消息格式/内容不合法。
- `MENTION_INVALID`：@ 成员参数存在问题（若接口返回可识别信息）。
- `REMOTE_REJECTED`：企业微信业务层拒绝。
- `CREDENTIAL_MISSING`：本地凭据不存在。

不能只根据 HTTP 200 判定成功；必须解析企业微信返回的 JSON `errcode`，并确认业务成功码。

### 11.2 频率控制

企业微信群机器人存在发送频率限制。平台采用按 Webhook 目标维度的 Token Bucket 或最小发送间隔控制；默认保守设置为每个机器人不超过 20 条/分钟，并留安全余量。

### 11.3 重试

- 网络临时错误：最多 3 次指数退避重试，并加随机抖动。
- 限流：按服务端提示或 Retry-After（若有）延迟；不得立即循环重发。
- Webhook 无效、机器人被移除、消息格式错误：标记永久失败，不自动重试。
- @ 成员问题：保留消息失败详情；允许移除 @ 配置后手动重试。
- 应用退出：未发送任务留在 SQLite 队列；下次启动检查并按策略续发，但必须先进行幂等校验。

### 11.4 重试和重复通知

幂等键：

```text
{platformSessionId}:{eventType}:{targetId}
```

同一幂等键已成功则跳过自动发送。手动重试要增加 retry operation 记录，但仍引用同一逻辑通知。

## 13. 进程与异步执行

- 通知 HTTP 请求不得阻塞 UI 渲染或 Runtime 任务结束回调。
- Agent 会话先落地终态和结果摘要，再异步入通知队列。
- 通知失败不能将已成功 Session 改为 failed。
- 应用退出时应优雅停止发送队列，并持久化尚未完成记录。
- 应用重启后恢复可重试队列，避免重复发送已成功记录。

### 14.1 单元测试

- 成功/失败消息模板。
- UserID 和手机号 @ 参数构造。
- Webhook 脱敏。
- 凭据读取失败。
- 企业微信 errcode 解析。
- 幂等去重。
- 目标策略解析。
- 多目标部分成功/部分失败。
- 节流和退避重试。

### 14.2 集成测试

用真实企业微信群机器人测试：
1. 无 @ 消息发送成功。
2. @ 一个成员成功。
3. 向专属通知群发送完成消息。
4. 向普通项目群发送消息。
5. 同时向两个群发送。
6. 错误 Webhook 能正确报错。
7. 机器人被移除/失效后，能识别失败且不无限重试。
8. 高频事件被节流。

### 14.3 Runtime 回归

分别使用 Codex、Jinggong、Claude Agent SDK 执行真实测试任务，验证统一终态事件只触发一次通知。

### 14.4 安全测试

- 数据库中搜索不到完整 Webhook。
- 日志中搜索不到 Webhook key。
- 导出诊断包不包含 Webhook。
- 通知正文不包含 API Key、模型密钥和未经允许的源码片段。

### 强制要求

- 本版本不得依赖企业微信自建应用。
- 不得要求提供 CorpID、AgentId、应用 Secret。
- 不得尝试向个人一对一聊天窗口发送消息。
- UI 必须明确说明个人专属通知群是群聊，不是个人私聊。

- 不得因通知失败改变 Agent 任务状态。
