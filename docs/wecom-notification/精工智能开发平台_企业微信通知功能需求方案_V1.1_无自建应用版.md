# 精工Agent——企业微信通知功能需求方案 V1.1（无自建应用版）

> 文档类型：产品需求方案  
> 产品：精工Agent（Windows 桌面客户端）  
> 版本：V1.1  
> 状态：供 Codex 研发实施  
> 修订说明：本版本根据“当前无法创建企业微信自建应用”的实际条件，移除自建应用消息 API 作为首期能力，统一改为企业微信群机器人 Webhook。  
> 重要边界：群机器人只能向配置的群聊发送消息，不能直接发送到个人聊天窗口。可通过 @ 群成员进行定向提醒，或建立只有目标用户和机器人的专属通知群，实现近似个人通知的体验。

---

## 1. 产品背景与目标

精工Agent支持 Codex Runtime、Jinggong Runtime、Claude Agent SDK Runtime。用户希望在 Agent 会话完成后，通过企业微信及时获知任务执行结果。

当前无法创建企业微信自建应用，因此首期不使用企业微信应用消息 API，不依赖 CorpID、AgentId、应用 Secret 或通讯录读取权限。

### 1.1 产品目标

1. 会话完成、失败或异常终止后，自动向配置的企业微信群发送通知。
2. 支持在群消息中 @ 指定员工，提醒具体负责人。
3. 支持建立专属通知群，让消息仅对目标个人可见（群成员仅目标用户及机器人/必要管理成员）。
4. 支持多个群机器人配置，例如个人通知群、研发群、项目群。
5. 三种 Runtime 使用平台统一通知服务，不允许每个 Runtime 自己实现企业微信通知。
6. 通知配置、发送历史、失败原因和重试操作在 Windows 客户端内完成。
7. 不要求部署服务器；客户端直接通过 HTTPS 访问企业微信 Webhook。

### 1.2 非目标与明确限制

- 不实现企业微信个人聊天窗口的一对一应用消息。
- 不采集企业微信登录密码、Cookie 或个人 OAuth Token。
- 不要求创建企业微信自建应用。
- 不调用企业通讯录 API 获取 UserID；UserID 由用户手动填写或从企业微信管理渠道取得。
- 不承诺群机器人消息能在用户个人聊天窗口显示。
- 不开发云端通知中继服务；本版本由 Windows 客户端直接发送 Webhook。

## 2. 用户角色与场景

### 2.1 用户角色

- 普通开发人员：配置自己的专属通知群，接收任务完成提醒。
- 项目经理/开发负责人：配置项目群，并设置需要 @ 的成员。
- 平台管理员：维护通知目标、消息模板、默认通知策略及发送记录。

### 2.2 典型场景

**场景 A：个人定向提醒（推荐）**

1. 用户在企业微信创建一个内部群，例如“精工平台-我的任务通知”。
2. 群成员只保留通知接收人（必要时包含协助管理人员）。
3. 在该群添加群机器人，复制 Webhook。
4. 在精工Agent添加“专属通知群”目标，并粘贴 Webhook。
5. Agent 任务完成后，精工平台向该 Webhook 发送结果。
6. 只有该群成员能看到消息，因此实现个人专属接收效果；但消息技术上仍属于群消息。

**场景 B：群通知并 @ 负责人**

1. 用户为研发群或项目群添加群机器人。
2. 配置 Webhook，并填写群成员 UserID（可选手机号作为备用字段）。
3. 会话完成后，精工平台在文本消息中 @ 指定成员。

**场景 C：多个目标同时通知**

任务完成后，同时通知个人专属群和项目群；每个目标可单独开关成功、失败、异常等事件。

## 4. 通知目标配置

### 4.1 通知目标类型

首期只提供一种底层通道：`wecom_group_bot`。

界面提供两个业务用途标签：

- **专属通知群**：推荐用于个人提醒。填写一个只面向目标用户的群机器人 Webhook。
- **普通群聊**：用于研发群、项目群等多人群聊，可配置 @ 成员。

这两个用途最终均通过群机器人 Webhook 发送消息，不代表企业微信支持一对一应用消息。

### 4.2 配置字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 目标名称 | 是 | 例如“我的个人通知群”“MES 项目群” |
| 用途 | 是 | `private_group` / `team_group` |
| Webhook URL | 是 | 企业微信群机器人完整 Webhook |
| 启用状态 | 是 | 启用/禁用 |
| @ 成员 UserID | 否 | 支持多个，填写企业微信内部成员 ID |
| @ 成员手机号 | 否 | 兼容备用；须与企业微信群成员手机号匹配 |
| 默认接收事件 | 是 | 成功、失败、异常、取消等 |
| 消息级别 | 是 | 全量 / 仅失败 / 仅重要任务 |
| 备注 | 否 | 群用途和负责人 |

### 4.3 Webhook 安全

- Webhook URL 包含机器人密钥，必须作为敏感凭据处理。
- 使用 Windows Credential Manager 或 DPAPI CurrentUser 加密保存。
- SQLite 只存凭据引用和脱敏后的目标信息，不存明文 Webhook。
- UI 展示时只显示脱敏地址；复制/替换需用户主动操作。
- 日志、异常、导出文件不得出现完整 Webhook URL。
- 用户删除目标时，删除本地凭据并保留必要的脱敏审计记录。

## 5. 触发事件

| 事件 | 默认是否通知 | 说明 |
|---|---|---|
| `session.completed` | 是 | Agent 正常完成 |
| `session.failed` | 是 | Agent 任务失败 |
| `session.error` | 是 | Runtime、模型或工具出现不可恢复异常 |
| `session.cancelled` | 否 | 用户主动取消；可在设置中打开 |
| `session.needs_approval` | 否 | 等待用户审批；P1 可选 |
| `session.interrupted` | 是 | 应用关闭或进程异常导致会话中断；仅确认任务未正常结束后触发 |

必须按平台统一 Session 终态事件触发通知，不能由各 Runtime 单独调用企业微信。

### 5.1 去重规则

- 每个 `platformSessionId + eventType + notificationTargetId` 生成唯一幂等键。
- 相同终态事件重复到达时，不重复发送。
- 用户手动点击“重新发送”应创建独立重试记录，但关联原通知记录。
- Runtime 自动重试、会话恢复或重复收到结束事件不得造成重复通知。

## 6. 消息内容

### 6.1 成功通知

至少包括：

- 产品名称：精工Agent
- 任务状态：已完成
- 任务标题/用户需求摘要
- Runtime：Codex / Jinggong / Claude Agent SDK
- 工作区名称
- 涉及仓库名称列表
- 修改文件数量（若可取得）
- 测试状态：通过 / 失败 / 未执行 / 部分执行
- 执行耗时
- 完成时间
- 会话本地查看入口（可选；不可生成不可访问的本机 URL）

### 6.2 失败通知

至少包括：

- 任务名称
- Runtime
- 工作区
- 失败阶段
- 脱敏后的错误摘要
- 已完成/未完成步骤摘要
- 是否存在未提交代码修改
- 本地排查提示

### 6.3 消息长度

- 遵守企业微信群机器人相应消息类型的官方长度限制。
- 超长日志不能整段推送，只发送摘要。
- 源码、密钥、完整命令环境变量、客户敏感信息不进入消息。
- 默认使用文本消息，以便可靠支持 `mentioned_list` / `mentioned_mobile_list`。

## 7. @ 指定成员规则

- 仅对普通群聊用途的目标展示成员提醒配置；专属通知群通常无需 @。
- 优先使用企业微信内部 UserID。
- 若使用手机号，必须由用户明确填写；不得自动从系统联系人或文件中推断。
- 仅提醒属于该群的成员。
- 不默认 @all。
- 未配置 @ 成员时正常发送消息，不阻断通知。
- UserID 或手机号错误时，发送记录应展示错误提示；不因 @ 失败无限重试。

## 8. 通知策略

配置层级优先级：

1. 会话临时设置（如产品支持）。
2. 工作区通知策略。
3. Runtime/全局策略。

每个目标可分别设置：
- 成功事件是否通知。
- 失败/异常是否通知。
- 取消事件是否通知。
- 是否 @ 成员。
- 是否发送任务摘要、Diff 统计、测试信息。

默认规则：成功与失败/异常均通知；用户主动取消不通知；个人专属通知群和普通项目群可以配置不同规则。

## 9. UI/交互要求

新增设置入口：**设置 → 通知 → 企业微信**。

页面至少包含：
1. 通道说明：明确说明“群机器人只能发群消息，不支持直达个人聊天”。
2. 通知目标列表。
3. 新增/编辑目标表单。
4. Webhook 输入与安全保存。
5. @ 成员配置。
6. 事件开关。
7. 测试发送按钮。
8. 通知记录列表和失败重试。

专属通知群创建向导应显示步骤：
- 在企业微信创建一个内部群。
- 将目标人员加入该群。
- 在群内添加群机器人并复制 Webhook。
- 回到精工平台粘贴 Webhook。
- 点击发送测试消息确认。

不得把“专属通知群”标注成“个人私聊”或“一对一消息”。

## 10. 发送行为与异常处理

- 每个机器人受企业微信接口频率限制；平台应采用队列和节流机制，避免集中通知超限。
- 对网络超时、临时网络故障和可重试服务错误进行有限次数退避重试。
- 对 Webhook 无效、机器人被移除、权限错误、消息格式错误等永久性错误不无限重试。
- 每个目标发送结果独立记录；一个群发送失败不影响其他目标。
- 通知发送失败不得改变 Agent 会话成功/失败状态。
- 用户可手动重试单条失败通知。

## 11. 本地数据与隐私

- 所有通知配置和记录保存在本地 SQLite。
- Webhook 凭据保存在 Windows 凭据保护层。
- 通知正文只保留必要摘要，默认不保存完整 Agent 对话。
- 提供通知历史保留期限设置，默认 90 天；用户可以清理。
- 诊断日志不得包含 Webhook 密钥。

## 12. 验收标准

### P0 功能验收

1. 不配置企业微信自建应用，单靠群机器人 Webhook 即可配置和发送。
2. 配置专属通知群后，任务完成消息能够发送到该群。
3. 配置普通群和成员 UserID 后，消息能够 @ 指定成员（以真实企业微信测试群验证）。
4. 同一会话可以通知多个目标。
5. Codex、Jinggong、Claude 三种 Runtime 均通过平台统一事件触发通知。
6. 成功、失败、异常事件按策略发送。
7. 重复终态事件不会重复发送。
8. 网络暂时失败可有限重试，永久错误不会无限重试。
9. Webhook 不以明文保存在 SQLite、日志或导出文件中。
10. 通知发送失败不影响会话结果和工作区状态。

### 明确不作为验收项

- 消息出现在企业微信个人聊天窗口。
- 精工平台读取企业微信完整通讯录。
- 自动获取任意员工 UserID。
- 无管理员/群管理权限时绕过群机器人添加限制。

## 13. 产品文案

推荐设置页说明：

“当前版本通过企业微信群机器人发送通知，不需要创建企业微信自建应用。若要只通知某一位员工，请创建专属通知群，并将该员工和群机器人加入群聊。若要在项目群中提醒负责人，可以配置成员 UserID 进行 @ 提醒。群机器人不支持直接发送到个人聊天窗口。”

## 14. 交付要求

Codex 完成后提供：
- 通知目标配置页面。
- Webhook 凭据安全存储。
- 测试发送。
- 统一事件订阅和通知服务。
- 多 Runtime 触发集成。
- 通知历史和重试。
- Windows 真实环境测试报告。
