# 精工 Agent UI 改造：Codex 执行说明

你现在负责改造现有的「精工Agent」桌面端 UI。请直接检查当前仓库并实施，不要只输出建议或伪代码。

## 本包文件

- `01-UI改造需求与技术实施方案.md`：完整需求、布局规范、设计 Token、组件拆分、交互要求和验收标准。
- `02-设计规范与视觉Token.md`：颜色、字体、字号、间距、圆角、图标等统一规范。
- `references/current-ui.png`：当前产品界面截图，作为现状和功能盘点依据。
- `references/target-ui-concept.png`：目标视觉方向参考图，仅作为风格和布局参考，不代表现有功能已经具备。

## 执行要求

1. 先检查仓库结构、前端框架、路由、主题系统、组件库、当前页面入口和已有业务交互。
2. 盘点当前截图中已有功能，建立「现有功能—新组件—回归验证」清单。不得擅自删除或弱化 Jira、代码变更、Git、上下文、需求准入检查、Runtime/模型选择、附件上传、会话和项目导航等现有功能。
3. 先给出简短的现状诊断和实施计划，然后继续直接修改代码，不要停下来等待确认。
4. 优先复用现有技术栈和组件，不要无理由更换 UI 框架、状态管理、路由或构建工具。
5. 按 `01` 文档的 P0 顺序实施；P0 完成并验证后，再实施 P1。若仓库现有架构不支持某项要求，先采用兼容现有架构的实现，并在最终报告说明限制，不要伪造功能。
6. 所有按钮、菜单、Tab、折叠、面板尺寸调整等控件必须有真实行为。不能只做静态装饰。
7. 完成后运行项目已有的 lint、typecheck、test、build 命令（以仓库实际脚本为准），修复本次改造引入的问题。
8. 至少提供 1600×900 和 1366×768 两种分辨率的运行截图；如当前环境无法启动桌面端，说明实际阻塞原因，不得声称已视觉验收。

## 本次设计目标

将当前界面调整为「深色专业 IDE 工作台」：左侧项目与会话导航，中间任务对话与执行区，右侧上下文检查器。界面应更清晰、更有层次、更易读，避免大面积同色灰黑、过小字体、拥挤标签和风格不一的图标。

请以 `01-UI改造需求与技术实施方案.md` 为实施依据，以 `references/target-ui-concept.png` 为视觉方向，以 `references/current-ui.png` 为现有功能基线。

## 完成汇报格式

- 改造前问题诊断
- 修改文件清单
- 新旧布局变化
- 保留的现有功能及回归结果
- lint/typecheck/test/build 的实际执行结果
- 运行截图路径
- 尚未完成项及原因
