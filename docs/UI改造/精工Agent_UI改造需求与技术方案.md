# 精工Agent UI 改造需求与技术实施方案

版本：V1.0  
目标：桌面端 UI 视觉与布局升级  
改造方式：在现有产品代码上渐进式重构，不推翻业务功能和 Runtime 架构。

---

## 1. 改造目标

当前界面存在以下可见问题：

1. 左侧项目、会话和全局入口层级不够清楚，信息堆叠。
2. 中间对话区、顶部任务信息和底部输入区缺少明确的视觉层级，部分空间利用率偏低。
3. 右侧 Jira 面板占用较大，但空状态信息较多，重要信息不够聚焦。
4. 深色背景、卡片和边框的明度接近，界面容易显得灰、闷、层次不清。
5. 字体字号偏小，次级信息与主要内容区分不足。
6. 图标线条、尺寸和语义不统一，状态更多依赖文字表达。
7. 顶部工具、面板 Tab、状态信息和会话输入区的控件密度不一致。

改造后应达到：

- 专业、克制、清晰的深色 IDE 工作台风格。
- 形成稳定的「左侧导航 / 中间工作区 / 右侧上下文面板」三栏结构。
- 让用户快速识别当前项目、当前任务、Runtime、运行状态和项目上下文。
- 提升字体、图标、间距、颜色和控件的一致性。
- 保留现有功能，给后续多 Agent 工作台预留扩展位置。

设计参考：
- `references/current-ui.png`：当前版本截图，功能保留依据。
- `references/target-ui-concept.png`：目标视觉概念图，只参考视觉语言与三栏布局。图中新增的功能、数据、人物、统计和按钮均不可直接视为现有产品能力。

## 2. 设计原则

1. **先整理信息层级，再调整颜色。** 不通过增加渐变、阴影和装饰来掩盖布局问题。
2. **保留真实能力。** 当前存在的 Jira、代码变更、Git、上下文、需求检查、Runtime、模型、附件、项目和会话功能必须保留。
3. **不造假。** 不展示虚构的运行进度、Agent 数量、测试通过状态、Git 分支或 Jira 数据。
4. **渐进式改造。** 尽量复用现有组件、路由、状态管理和样式基础设施。
5. **桌面优先，响应式适配。** 主要面向 Windows 桌面端，同时适配较小窗口。
6. **功能优先于装饰。** 不为了截图效果隐藏必要操作或降低可访问性。

## 3. 总体布局

### 3.1 三栏工作台

以 1600×900 桌面窗口为主要设计基准：

| 区域 | 建议尺寸 | 行为 |
|---|---:|---|
| 左侧导航 | 240–256 px | 固定宽度，可折叠为 64–72 px |
| 中间工作区 | 自适应，建议不少于 620 px | 对话、任务信息、输入区 |
| 右侧上下文区 | 340–380 px | 可折叠，可切换 Tab |
| 顶部全局栏 | 48–56 px | 面包屑、当前项目/任务、全局操作 |

尺寸必须通过 CSS Grid/Flex 实现，不允许使用固定截图坐标。中间工作区必须 `min-width: 0`，防止内容挤压导致横向溢出。

### 3.2 左侧导航

分为四个视觉分区：

**A. 品牌区**
- 产品图标和名称「精工Agent」。
- 版本号作为低强调辅助信息，不与产品名称争抢视觉注意力。

**B. 主导航区**
- Agent 工作台
- 本地项目 / 项目管理（按现有路由与功能命名）
- 知识库
- 模板中心（仅在现有功能存在时展示）

**C. 项目与会话区**
- 标题「项目」或「最近项目」。
- 项目列表支持展开/收起。
- 项目下展示会话，当前会话高亮。
- 新建会话入口放在明确、固定的位置。
- 长项目名和会话名截断显示，悬停提供完整名称。
- 不重复显示同一项目或同一会话入口。

**D. 底部状态区**
- 当前 Runtime 连接状态。
- 全局设置。
- 当前用户/工作区信息（沿用现有能力）。

要求：侧栏支持折叠；折叠后图标居中，悬停显示 Tooltip；折叠状态在重启后按现有偏好设置机制保存。若当前没有偏好存储机制，先使用项目现有配置能力，不要新增复杂持久化依赖。

### 3.3 中间工作区

从上到下分为：

**A. 工作区顶部栏（48–56 px）**
- 面包屑：工作台 / 项目 / 当前会话。
- 当前任务名称可编辑或复制（沿用已有能力；不存在编辑能力时不要伪造）。
- 右侧放置有实际功能的运行控制、布局切换或设置入口。
- 避免堆叠多个重复的项目名、会话名和任务名。

**B. 当前任务摘要区（建议 76–96 px）**
- 任务名称：18–20 px，中高字重。
- 一行任务描述：13–14 px，最多两行。
- 任务标签：项目类型、Runtime、运行状态等。标签只显示真实数据。
- 运行中、暂停、完成等状态使用统一状态徽标。
- 需求准入检查卡片应紧凑展示状态和操作入口；详细结果通过展开或点击查看，不要占据过大的固定高度。

**C. 对话与执行时间线（自适应滚动区）**
- 用户消息和 Agent 消息采用明确区分的消息样式。
- 主内容字号 14–15 px，行高 1.55–1.7。
- 长代码、Markdown 表格、命令输出必须在容器内处理溢出，不得撑破三栏布局。
- 工具执行过程、构建、测试和报告等信息按时间线或可折叠执行卡片呈现。
- 运行日志默认折叠或摘要展示，用户主动展开后显示详细内容。
- 不要让一条简短状态信息占据整行大面积空白。
- 对话滚动位置在新增消息时保持合理行为；用户向上查看历史时不得强制跳回底部。

**D. 底部输入区（固定在中间栏底部）**
- 输入框有明确焦点态和可读占位符。
- 常用操作统一放在输入框下方工具栏：添加附件、代码/文件相关操作、知识库选择、Runtime 选择、模型选择、发送。
- 保留现有发送快捷键说明。
- 次要信息用 Tooltip 或菜单，不要全部挤在一行。
- 输入区随内容增长但设置合理最大高度，滚动不影响整个页面。
- 发送、附件、Runtime、模型等必须连接现有真实逻辑。

### 3.4 右侧上下文面板

默认宽度 340–380 px，可收起。沿用并整理现有 Tab：

1. Jira
2. 代码变更
3. Git
4. 上下文

如果代码中已经存在其他面板，可在不删减原功能的前提下纳入 Tab 或二级入口。后续多 Agent 功能接入时，可增加 Agent Tab，但本次 UI 改造不能假装多 Agent 功能已经实现。

各面板要求：

- Tab 高度统一，选中态使用底部强调线或轻量背景，不同时使用多种选中效果。
- 面板标题、连接状态、主要操作、数据列表层级清楚。
- Jira 的日期、查询条件、抓取任务按钮保留；历史查询条件采用折叠区。
- 空状态使用紧凑图标、简短说明和下一步操作，不保留大面积无内容占位卡。
- 代码变更应突出文件数量、文件列表、Diff 入口和变更状态。
- Git 应突出当前仓库、分支和真实状态；不存在的数据不展示假值。
- 上下文应展示当前项目、知识库/文件引用及实际加载情况。
- 面板内容独立滚动，Tab 切换不重置其他面板的必要状态。

## 4. 设计 Token

颜色、字体、字号、间距、圆角和阴影详见 `02-设计规范与视觉Token.md`。实现时优先接入现有主题变量；若没有统一 Token，再建立 CSS Variables 或现有框架对应的主题变量。

关键要求：
- 页面背景与卡片背景必须有足够明度差。
- 主文本与次级文本必须有明确对比。
- 蓝色仅用于主要操作、选中态和交互焦点。
- 绿色仅用于成功/正常状态，黄色用于警告，红色用于失败/危险。
- 不要用高饱和色装饰所有面板。
- 不要给每张卡片都叠加明显阴影、渐变和发光效果。

## 5. 字体与图标

### 字体

中文优先：`Microsoft YaHei`、`PingFang SC`、`Noto Sans CJK SC`，最后回退系统 sans-serif。

英文/代码优先：`Inter`、`Segoe UI`、`Arial`；代码使用 `JetBrains Mono`、`Cascadia Code`、`Consolas`。

如果项目未内置相关字体，不要擅自引入来源不明的字体文件；使用可用系统字体回退。

### 图标

- 优先统一使用现有图标库；若现有项目使用 Lucide，则统一为 Lucide outline 风格。
- 默认尺寸：16 px（行内）、18 px（常规操作）、20 px（主要导航）、24 px（空状态/重点状态）。
- 默认描边宽度约 1.75–2 px。
- 同一语义始终使用同一个图标。
- 禁止混用 Emoji、彩色贴图图标和不同风格的线性图标作为功能图标。
- 图标按钮必须有 Tooltip、可访问名称和清晰 hover/focus/disabled 状态。

## 6. 状态与徽标

统一状态：运行中、已完成、等待中、已暂停、失败、未连接、未检查。

- 使用图标 + 文本表达，不单靠颜色。
- 标签高度建议 22–26 px，圆角胶囊或轻圆角矩形二选一并保持一致。
- 普通信息使用中性灰色；绿色/黄色/红色仅用于状态语义。
- 不要在一个面板中同时出现多种不同尺寸的状态徽标。

## 7. P0 实施范围（本轮必须完成）

### P0-1 设计基础统一
- 建立颜色、字体、字号、间距、圆角、边框、阴影和层级 Token。
- 统一 Button、IconButton、Input、Select、Tabs、Badge、Tooltip、Card、EmptyState。
- 清除重复、冲突的页面级样式。

### P0-2 三栏布局重构
- 完成左侧导航、中间工作区、右侧上下文区布局。
- 侧栏和右侧面板可折叠。
- 页面不出现整体横向滚动条。
- 小窗口时按规则折叠侧栏或将右侧面板转为抽屉。

### P0-3 中间对话区重构
- 优化任务摘要、需求检查卡片、聊天消息、执行信息和输入区。
- 去除无意义的大面积留白。
- 提升正文和辅助文字可读性。
- 保证历史消息、代码块、Markdown、日志均正常展示。

### P0-4 右侧面板重构
- 保留 Jira、代码变更、Git、上下文现有入口和行为。
- 优化 Tab、空状态、数据列表、详情区和操作按钮。
- 空数据时显示简洁且真实的状态说明。

### P0-5 图标和交互统一
- 统一图标库、尺寸和语义。
- 统一按钮高度、圆角、hover、focus、disabled 状态。
- 纯图标按钮补充 Tooltip/aria-label。

### P0-6 功能回归
- 验证项目切换、会话切换、新建会话。
- 验证发送消息、附件上传、模型选择、Runtime 选择。
- 验证需求准入检查。
- 验证 Jira 连接、日期选择、抓取任务、历史条件。
- 验证代码变更、Git、上下文面板。
- 验证全局设置、运行状态和日志入口。

## 8. P1 实施范围（P0 稳定后）

1. 支持拖拽调整左侧/中间/右侧面板宽度，并设置最小/最大宽度。
2. 记住用户的面板折叠状态和宽度偏好。
3. 提供紧凑/舒适两种密度设置（如现有产品设置体系允许）。
4. 右侧面板支持自定义默认 Tab。
5. 为未来多 Agent 运行状态面板预留扩展点，但没有后端数据时不展示虚构状态。
6. 可选提供浅色主题；若现有主题体系已有浅色主题，保证本轮组件兼容，不要求重做整套浅色设计。

## 9. 响应式规则

- ≥1440 px：三栏完整显示。
- 1200–1439 px：左侧保持可折叠，右侧可收窄至 300–340 px。
- 960–1199 px：左侧默认折叠，右侧可切换抽屉。
- <960 px：保留中间核心工作区，左侧和右侧使用抽屉/覆盖层，不允许三栏挤压。

具体断点可结合当前 Electron/WebView 窗口能力微调，但必须覆盖 1366×768 和 1600×900。

## 10. 技术实施约束

1. 先识别项目技术栈、页面入口、样式方案、组件库和状态管理方式。
2. 不要凭空假定 React/Vue/Tailwind/Ant Design 等技术；以仓库实际情况为准。
3. 不要在本次视觉改造中改造 Runtime、Jira API、Git 执行逻辑或模型调用链。
4. 抽取布局组件和通用 UI 组件，但避免过度抽象。
5. 业务数据从现有状态/接口读取；不在 UI 中硬编码示例项目和执行结果。
6. 现有功能找不到对应入口时，先追踪其路由和调用链，再决定新位置。
7. 样式使用 Token，避免到处写散落的硬编码颜色。
8. 关键操作必须保持原有事件处理、快捷键和状态行为。
9. 所有新增依赖必须说明必要性，能复用已有库就不新增。
10. 组件拆分应服务于复用和维护，不要为每个小块创建过多文件。

建议组件边界（名称可根据项目现状调整）：

- PrimarySidebar
- ProjectSessionTree
- WorkspaceTopbar
- TaskSummaryHeader

- ChatMessage

## 11. 验收标准

### 视觉验收
- 与当前截图相比，三栏层级清晰，主次关系明确。
- 标题、正文、辅助信息字号层级一致。
- 背景、卡片、边框的明度有区分，不再呈现一整片相近灰黑。
- 图标风格、尺寸和含义统一。
- 中间对话区和输入区比例合理，页面无明显无意义留白。
- 右侧面板在空状态下不占用大量无效空间。
- 1600×900、1366×768 均无横向溢出、控件遮挡和文本截断事故。

### 功能验收
- 当前截图可见的现有功能全部保留且可操作。
- 项目/会话切换不会错乱。
- 右侧 Tab 切换正常，数据和加载状态正确。
- 面板折叠后主工作区正确扩展。
- 发送消息、附件、Runtime、模型、Jira、Git、代码变更等主要交互回归通过。
- 不显示虚构数据或静态假按钮。

### 工程验收
- 运行 lint、typecheck、test、build（以项目已有脚本为准）。
- 没有引入本次改造导致的控制台异常或明显性能退化。
- 输出改造前后截图和修改文件清单。
- 报告所有未完成项及真实原因。

## 12. 最终交付

Codex 完成后必须提供：

1. 改造前问题诊断。
2. 新布局说明。
3. 修改文件清单。
4. 现有功能保留与回归清单。
5. lint/typecheck/test/build 实际执行记录。
6. 1600×900 和 1366×768 运行截图。
7. 未完成项、已知限制和后续建议。

**完成定义：代码已实际修改并运行验证，而不是只生成设计说明、静态 HTML 或截图。**
