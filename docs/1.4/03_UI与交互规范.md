# 03｜右侧 UI 与交互规范

## 1. 改造目标

保留右侧现有两个入口：「上下文」和「执行监控」，但从静态环境说明升级为以当前 Session、本轮 Trace 为中心的运行面板。

不要求复制 Claude Code 的像素风格。采用精工 Agent 现有深色蓝色主题、字体、间距、边框、图标和状态色。优先提高信息密度、层级清晰度和可追溯性。

## 2. 右侧信息架构

```text
右侧面板
├── Jira
├── 子 Agent（现有）
├── 项目工作台
├── Git
├── 项目文件
├── 执行监控（改造）
│   ├── 本轮概览
│   ├── 执行时间线
│   ├── 工具调用
│   ├── Agent 执行树
│   ├── 构建与测试
│   ├── 历史性能趋势 / 当前不可用指标
│   └── 性能策略设置（保留）
└── 上下文（改造）
    ├── 当前会话绑定
    ├── Runtime 与模型
    ├── 工作区索引
    ├── Context Budget
    ├── 上下文来源分类
    ├── 已选来源详情
    └── 未选/排除来源详情
```

## 3. Context Inspector（上下文面板）

### 3.1 顶部：当前会话绑定

卡片建议展示：

| 字段 | 显示规则 |
|---|---|
| 会话类型 | 「项目会话」或「独立会话」 |
| 项目名称 | 从 `session.projectId` 精确查找 `data.projects`；无项目显示「未关联 Git 项目」 |
| Git 项目根目录 | 仅绑定 Project 存在时展示 `project.path` |
| 当前工作目录 | 始终展示 `session.workspacePath`，标签必须是「当前工作目录」 |
| Worktree | 仅识别到 Worktree 时展示分支/路径，否则显示「非独立 Worktree」或不可用 |
| 产品系统 | `session.system`，如 MES5/MES6/WMS/通用 |
| 当前 Runtime | Codex / Claude Agent SDK / Jinggong / Grok Build 等 |
| Provider / Model | 使用 Session 实际配置；Endpoint 只显示 host |
| Reasoning Effort | 显示当前会话选择值 |

**重点：** 禁止继续简单使用左侧全局 `project` 对象表示当前 Session 项目。必须创建 `sessionBoundProject = data.projects.find(p => p.id === session?.projectId)`。如果 session.projectId 为空，即使左侧已选择项目，也必须显示「独立会话」。

### 3.2 项目/会话状态样式

- 已关联项目：显示项目名、根目录、当前工作区，可展开完整路径。
- 独立会话：中性提示「当前为独立会话，未关联 Git 项目；本轮不执行项目索引」。同时展示当前工作目录。
- Project ID 存在但未找到记录：警告「项目记录缺失，需要重新关联」，不要使用另一个 Project 替代。
- 路径不存在/不可读取：显示异常状态与最近错误，不自动改用任意路径。

### 3.3 Context Budget 卡片

展示两种不同口径，不要混成一个上下文窗口进度条：

**A. 应用侧上下文组装预算**

- 构造上下文估算 Token：`context.estimatedTokens`
- 必需上下文估算：`requiredEstimatedTokens`
- 可选来源估算：`optionalEstimatedTokens`
- 可选上下文预算：`budgetTokens`
- 是否必需内容超预算：`requiredOverBudget`
- 去重数量：`deduplicatedCount`
- 裁剪/排除数量：`trimmedCount`、`excluded.length`
- 缓存状态：hit / miss / disabled
- 检索、组装、缓存查找耗时

所有 Token 展示旁必须有「估算」标签或 Tooltip：例如「应用侧组装 4,680 Token（估算）」。预算是应用侧上下文管理预算，不表示模型上下文窗口上限。

**B. 模型实际 Usage（如有）**

- Input / Output / Cache Read / Cache Write / Total
- 右侧注明「Runtime 报告」或「Provider 报告」
- 没有 usage 数据就显示「当前 Runtime 未提供实际 Token 用量」；不能用估算数字填充。
- 模型上下文窗口百分比仅在 limit 和 used 都有可信数据时渲染。否则不渲染进度条。

### 3.4 来源分类概览

使用小型分类列表/网格，按实际 `sourceCounts` 显示：

- 开发规范/系统必需上下文（如果统计完整）
- 用户/项目记忆
- 项目事实
- 项目决策
- Skill 元数据 / Skill 正文
- 数据字典
- 产品操作手册
- 项目资源
- 工作区代码片段
- 任务证据

分类数值来自本轮 Trace 的 ContextBuildStats，不得根据当前已启用资料列表计算“已注入数量”。「已启用」与「本轮选中」要分别展示。

### 3.5 来源明细

默认展示「已选入本轮」列表，支持折叠查看「未选/排除」。每条包含：

- 来源类型、标题。
- Scope：global / project / workspace / session。
- 版本/Hash（可折叠）。
- 路径与行号（工作区代码/文件型资源）。
- 估算 Token。
- 选中理由或排除原因。
- 状态：已选入应用上下文 / 未选入 / 已加载 / 不可用。

可提供过滤器：全部、已选入、已排除、按来源类型。1.0 不需要复杂全文搜索。

### 3.6 当前资料配置与本轮来源区分

页面可保留「当前已启用资料」入口，但与本轮来源列表分区：

- 「可用资料配置」：展示当前系统适用且启用的规范、字典和手册配置；不声称它们本轮都已加载。
- 「本轮实际来源」：展示 Trace 中 selected/loaded/excluded 的真实记录。

### 3.7 上下文空状态

- 尚未发起本轮：显示「发送任务后显示本轮上下文快照」。
- 没有候选来源：显示「本轮没有可选上下文来源」，同时区分必需上下文是否存在。
- Context 优化关闭：显示「上下文优化已关闭，本轮按 Runtime 原始上下文路径执行」，不可展示旧轮来源。
- 性能采集关闭：显示「本轮遥测未采集」，不可复用历史 Trace 伪装当前轮。
- 选择了独立会话：项目索引区显示「独立会话未关联项目」，不报错。

## 4. Execution Monitor（执行监控）

### 4.1 顶部运行概览

建议采用紧凑的统计卡片：

- 本轮状态：排队/初始化/运行中/等待审批/完成/失败/取消/中断。
- 总耗时：Trace 实际运行时长。
- 首个可见响应：明确标注「首个可见响应」，不是「首 Token」。
- 真实工具调用数：只统计 callId 完整/部分配对后的唯一调用；另列「事件通知数」。
- Agent 子任务数：仅当前 Run 明确关联的任务。
- Token Usage：仅展示真实 usage；不支持时显示 N/A。

不要把所有统计卡片都使用高饱和色。状态色仅对失败/警告/运行状态使用。

### 4.2 执行时间线

按时间排序展示 Span：

1. Session/Project 工作区身份确认。
2. Runtime 启动/复用和初始化。
3. 工作区索引检查/更新。
4. Context 检索、来源筛选、预算分配、缓存和组装。
5. Runtime 第一条可见响应。
6. 工具/搜索/文件读取/命令/测试/构建。
7. Agent 子任务。
8. 结果收尾和验证。

要求：

- 显示阶段名称、操作摘要、状态、耗时和开始时间。
- 有父 Span 时可以折叠子步骤。
- 同时发生的阶段按真实起止时间展示，不强制串行化。
- 不展示内部思维链或完整事件正文。
- 点击某个阶段可以打开它关联的工具调用/来源记录（有关联时）。

### 4.3 工具调用明细

表格列：工具/操作、类型、开始时间、耗时、状态、退出码。

- 仅展示 Runtime 提供稳定 `callId` 的调用明细。
- 对应数据源不支持时，显示「当前 Runtime 未提供结构化工具生命周期事件」。
- 开始事件缺失或完成事件缺失的调用，显示「事件不完整」，不计算 duration。
- operation 字符串需脱敏、去控制字符、截断；不展示参数和输出。
- 支持按失败/运行中/全部过滤。

### 4.4 Agent 执行树

- 区分平台受控 AgentTask 和 Runtime 原生 Agent。
- 平台任务来自 AgentTaskRunner 的真实记录；必须与当前 Trace/Run 显式关联。
- 展示主任务、子任务、父子关系、角色、状态、耗时、Runtime/Model（有真实字段时）。
- 展示各 Agent 的结果摘要，但不展开完整任务输入/输出。
- 没有当前轮 Agent 任务时显示「本轮未调用子 Agent」。
- 如果发现同 Session 历史任务但没有本轮 ID 关联，不得加入当前执行树。

### 4.5 构建与测试结果

展示当前轮关联到的验证记录：

- 验证项名称、命令登记名、运行时间、耗时、退出码、状态。
- 状态分类：已执行通过、已执行失败、未执行、环境受阻、未关联。
- 仅从平台 Verification 实际返回的数据展示。
- 测试计划必须明确标「建议/未执行」，不可混成测试结果。
- 与当前 Trace 未建立关联的验证记录不得显示为「本轮验证」。

### 4.6 当前不可采集指标

保留「当前不可采集」折叠区，将 Runtime/Provider 真实缺失的字段列出。建议说明：

- 模型内部队列/推理时间（Runtime 未公开）。
- Provider 输入/输出 Token（当前 Provider 未返回）。
- 模型上下文窗口占用（缺少窗口上限或使用量来源）。
- 部分 Runtime 的原生工具完整参数和输出（为安全不采集）。

不要把“未采集”都解释成故障。

### 4.7 性能策略设置

保留当前 PerformancePanel 既有设置：性能优化总开关、耗时监控、工作区索引、上下文优化、统一上下文、缓存、来源可解释、只读并行、各来源开关/数量上限、Runtime 复用策略、预算和保留天数。设置改动仍遵循现有 idle 限制与验证流程。

## 5. 视觉与组件规范

- 沿用当前精工 Agent 深蓝背景、细边框、文本层级和 CSS Variables。
- 优先复用现有 Icon 组件和按钮/表单样式。
- 右侧面板可调整宽度，最小 320px；在 320–420px 下表格应改为纵向摘要卡片，不允许横向溢出。
- 标题 14–16px，正文 12–13px，辅助信息 11–12px；遵循当前项目字体体系。
- 数值使用等宽数字；毫秒、秒、Token、文件数统一格式。
- 列表默认折叠长尾；超过 20 条分页或虚拟滚动，不一次性渲染所有历史 Event。
- Loading、Empty、Unavailable、Error、Running、Completed、Failed 六种状态必须完整。
- 提供 aria-label、键盘可操作性、焦点状态。

## 6. 状态与刷新

- 沿用 `PerformancePanel` 当前每 2 秒 report/indexStatus 刷新的机制，优先避免全量拉取过大的历史 Trace。
- Context Inspector 复用同一次 report 请求的缓存/状态，不同时重复请求。
- 面板隐藏时降低或暂停轮询；重新打开时立即拉取一次。
- Session 切换时清空旧快照，并使用 active 标志/AbortController 防止旧请求覆盖当前状态。
- 最新 Trace 尚未结束时显示实时累计总耗时；结束后显示定值。
- 没有新 Trace 时显示最新一轮完成数据，并清楚标记 Trace 创建时间，避免误以为是正在发生的运行。

## 7. 推荐拆分组件

建议（名称可调整）：

- `ContextInspectorPanel.tsx`：上下文面板主组件。
- `ContextBudgetCard.tsx`：应用侧预算与真实 Usage 的分离展示。
- `ContextSourceList.tsx`：已选/排除来源明细。
- `ExecutionMonitorPanel.tsx`：可由现有 `PerformancePanel.tsx` 演进，不要求重复组件。
- `ExecutionTimeline.tsx`：Span 时间线。
- `ToolCallsTable.tsx`：结构化调用明细。
- `AgentExecutionTree.tsx`：当前轮子 Agent 树。
- `VerificationSummary.tsx`：真实构建/测试记录。

组件拆分以减少 `App.tsx` 复杂度为目的，避免每项信息都单独创建一个新组件造成过度工程化。
