# 05｜测试与验收矩阵

## 1. 测试原则

- 测试数据分为单元测试构造数据与真实 Runtime 集成数据；Mock 只能用于验证纯逻辑，不能作为真实 Runtime 交付证据。
- 时间、Token、调用数量必须验证口径和来源。
- 任何无关联、不可用、未执行的数据必须保持空值/未知状态，不得自动补齐。
- 旧版本数据读取和设置兼容必须有回归测试。

## 2. Trace / Session / Project 关联

| ID | 场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| T-001 | 项目 Session | session.projectId 指向 Project A | Trace.projectId=A；UI 展示 Project A |
| T-002 | 左侧选中不同 Project | Session 绑定 A，左侧当前选中 B | Context Inspector 仍展示 A，不展示 B |
| T-003 | 独立 Session | session.projectId 为空，workspacePath 有值 | 显示独立会话；工作目录单独显示；不显示 Git 项目根目录 |
| T-004 | Project 缺失 | session.projectId 有值但 Project 列表未返回 | 显示项目记录缺失；不能退化到左侧其他项目 |
| T-005 | 同一 Session 连续两轮 | 发送任务 1、任务 2 | 生成两条独立 Trace；最新 Trace 对应任务 2 |
| T-006 | 两个 Session | 各自运行一轮 | report(session A) 不包含 Session B 数据 |
| T-007 | Session 切换竞态 | 快速 A->B | A 请求返回不能覆盖 B 面板 |
| T-008 | Worktree | 当前 Session 使用独立 Worktree | Project Root 与 Worktree/Workspace Path 分开显示 |
| T-009 | 无 Run ID | 运行流程无法提供可靠 Run ID | runId 留空并显示不可关联，不使用 sessionId 冒充 |
| T-010 | 历史 v1 Trace | 加载旧 PerformanceState | 数据可读，新增关联字段为空，不丢失设置/Trace |

## 3. Context Snapshot / Token 口径

| ID | 场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| C-001 | 规范资料 | 本轮启用且实际进入 requiredText | 统计到必需上下文；无法分项时只显示汇总估算 |
| C-002 | 已启用未加载资料 | 配置中启用但本轮未检索/未选择 | 只出现在可用资料区，不记为本轮 selected |
| C-003 | 来源选中 | Planner/Optimizer 选择一个 Dictionary | 来源明细显示 selected、reason、Hash 和 estimated Token |
| C-004 | 来源排除 | 项目范围不匹配 | 显示 excluded 和准确原因 |
| C-005 | 超预算 | 多个可选来源超出预算 | 显示类别/全局预算排除原因与 trim 数量 |
| C-006 | 去重 | 两个相同 Hash 来源候选 | 去重数量增加，排除原因是重复来源 |
| C-007 | 必需上下文超预算 | requiredEstimatedTokens > budgetTokens | 显示超预算警告；确认必需上下文未被裁剪 |
| C-008 | Token 估算 | 使用 estimateContextTokens | 必须显示「估算/应用侧」，不得显示成真实 Input Tokens |
| C-009 | 无 Provider Usage | Runtime 未返回 usage | Input/Output/Total 显示不可用，不回填估算值 |
| C-010 | Provider Usage 部分字段 | Provider 只提供 inputTokens | 只展示 Input；Output/Total 按字段语义显示不可用，不虚构 |
| C-011 | 无 Context Trace | 尚未发起任务 | 显示发送任务后查看，不复用历史 Trace 冒充本轮 |
| C-012 | 性能采集关闭 | telemetryEnabled=false | 显示本轮未采集，不阻断任务 |
| C-013 | Runtime Context fallback | 检索失败调用 fallbackText | Trace 阶段标记 unavailable；Runtime 继续原路径执行 |
| C-014 | 跨项目资料 | candidate.projectId 与当前项目不同 | 不注入，不显示为 selected |
| C-015 | 会话历史隔离 | 同 Session 以前的对话存在 | 不作为 Context Source 列表来源；只显示本轮实际上下文候选 |

## 4. Runtime / Tool Call / Timeline

| ID | 场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| R-001 | Runtime 启动 | 收到 spawn start/end | Span 正确计算本地实际耗时 |
| R-002 | 首个可见响应 | 收到首条非空 delta/message | 显示首个可见响应，不显示成模型首 Token |
| R-003 | Tool 正常配对 | 同 callId started + completed | 一条工具调用，耗时由本地时间差计算 |
| R-004 | Tool 缺开始 | 只有 completed | 标记 complete_only，无 duration |
| R-005 | Tool 缺结束 | 只有 started，Trace 结束 | 标记 start_only/interrupted，不标记成功 |
| R-006 | 重复 completed | 同 callId 重复通知 | 幂等，不重复计数、不重复完成 Span |
| R-007 | 不同 callId | 两次工具执行 | 统计两次独立调用 |
| R-008 | 无 callId 的 tool event | 只有 `event.type=tool` | 仅增加事件通知数，不增加真实工具调用数 |
| R-009 | 退出码 0 | completed + exitCode 0 | 按 Runtime 事件含义标记完成 |
| R-010 | 非零退出码 | completed + exitCode 非 0 | 标记失败，并展示退出码 |
| R-011 | exitCode 未知 | completed + null/undefined | 不推断命令成功，状态按实际数据标识 |
| R-012 | 并行 Span | 两个重叠 Span | 时间线显示重叠，总耗时仍按 Trace 开始/结束时间计算 |
| R-013 | Runtime 不支持 | 某 Adapter 不发结构化事件 | 显示 Runtime 未提供，不造假调用列表 |
| R-014 | 错误/取消/中断 | Runtime 失败或取消 | Trace 和未结算 Span 正确落终态 |
| R-015 | Telemetry 写入失败 | 存储 save 抛错 | 原 Runtime 任务不被阻断 |
| R-016 | 超过事件上限 | 大量工具事件 | 保留限制内摘要并显示截断/上限提示，不无限增长 |

## 5. Agent / Verification

| ID | 场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| A-001 | 当前轮有 AgentTask | task 显式关联 runId/turnId/orchestrationId | 展示在当前轮 Agent 树 |
| A-002 | 同 Session 历史 AgentTask | task 属于旧轮，无本轮关联 | 不显示在当前轮树 |
| A-003 | Native Agent 未提供事件 | Runtime 无 Agent 事件 | 不虚构原生 Agent 树 |
| A-004 | 多类型 Agent | 平台 AgentTask 与 Runtime Native Agent 同时存在 | 标记来源类型，不混为同一种 Agent |
| A-005 | 子任务失败 | 子任务失败 | 显示失败状态和短摘要，不展开完整输出 |
| V-001 | 本轮构建通过 | Verification 有明确 Run 关联、exitCode 0 | 显示已执行通过 |
| V-002 | 本轮构建失败 | exitCode 非 0 | 显示已执行失败 |
| V-003 | 仅有测试计划 | 未启动测试 | 显示建议/未执行，不标记通过 |
| V-004 | 环境受阻 | 缺工具链/网络/授权 | 显示环境受阻与原因 |
| V-005 | 历史验证无关联 | 只有 Session 相同，无 Run 关联 | 不显示成当前轮验证 |

## 7. 安全与数据保护

| ID | 场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| S-001 | API Key 出现在 operation/text 中 | 输入模拟凭据 | 脱敏后保存/导出 |
| S-002 | 工具参数含业务数据 | Runtime Event 含自定义参数 | 不保存原始参数和输出 |
| S-003 | 用户消息正文 | Trace 触发 | 不新增持久化保存完整正文的行为 |
| S-004 | Trace IPC 越权 | A Session 请求 B Trace | 主进程拒绝并返回受控错误 |
| S-005 | 端点脱敏 | URL 带 path/query/token | 只保留 scheme + host |
| S-006 | 恶意上下文资料 | 项目代码/手册包含 prompt injection | 只记录来源元数据；不执行资料内指令 |
| S-007 | 数据保留策略 | 保留天数到期 | 按既有 prune 规则清理旧数据 |

## 8. 最终回归清单

- `npm run build`
- `npm test`
- `npm run test:desktop`
- 当前仓库实际定义的其他受影响专项测试。
- 至少人工运行一次 Codex Runtime 与 Claude Agent SDK Runtime，验证真实面板数据。若环境无法运行某 Runtime，必须注明未执行原因，不以 Mock 取代。
- 若有改动涉及 Jinggong/Grok Runtime，同样进行对应的真实冒烟测试；若该环境没有配置，列为未执行。
- 记录实际命令、退出码和结果，不可只写「测试通过」。
