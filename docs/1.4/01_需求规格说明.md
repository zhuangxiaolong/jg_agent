# 01｜精工 Agent Runtime 可观测性中心 1.0 需求规格说明

## 1. 项目背景

精工 Agent 已支持 Codex、Claude Agent SDK、Jinggong Runtime、Grok Build ACP 等运行时，并已有基础性能遥测和上下文优化能力。但右侧面板的信息组织比较基础：

- 「上下文」更多是当前项目、目录、系统、Runtime、模型中转站和已启用资料的环境摘要，没有把本轮真正参与组装的上下文来源、选中/排除原因、来源 Token 估算集中呈现。
- 「执行监控」已经能显示总耗时、Runtime、Provider、模型、首个可见文本、工具事件通知数、上下文统计和部分执行阶段，但缺少结构化工具调用明细、当前 Run 关联、Agent 子任务视图和更明确的数据可信度标签。
- 当 Session 没有关联 Project 时，工作区索引显示「未关联项目」是正确的；但界面必须明确区分「独立会话工作目录」与「项目 Git 根目录」，不能让用户误以为项目已关联。
- 当前上下文统计中的 Token 是应用侧估算值，不是模型服务报告的真实 prompt token。部分 Runtime 不公开模型 Token 用量，也不一定提供完整工具生命周期。

因此，本项目目标不是简单仿制 Claude Code 的上下文条，而是建立一套跨 Runtime、可追溯、诚实标注数据来源的运行观测能力。

## 2. 产品目标

用户在任意会话的一轮任务中，可以快速回答以下问题：

1. **本轮绑定了什么项目和工作区？** 实际 Git 项目、工作区目录、Worktree、系统类型和 Runtime 是否明确？
2. **AI 本轮看到了哪些资料？** 哪些规范、字典、手册、项目事实、记忆、Skills、代码片段被检索、筛选并组装？为什么被选中或排除？
3. **上下文用了多少？** 应用侧构造的必需上下文和可选上下文各是多少估算 Token？是否超预算？实际模型 Token 若 Runtime 没报告，必须明确标为不可用。
4. **AI 本轮做了什么？** Runtime 启动、初始化、上下文检索、模型可见响应、工具调用、命令/测试/构建等阶段的状态、耗时与失败信息是什么？
5. **是否有子 Agent 参与？** 仅展示能与本轮 Run 明确关联的任务，不把历史任务或同 Session 的其他轮次混进来。
6. **结果有没有验证？** 构建、测试等仅展示平台真实采集的执行记录和结果，不把建议计划或未执行命令显示为通过。

## 3. 产品范围

### 3.1 本期必须实现（P0）

- 一轮用户提交生成独立 Trace，并关联 sessionId、turnId/runId（以当前 RunLifecycle 可提供的真实 ID 为准）、projectId、workspaceId、worktreeId、runtimeKind、providerId、modelId。
- 当前 Session 项目绑定信息正确显示：以 `session.projectId` 查找真实 Project；未关联时显示「独立会话」，不使用左侧当前选中 Project 代替。
- 明确区分 `projectRoot`、`workspacePath`、`worktreePath`。没有 Project 时，不把 `%LOCALAPPDATA%` 下的会话数据目录冒充 Git 项目目录。
- 复用现有上下文检索/优化结果，按本轮 Trace 显示实际选中、排除、去重、裁剪和来源数量。
- Token 指标标识测量口径：当前已有的 `estimated` 必须显示「估算」；实际 Runtime usage 必须有明确来源字段；不可用时显示「暂不可用」。
- 右侧「上下文」改造成 Context Inspector；「执行监控」改造成 Execution Monitor。
- 历史 Trace 与当前 Trace 区分；切换 Session 必须重新加载对应报告。
- 保留当前性能策略配置、索引重建、性能数据导出、测试计划等已有功能。

### 3.2 本期应实现（P1）

- 工具调用列表：优先用 `RuntimeEvent.performance.callId` 对 `started/completed` 事件配对，展示名称、类别、状态、耗时、退出码（若可用）。
- 执行时间线：以统一 Span/Event 模型展示启动、初始化、检索、预算分配、上下文组装、首个可见响应、工具执行、验证、收尾。
- 子 Agent 任务树：只展示当前 Trace/Run 下明确关联的 AgentTask，含角色、状态、开始结束时间和摘要；不显示完整任务输入输出正文。
- 验证摘要：展示与当前 Run 有明确关联的构建/测试记录；状态分为通过、失败、未执行、受阻、未采集。
- 当前运行状态可刷新，沿用已有轮询机制，避免新增复杂实时消息总线。

### 3.3 本期可选（P2，不能阻塞 1.0）

- 同一 Runtime/Provider/Model 配置的历史趋势、P50/P90 对比。
- 缓存命中率、模型成本估算、工具失败率趋势。
- 将同一个 Trace 导出为可阅读的 HTML/Markdown 诊断报告。

## 4. 非目标与明确禁止

- 不重写 Codex App Server、Claude Agent SDK 或其他 Runtime Adapter。
- 不自行实现新的模型调用循环、Agent 调度器、第二套任务 Runner。
- 不要求模型输出隐藏推理，也不保存 Chain of Thought。
- 不通过扫描完整聊天记录或会话历史来“补足”本轮上下文来源。
- 不伪造模型 Token、模型调用次数、工具调用次数、模型队列耗时、子 Agent 或验证结果。
- 不用静态假数据、Mock 数据或固定样例冒充真实 Runtime 展示。
- 不将所有工具都强制包装为精工自定义工具；原生 Runtime 自身的执行策略和权限体系保持不变。
- 不为展示 Token 使用量而擅自把完整 prompt、消息正文、工具参数和结果持久化。

## 5. 当前实现基线和具体差距

> 下述为本开发包编写时对 `develop/desktop-poc` 的核对结果。Codex 实施前需重新核对。

| 当前文件/能力 | 已有实现 | 本次需要补充 |
|---|---|---|
| `packages/performance/src/types.ts` | PerformanceTrace、Span、ContextBuildStats、PerformanceState v1 | 增加本轮/项目关联、结构化事件/工具摘要、可选真实 Usage 元数据和兼容迁移 |
| `telemetry.ts` | 记录 Trace、Span、Runtime 事件、首个可见响应、上下文统计；最多保留 200 条 Trace、每条最多 1500 Spans | 更明确的 Run/Turn 关联、结构化事件、稳定调用 ID 统计、异常未配对事件和数据可信度 |
| `RuntimeEvent.performance` | 有 callId、phase、operation、stage、exitCode | 补齐真实来源能力，保留未知/不支持状态；不能靠普通 `tool` 通知反推调用数 |
| `context-retrieval.ts` | 来源过滤、排序、范围检查、排除原因 | 将本轮候选、最终选中/排除记录稳定绑定到 Trace |
| `context-optimizer.ts` | 必需/可选估算 Token、预算、去重、裁剪、来源 Token 摘要 | 将统计结果在 UI 上准确解释为应用侧估算，不等同模型实际 Prompt |
| `performance-service.ts` | 工作区索引、Context Retrieval/Build、Trace 管理 | Trace 使用唯一轮次 ID；明确 Project/Workspace/Worktree 关系；提供只读快照 |
| `PerformancePanel.tsx` | 性能设置、索引、基础指标、来源详情、时间线、历史基线、测试建议 | 重新组织信息层级，增加工具调用、Agent、验证和数据可信度说明 |
| `App.tsx` Context Tab | 项目、目录、系统、Runtime、Provider、已启用资料、本机环境 | 根据当前 Session 绑定，而不是左侧当前选中项目；展示本轮真实上下文来源和状态 |
| `performance:*` IPC | 已有 report/settings/export/index/test-plan 等接口 | 优先扩展已有 report，避免重复建 API；所有会话数据仍必须做 session 所有权校验 |

### 特别需要修复的项目关联逻辑

当前 `App.tsx` 右侧 Context 区域使用 `project?.name` / `project?.path` 展示「当前项目」，但会话本身可以是独立会话，也可能与当前左侧选中项目不同。1.0 必须按以下顺序解析：

1. 若 `session.projectId` 存在，从 `data.projects` 中按 ID 查找对应 Project。
2. 查找到时显示该 Session 绑定的 Project 名称和 Git 根目录；同时独立展示 `session.workspacePath`，若是 Worktree 则显示 Worktree 路径。
3. `session.projectId` 为空时显示「独立会话 / 未关联 Git 项目」，`session.workspacePath` 只能标记为「当前会话工作目录」，不得显示成 Git 项目目录。
4. 找不到 Project 记录时显示「项目记录缺失/需要重新关联」，不能自动按目录名称或历史会话推断项目。
5. 不展示其他 Session 的 Trace、Context Source、聊天历史或子 Agent 记录。

## 6. 角色与使用场景

### 场景 A：开发者检查 AI 是否读取正确规范

用户选择一个 MES6 项目会话，打开「上下文」：看到项目绑定为 MES6 工程、工作区路径、MES6 系统类型；本轮选中了开发规范、MES6 字典、项目事实、操作手册和相关代码片段。用户展开来源，可以查看文件/文档名、版本、Hash、检索原因、Token 估算、是否最终组装，以及排除原因。

### 场景 B：排查模型响应慢

用户打开「执行监控」：能区分 Runtime 启动、初始化、上下文检索、组装、首个可见响应和工具执行的实测时间。若模型内部队列或真实首 Token 时间没有公开数据，则显示「Runtime 未提供」，不能用首个可见 delta 伪装成模型首 Token。

### 场景 C：排查工具调用是否卡住

工具调用表展示稳定 callId 配对的 started/completed 记录；没有完整事件时显示「开始/结束事件不完整」，不生成虚假耗时。失败命令只显示已允许展示的操作名、阶段和退出码，不持久化完整命令参数或输出正文。

### 场景 D：检查 Agent 子任务

当前轮确实创建了受控子 Agent 时，查看本轮执行树。历史 AgentTask 只有在 Run/Turn 关联明确时才可出现；否则单独标明「无法关联到本轮」，默认不加入本轮树。

## 7. 功能需求明细

### FR-01 当前 Session 项目与工作区身份

- 展示 Session ID 的短标识、Session 类型（项目会话/独立会话）、Project、Git 根目录、当前 Workspace、Worktree、系统类型。
- 展示 Git 分支/工作区是否 dirty（已有信息可用时）；不为可观测性面板额外执行高成本 Git 操作。
- 不允许从会话标题、聊天内容、目录名或最近使用记录自动猜测 Project。
- 对索引状态展示「未关联项目、未建立、索引中、可用、失败、已关闭」等真实状态。

### FR-02 当前 Runtime 身份

- 展示 Runtime 类型与版本（有可信版本字段才显示）、Provider、模型 ID、Reasoning Effort、endpoint host。
- API Key、Authorization、完整 URL query、凭据、环境变量不得展示或保存。
- 模型上下文窗口上限只有在模型元数据/供应商数据明确提供且与当前模型配置匹配时才展示；否则显示「未提供」。

### FR-03 本轮 Context Snapshot

- Trace 绑定当前一轮请求的上下文统计。
- 来源分类沿用 `ContextSourceType`：memory、project_fact、project_decision、skill_metadata、skill_body、dictionary、operation_manual、project_resource、workspace_code、task_evidence。
- 另行呈现必需开发规范/系统指引等应用侧必需上下文；如果无法准确分项统计，应标注「整体估算」而不是拆出虚构分类。
- 每个来源展示来源类别、标题、来源 ID（必要时脱敏/截断）、scope、Hash、版本、路径/行号、选中/排除状态、原因、估算 Token。
- 选中意味着通过本地预算组装器写入本轮发送的应用管理上下文；不代表模型内部必然完整读取或注意到每个 Token。
- 排除原因至少保留现有的：来源关闭、状态不可用、项目/工作区/会话范围不匹配、系统不匹配、关键词未命中、达到条数上限、重复 Hash、类别预算不足、全局预算不足。

### FR-04 Token 统计口径

UI 必须同时支持以下状态标签：

- `实际 / Runtime 报告`：Runtime/Provider 明确返回 usage 数据，并记录来源。
- `估算 / 应用侧`：通过 UTF-8 字节或字符估算得出；当前 `estimateContextTokens()` 即属于此类。
- `不可用`：当前 Runtime/Provider 没有公开数据。
- `未采集`：本轮尚未完成对应阶段或采集功能关闭。

禁止将 `ContextBuildStats.estimatedTokens` 显示成模型窗口整体使用量。推荐分别展示：

1. 应用侧管理上下文估算：required + optional、预算、超预算、去重、裁剪。
2. Runtime/Provider 报告的模型 Usage：input/output/cache/total tokens，字段缺失就显示 `—`。
3. 模型上下文窗口：limit/used 只有来源明确时才展示；否则不显示百分比进度条。

### FR-05 执行 Trace 与 Span

- 每一轮请求创建独立 Trace；Trace 至少包含 startedAt、endedAt、status、totalDurationMs。
- Span 支持开始、结束、失败、取消、中断、不可用状态；记录 parentSpanId/correlationId（可选）。
- 阶段至少覆盖 Runtime 启动/初始化、项目绑定/索引、Context 检索、预算分配、组装、模型可见响应、工具、命令、测试/构建、结束收尾。
- 并行 Span 不应被简单累加成总耗时；总耗时以 Trace 的真实开始/结束时间计算。
- 首个可见文本应继续标记为「首个可见响应」，不要命名成「模型首 Token」除非 Provider 精确提供该指标。

### FR-06 工具调用追踪

- 以 `RuntimeEvent.performance.callId` 为首选关联标识；同一 callId 的 started/completed 配成一条调用。
- 每条调用展示 operation、stage、status、startedAt、endedAt、durationMs、exitCode（如果有）。
- 对孤立 started、孤立 completed、重复事件、缺少 ID、超时未结束等情况给出明确状态。
- `event.type === 'tool'` 计数只能称为「工具事件通知数」，不能称为调用次数。
- 不记录完整工具参数、完整执行输出、敏感命令内容和文件正文。

### FR-07 子 Agent 观测

- 仅展示与当前 Trace/Run 显式关联的 AgentTask。
- 优先使用现有 AgentTask 的 taskId、orchestrationId、父任务关联、创建/开始/结束时间和状态。
- 若当前模型/Runtime 没有原生 Agent Teams 事件，UI 不得显示假的原生 Agent 树。
- 区分「平台受控子 Agent」与「Runtime 原生子 Agent」；数据来源不混用。
- 展示角色、名称、状态、耗时、使用的 Runtime/Model（真实字段可得时）、结果摘要长度受限；不得默认展开原始输入输出。

### FR-08 构建与测试验证

- 关联当前 Run 的验证记录，展示执行命令的登记名称、开始/结束时间、进程状态、退出码、耗时和报告路径（只有真实返回时）。
- 状态标签：已执行通过、已执行失败、未执行、环境受阻、无可关联记录。
- 「测试建议」不是「测试已执行」；未执行计划不可显示成功率或通过标记。
- 如果当前记录模型无法与 Trace 准确关联，显示在「最近验证记录（非本轮关联）」或暂不展示，不得猜测。

### FR-09 实时刷新与历史查看

- 保留现有 2 秒级轮询模式作为 1.0 默认实现；轮询期间页面隐藏时应暂停或降低频率。
- 当前 Trace 实时状态更新；会话任务完成后保留该轮快照。
- 可查看当前 Session 的历史 Trace 列表，但默认只展开最新一轮；不能跨 Session 混合。
- 切换 Session/关闭面板时取消旧请求，防止旧结果覆盖新 Session。

### FR-10 导出与设置兼容

- 继续使用现有 `performance:export`、`performance:export-diagnostics`、`performance:settings`、`performance:index-status`、`performance:index-rebuild`、`performance:test-plan` 等接口。
- 导出数据必须脱敏，且保留 `estimated/reported/unavailable` 等测量口径。
- 现有性能设置、索引、测试策略功能不能因 UI 重构而丢失。

## 8. 验收目标

- 用户能明确知道当前 Session 是否关联 Git 项目；独立会话不会被显示为一个已关联项目。
- 有真实上下文候选的轮次，能查看最终入模前由应用管理上下文组装器选中/排除的来源与原因。
- 没有来源/没有项目/没有工具事件时，显示明确空状态，不显示虚构样例。
- 至少 Codex 与 Claude Agent SDK 两种 Runtime 的基本 Trace 可用；某一 Runtime 缺少字段时按能力标注不可用，而不是回退为猜测值。
- 所有新增/扩展测试通过；项目正式 build 和 test 命令通过。
