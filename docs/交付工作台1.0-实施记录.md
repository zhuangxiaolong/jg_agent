## 1. 实施结论

已完成交付工作台的本地单机 P0 数据管理骨架和可用桌面页面，现有研发工作台、原有 DeliveryPanel、Runtime、专家中心、Jira、操作手册和 Excel 映射功能保持原有入口。

## 2. 功能完成范围

### 已实现

- 独立“交付工作台”一级入口、总览、项目列表和项目详情。
- 客户交付项目新建、编辑、归档、搜索、按系统类型/阶段/项目经理筛选、按更新时间/计划结束日期排序。
- 项目经理、成员、系统类型、阶段、计划日期、Jira Key 和可选本地代码项目关联。
- 里程碑新增、编辑、删除、排序和状态管理。
- 任务新增、编辑、删除、状态/负责人/优先级/逾期筛选，以及最多 100 条的人工多行批量录入。
- 问题、阻塞、风险、待确认和需求变更记录的新增、编辑、删除和筛选。
- 会议纪要新增、编辑、删除和项目动态留痕。
- 项目活动追加记录，子记录按 `deliveryProjectId` 隔离，错误项目归属会被主进程拒绝。
- 项目资料通过主进程文件选择器导入，复制到应用管理目录，保存类别、文件名、大小、SHA-256、相对路径和导入时间。
- 资料导入限制为普通单文件且不超过 50 MiB，拒绝符号链接、硬链接、路径越界和导入期间文件变化。打开资料前重新校验路径、大小、链接状态和 SHA-256，变化后标记为过期。
- 交付总览的进行中项目、未完成任务、逾期任务、逾期/临近里程碑、高优先级未关闭问题和需关注项目统计。
- 确定性健康规则和可解释原因，包括 Critical 问题、阻塞项、逾期里程碑、逾期 High 任务、7 天内里程碑、High 问题、长期未更新及数据不足。
- 周报和风险巡检数据草稿的生成、编辑、保存、复制和 Markdown 导出，报告保存来源快照 SHA-256 并显示周期与数据限制。
- 从交付项目进入现有 Excel 映射工作流，传递已关联本地代码项目、系统类型和产品版本，不把交付项目 ID 当作代码项目 ID。

### 未实现或待后续接入

- 真实 Runtime/模型驱动的周报、风险摘要、计划草稿和会议行动项抽取。
- 操作手册引用式问答、上线准备清单、项目 JSON/ZIP 备份导入导出。
- AI 任务或计划草稿的逐项确认写入流程。
- 服务端同步、多人协作、组织账号和权限体系。
- Jira 双向同步。当前只保留项目 Key 字段。
- 项目经理、实施工程师、交付负责人角色快捷预设，以及按个人显示名汇总的跨项目“我的任务”视图。当前可在单个项目任务列表按负责人筛选。

## 4. SQLite 迁移与备份

技术方案以 schema 21 为文档基线。检查当前工作区时，已有数据库迁移已达到 schema 22，因此本次实际从 **22 迁移到 23**，没有回写或覆盖历史表。

schema 23 新增交付工作台表和索引，并保留外键项目归属。应用在发现旧数据库需要升级时，先复制原始 SQLite 字节到同目录，文件名格式为 `*.pre-v23-from-v<旧版本>-<时间>-<随机值>.bak`，再在事务中执行迁移。数据库版本高于 23 时拒绝打开并保留原文件。

## 5. Runtime、AI 与资料外发边界

- Renderer 不接触 SQLite 句柄、任意磁盘路径或模型 API。
- 当前报告生成只读取本地结构化记录，并使用主进程计算的 SHA-256 来源快照。没有外发项目资料，也没有读取凭据、Token 或客户生产环境密码。
- 报告按任务当前 `updatedAt` 做周期筛选。没有历史变更快照时，正文会说明无法还原历史状态，不推断周期内完成事项。
- 资料正文只复制到当前用户本地应用管理目录 `delivery-workbench/<deliveryProjectId>/`。IPC 打开前执行 `realpath`、路径边界、普通文件、硬链接和 SHA-256 校验。
- 真实 AI 接入必须复用现有 Runtime/Session 体系，并补充只读交付项目上下文、权限边界、模型失败处理和草稿确认流程后再宣称完成。

## 7. 人工验收步骤

1. 启动桌面端，进入“交付工作台”，新建一个客户交付项目，填写 MES5、MES6 或 WMS、阶段、计划日期和项目经理。
2. 在项目详情新增里程碑、任务、问题/风险和会议纪要，确认总览统计、逾期标识、健康原因和项目动态变化。
3. 使用“多行录入”一次新增多条任务，检查负责人、优先级、逾期和状态筛选。
4. 导入一个普通资料文件，检查类别、大小和 SHA-256。修改或替换受管文件后尝试打开，确认文件被标记过期并要求重新导入。
5. 生成周报和风险巡检草稿，编辑后保存、复制和导出 Markdown，确认正文保留来源快照和数据限制说明。
6. 为交付项目关联已有本地代码项目，从项目入口打开 Excel 映射工作流，确认进入的是原有映射页面且代码项目 ID 没有被交付项目 ID 替换。
7. 复核现有研发会话、专家中心、Jira、操作手册、数据字典和原有开发交付证据包入口。
8. 若要验收真实 AI，需要配置并验证现有 Runtime 后，再单独补做受限交付上下文、事实/规则/建议分栏、草稿确认和失败处理验收。
