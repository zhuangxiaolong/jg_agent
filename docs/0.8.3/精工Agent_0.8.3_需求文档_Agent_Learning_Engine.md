# 精工 Agent 0.8.3 需求文档：Agent Learning Engine

版本：0.8.3  
前置版本：0.8.1 Memory Engine、0.8.2 Skill Intelligence Engine  
目标：让精工 Agent 从已完成任务中沉淀可复用的开发方法，并通过审核、版本、效果记录形成受控学习闭环。

## 1. 定位

0.8.1 解决“记住用户和项目事实”；0.8.2 解决“找到并加载已有 Skill”；0.8.3 解决“从真实任务中发现值得复用的方法，并将其整理成新 Skill”。

Memory 与 Skill 必须明确区分：

- Memory：用户偏好、长期约束、项目事实、决策和经验摘要。
- Skill：可以重复执行的流程、检查清单、代码模式、验证步骤和资源引用。
- Knowledge：数据字典、产品规范、项目文档和可查询事实。

不能把所有历史对话变成 Skill，也不能把模型回答当成经过验证的知识。

## 2. 目标

1. 识别适合沉淀为 Skill 的已完成任务。
2. 为任务生成 Skill Candidate（候选），候选包含来源、步骤、适用范围、前置条件、反例和验证证据。
3. 用户可审阅、编辑、拒绝或发布候选。
4. 发布后的 Skill 使用现有 Plugin Manager / Skill Catalog 管理，并具有版本、Hash、来源和启用范围。
5. Skill 调用与任务结果关联，记录使用次数、加载成功率、验证结果和人工反馈。
6. Skill 可升级、弃用、恢复历史版本，不静默覆盖正在使用的版本。

## 3. 非目标

- 不做模型微调、训练私有模型或自动修改 GPT/Claude/Grok 权重。
- 不把未经审核的候选自动发布或自动启用。
- 不在任务执行结束时额外自动调用模型，避免增加完成延迟和模型费用。
- 不自动把客户数据、数据库记录、生产凭据、完整项目代码或原始 Jira 内容写入 Skill。
- 不替代 0.8.1 Memory Engine；不重写 0.8.2 Skill Loader。
- 不声称 Skill 导致了任务成功；统计关联效果，不做未经实验的因果结论。

## 4. Skill 候选来源与门槛

### P0：可进入候选流程的来源

- AgentTask 已完成任务，且绑定当前 Task Contract。
- 任务对应的真实 Verification Run / TaskEvidenceRecord。
- 与该任务直接相关的 Skill Usage Event。
- 用户主动选择的会话/任务内容片段。
- 用户显式纠正或说明“这次做法以后可复用”。

### 候选准入规则

自动生成候选只在以下条件满足时可用：

1. 任务执行状态为完成，不是 FAILED、CANCELLED、INTERRUPTED 或 BLOCKED。
2. 如果任务涉及代码修改，必须有当前契约版本关联的真实构建/测试证据；证据状态为 passed，且代码指纹未变化。
3. 如果任务属于纯分析/设计/文档任务，至少有明确任务来源、人工确认或有效交付物引用；标记为“未经过代码验证”，不可冒充测试通过。
4. 候选包含可复用步骤，而非某一客户的特定值或仅对本次任务成立的结论。
5. 自动敏感信息扫描未发现凭据、个人敏感数据或未脱敏客户资料。
6. 与既有 Skill 相似度/规范化标题去重检查通过，或明确提示合并到已有 Skill。

失败任务可作为“反例/风险经验”候选，但必须单独标记，不能直接成为可执行流程 Skill。

## 5. 用户场景

**场景 A：任务完成后生成候选**

MES6 接口开发任务完成并且构建、自动化测试通过。任务详情显示“可沉淀经验”，用户点击“生成 Skill 草稿”。平台整理任务契约、已调用 Skill、验证证据、关键流程和人工反馈，生成候选草稿。

**场景 B：用户确认或修改**

用户在候选编辑页检查 Skill 名称、描述、适用系统、步骤、脚本和引用资源，删除客户特定数据，补充前置条件和验证命令。候选经验证后可以发布。

**场景 C：合并已有 Skill**

如果候选与已有“MES6 API 开发”相似，平台展示相似项和差异，用户可选择创建新 Skill、更新为新版本或放弃。禁止自动覆盖当前生产版本。

**场景 D：Skill 效果反馈**

下一次任务使用该 Skill。任务完成后将实际执行与验证证据关联，显示“已加载、是否按步骤执行、验证结果、用户反馈”。

**场景 E：失效和回滚**

新版本引入错误，用户可停用该版本并回滚到上一个已审核版本；已有会话 Snapshot 保持原 Hash，不能静默替换。

## 6. 功能需求

### P0-01 候选发现

- 任务详情新增“经验沉淀”区域。
- 仅满足准入规则的任务提供生成候选入口。
- 可手动选择任务事件和输出片段作为来源，不默认复制全部历史。
- 一项候选可关联一个或多个任务，但必须区分来源证据和模型生成的推断。
- 失败/中断任务可生成“问题复盘候选”，默认不属于可执行 Skill。

### P0-02 候选草稿结构

每个 Candidate 至少包含：

- 标题、名称、description、tags、适用系统（MES5/MES6/WMS/通用）。
- 适用任务类型、适用版本/模块（可选）。
- 前置条件和不适用场景。
- 可复用步骤、关键检查点、期望结果。
- 常见错误和恢复方法。
- 必须由用户提供的输入参数。
- 验证方法与验收清单。
- 参考资源（只引用脱敏、可授权的文件或文档）。
- 证据列表、来源任务 ID、Task Contract Version、Verification Run ID、代码指纹。
- 生成方式与不确定性标记。

候选的模型推导内容必须标记“草稿/待审核”，不得标记为已验证事实。

### P0-03 生成方式与费用

- 默认不在任务完成回调中发起额外模型请求。
- 本地可先生成确定性骨架（任务目标、阶段、文件引用、验证记录、步骤占位）。
- 用户主动点击“AI 整理草稿”后，才使用当前选择的模型整理步骤和描述；操作前明确提示可能产生模型费用及会发送哪些选定内容。
- 仅允许发送用户选中的、经脱敏检查的任务片段和证据摘要。
- 模型无法确认的内容标记待确认，不得补造代码事实、客户规则或测试结论。

### P0-04 人工审核与发布

候选状态：`draft`、`needs_review`、`approved`、`published`、`rejected`、`superseded`。

用户可：编辑、预览、运行格式校验、查看来源证据、拒绝、批准发布、选择目标范围、选择目标版本号。

发布门槛：

- Frontmatter 符合现有 Skill 规范。
- 资源路径与文件类型通过安全检查。
- 敏感信息扫描无阻断项。
- 使用范围明确。
- 来源证据完整。
- 用户明确批准。

### P0-05 发布到现有 Skill Catalog

- 学习生成的 Skill 通过现有 Plugin Manager 管理，不建立第二套平行 Skill Catalog。
- 使用精工 dataRoot 下受管的 Internal/Learned Plugin Package。
- Plugin/Skill 来源标记为 `learned`，保留发布人、发布时间、来源任务和版本链。
- 版本不可变；修改生成新版本，旧版本保留。
- 发布后默认 disabled 或仅在用户明确指定范围内启用；不得默认全局向所有项目开放。
- 通过现有 Skill Loader 在 0.8.2 路径中使用。

### P0-06 Skill 使用反馈

记录：推荐、选中、加载、未使用、完成、失败、用户拒绝建议、实际验证状态和用户评分（可选）。

把一次 Skill 使用标记为：

- `loaded`：Runtime 确认加载内容。
- `used`：有可观察证据表明模型/Agent 请求或执行了该 Skill 的步骤/资源；没有证据时不得标记 used。
- `task_completed`：任务完成，不代表成功。
- `verified_passed`：当前代码或交付物经过真实验证并通过。
- `accepted`：用户人工验收通过。

### P0-07 Skill 管理和版本

- 候选列表、已发布 Skill、版本历史、使用统计和状态统一展示。
- 支持停用、弃用、恢复旧版本。
- 每次版本更新需要重新做敏感扫描和用户审核。
- 既有 Session Snapshot 继续绑定旧版本；不允许热替换旧会话中的内容。

## 7. 数据边界和隐私

严禁自动沉淀：

- API Key、Bearer Token、密码、Cookie、私钥、连接串。
- 客户人员个人信息和非必要联系方式。
- 未授权的客户数据库样本、生产订单、工单、库存、人员工时和业务报表原始数据。
- 整个客户代码仓库、商业秘密文件和大段源代码。

可以沉淀：脱敏后的流程步骤、通用代码模式、错误类型、验证清单、通用字段映射规则（必须移除客户特定内容）、项目公开的技术约束和用户已批准的实践。

## 8. 验收标准

1. 没有真实证据的代码任务不能标记为已验证成功。
2. 任务失败不会自动产生可启用 Skill。
3. 任务完成后不自动发起模型请求。
4. 用户点击 AI 整理前显示发送内容范围及费用提示。
5. Candidate 来源可追溯至任务、契约和验证证据。
6. 凭据扫描命中时拒绝发布，日志和 UI 不显示原值。
7. 用户审核通过后才创建 Internal/Learned Plugin Package。
8. 发布生成新的版本和 Hash，不覆盖历史版本。
9. 用户可以拒绝、停用、弃用和回滚。
10. 统计正确区分 loaded、used、task_completed、verified_passed、accepted。
11. Skill 使用结果在跨 Runtime 场景中保留各自 runtimeKind。
12. 与现有插件导入、Memory、Task Engineering、Verification、备份和恢复功能回归通过。

## 9. 发布策略

Feature Flags：`learning.candidate_discovery`、`learning.ai_draft_generation`、`learning.publish_internal_skill`、`learning.skill_effectiveness`。

首期默认只启用候选发现和手动草稿；AI 整理需要用户点击；发布必须审核。候选数据和已发布 Skill 分离存储，功能回滚不删除 Skill 文件。

## 10. Codex 实施要求

- 先验证 0.8.1 Memory 与 0.8.2 Skill Loader API 已在当前分支存在。
- 复用 AgentTask、Task Contract、TaskEvidenceRecord、Verification Service 和 Plugin Manager。
- 不新建与 PluginSkillRecord 重叠的第二套已发布 Skill 模型。
- 不把模型自行总结当作真实验证证据。
- 不在本版本实现多 Agent 并行调度或 Context Engine 大规模重构。
