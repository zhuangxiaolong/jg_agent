版本与项目目录说明

本手册依据当前工作区 0.9.2 的源码和界面整理。安装包是否为 0.9.2，请在应用的【设置 → 更新】查看当前版本。本版本增加产品操作手册知识库与四份内置资料。项目会话直接使用所选 Git 项目目录和当前分支，Agent 的文件与命令操作按所选 Runtime 和当前 Windows 用户权限执行。开始任务前请检查已有修改，并确认本次允许变更的范围。

01快速开始

首次使用时，先准备一个本地 Git 项目和可用的模型中转站，然后新建项目会话。

  1. 添加项目在左侧【本地项目】旁点击加号，选择 Git 仓库根目录。先确认仓库当前分支和未提交修改。
  2. 配置模型连接打开左下角【全局设置 → 模型中转站】，填写 HTTPS 地址、模型列表和 API Key 并保存。
  3. 检查运行时在【全局设置 → 运行时】检查需要使用的 Runtime 状态。未就绪时按界面提示处理后再创建会话。
  4. 创建项目会话在项目下新建会话，或从 Jira 任务创建会话。会话设置中选择中转站、模型、系统类型、推理强度和 Runtime。
  5. 描述目标并发送写明要解决的问题、涉及范围、不可修改项、验收标准和希望执行的验证命令，按 Enter 发送。
  6. 检查结果查看运行输出、工具活动和右侧代码变更，运行适用的真实验证，再决定是否提交。
输入框快捷键为 Enter 发送、Shift + Enter 换行，Ctrl + V 粘贴文件。

02首次配置

模型中转站
新增中转站，填写 HTTPS 地址和独立 API Key，获取或录入该服务支持的模型。API Key 由本机保护存储。
运行时
查看 Jinggong Runtime、Codex Runtime 和 Claude Agent SDK Runtime 状态。Runtime 按会话选择，未就绪时不会静默切换到其他运行时。
Jira 连接
填写 Jira 地址、账号、密码、默认项目和日报日期字段。保存后可测试连接，并在 Jira 面板读取任务。
数据字典
按 MES5、MES6、WMS、前端或通用维护字典。可导入 TXT、MD、JSON、CSV、SQL、XLSX、DOCX 等资料。
开发要求与规范
按系统导入或录入团队规范并启用。规范作为当前项目任务上下文供 Agent 参考。
会话与数据
查看会话、项目和本机数据目录，可导出或导入会话数据。
企业微信通知
配置群机器人目标、适用 Runtime 和通知事件，可发送测试消息并查看通知记录。
更新
查看已安装版本、设置更新来源，并选择自动或手动更新。
不要把密码、API Key、Webhook 或业务 Token 写入任务描述、项目开发规范、普通记忆或提交说明。

03项目与会话

项目会话

添加已有 Git 仓库后，在项目下创建会话。项目会话直接在该项目目录和当前分支上工作，代码变更会出现在仓库的真实 Git 差异中。开始前检查已有修改，避免把历史修改误认为本次 Agent 产生的内容。

独立会话

从欢迎页或左上角【新建会话】创建不关联项目的会话，适合一般问答和不需要修改项目代码的分析任务。

系统类型

新建项目会话时，应用根据仓库根目录指纹识别 MES5、MES6、WMS 或前端。可在会话设置中手动调整系统类型。已启用的通用资料和当前系统资料会用于上下文。

任务描述建议

说清目标和范围

说明预期行为、业务场景、涉及模块和明确不应修改的内容。

给出验收条件

列出可观察结果、兼容要求、异常场景，以及要运行的构建或测试命令。

会话运行期间可以补充指令。需要终止当前任务时使用【停止】，并在完成后重新查看变更和运行状态。

04模型与 Runtime

输入框下方的【会话设置】控制当前会话配置，切换 Runtime、模型或系统前先停止运行中的任务。

设置项使用说明
中转站与模型选择已启用且凭据可用的中转站和模型。更换服务地址时按界面提示更新 API Key。
系统选择通用、MES5、MES6、WMS 或前端，用于匹配项目说明、规范和字典。
推理强度选择模型默认、无、最低、低、中、高或超高。具体效果仍由服务端模型支持情况决定。
Runtime选择 Jinggong、Codex 或 Claude Runtime。设置页展示组件可用性和版本信息。
普通 Runtime 会按任务访问项目文件并执行本机命令。执行能力遵循当前 Windows 用户权限，发送前请确认项目路径、任务范围和外部系统操作要求。

05工作区界面

左侧项目与会话

添加项目、创建会话、切换当前会话。项目和会话的管理菜单提供重命名或删除等操作。

会话输入区

提交任务、补充说明和附件。应用显示当前会话的中转站、模型、Runtime 和推理强度。

右侧任务面板

查看 Jira、子 Agent、Git 差异、项目文件、执行监控和上下文。部分面板需要先选择项目或会话。

底部运行活动

在【运行输出】和【工具活动】之间切换，查看状态、错误、模型输出和工具事件。

拖动侧栏分隔线可调整面板宽度，拖动底部分隔线可调整运行活动区域高度。右侧【上下文】可核对项目目录、系统类型、Runtime、中转站和已启用资料。

06产品操作手册知识库

在【全局设置 → 产品手册】管理本机产品资料。会话会按项目、问题和手动选择的产品范围检索相关片段，并把真实来源定位交给当前 Runtime。

安装后已有的手册

首次启动时，应用会校验安装包中的手册文件，将原件复制到当前 Windows 用户的数据目录，并在后台建立本地索引。列表中会显示“安装包内置手册”。

iMES5.9 操作手册 V1.1

分类 MES5，产品版本 iMES 5.9。

SRM 系统操作手册

分类 SRM。

JMOM 仓库和品质模块操作手册

分类 JMOM。

PDA 移动仓库和品质操作手册

分类 PDA。

MES6 分类已经可用。当前没有 MES6 内置资料时，可以在导入手册时选择 MES6 分类。

导入和解析

  1. 填写默认信息在“导入手册”填写产品分类、产品版本、手册版本、生效日期和适用范围或备注。
  2. 选择文件点击【选择手册文件】，可一次选择多份资料。支持 PDF、DOCX、XLSX、PPTX、MD、TXT、HTML。产品分类可选 MES5、MES6、WMS、SRM、JMOM、PDA 或通用。
  3. 逐份核对在待导入列表中分别确认分类和版本，也可以把默认信息应用到全部文件。
  4. 提交解析点击【导入并解析】。文件复制到本机知识库后进入后台队列，页面会刷新处理状态和进度。

单文件最大 100 MiB，每批最多 20 个文件。相同产品分类下重复导入同一 SHA-256 文件时会提示已有记录，不会创建重复索引。

解析边界 当前版本没有 OCR。扫描版 PDF 没有可搜索文字时不能建立完整索引。DOCX 内嵌图片只保留图片数量和提示，图片中的文字不会参与检索。

选择会话的产品知识范围

在“手册范围”选择会话，再设置产品知识范围。

  • 自动匹配 使用项目识别结果和问题中明确提到的 MES5、MES6、WMS、SRM、JMOM 或 PDA 分类，并包含通用手册。
  • 指定产品 选择 MES5、MES6、WMS、SRM、JMOM 或 PDA 时，检索对应产品与通用手册。
  • 关闭手册检索 当前会话不注入产品操作手册上下文。
未知项目且问题没有明确产品范围时，不会自动混合不同产品的手册。请在此手动指定范围，或在问题中写明产品类别。

手册库和详情

“手册库”支持按产品、状态和名称或版本筛选。选择手册后，可以查看原始文件、文件大小、SHA-256、导入时间、解析摘要、片段数量和来源定位。

状态含义可执行操作
等待处理已登记，等待后台任务。等待任务开始。
处理中正在解析或建立索引。查看阶段和进度，可取消排队任务。
可用正文解析和索引已完成。参与正常检索。
部分可用部分内容无法解析，但已有可检索内容。查看提示，必要时替换文件或重新解析。
解析失败没有可用正文，或文件无法处理。修复文件后重新解析或替换。
已停用保留在本地但不参与自动检索。需要时重新启用。

编辑、替换和删除

  1. 在详情中编辑名称、产品分类、产品版本、手册版本、生效日期和适用范围，点击【保存信息】。
  2. 点击【重新解析】使用当前文件重新建立解析结果。解析失败时，原有可用索引会保留。
  3. 点击【重新上传并替换】时只选择一个文件。替换成功后，新原件和新索引一起生效。
  4. 普通用户导入的手册可二次确认后删除。内置手册不能直接删除，可以停用或替换。
替换、解析失败、取消或应用中断时，旧手册及旧索引会保留，避免当前问答突然失去可用资料。

测试检索和来源引用

“测试检索”可指定产品范围并输入操作问题，结果会展示命中的手册、手册版本、分类、来源定位、匹配分数和正文片段。解析片段预览会显示章节、页码、工作表或幻灯片定位。

回答使用手册资料时，来源标识会随检索结果进入会话上下文，例如 来源：《iMES5.9 操作手册 V1.1》— 第 12 页 — 生产管理。手册未说明的内容需要明确标注，不能补造页码、菜单或操作步骤。不同版本来源出现冲突时，需要分别引用并提示版本差异。

本地存储和隐私

原件默认存放在 %LOCALAPPDATA%\JinggongAgent\knowledge\manuals\originals，索引存入本地 SQLite。用户替换后的文件不会因为更新安装包而恢复成初始版本。

手册全文不会在每轮发送。只有当前问题命中的片段会作为资料上下文发送给已配置的模型服务。可以在性能设置中关闭“产品操作手册”上下文来源。

07Jira 任务

  1. 在【全局设置 → Jira 连接】填写地址、账号和密码，保存后测试连接。
  2. 打开右侧【Jira】，选择项目范围和查询范围。可按日报日期抓取，也可选择最近任务或点击【抓取所有任务】。
  3. 选择负责人范围并抓取任务。查询条件有变更时重新抓取后再打开详情或创建会话。
  4. 打开任务查看详情，选择关联的本地 Git 项目，然后点击【从此任务创建会话】。
  5. 应用会重新读取 Jira 任务并保存任务快照。检查会话内容后，由用户发送任务。

Jira 面板可恢复本地抓取记录、刷新查询和查看任务工作流。日报日期使用 Jira 账户时区解释。任务是否可见取决于当前 Jira 账号权限。

08子 Agent 与 0.9 协作能力

0.9.2 在现有子任务面板和 AgentTaskRunner 上加入了主 Agent 动态委派接口。面板可按编排轮次显示任务、状态、结果、证据、日志，并提供停止单个任务或取消本轮的操作。

使用状态取决于认证门禁。 只有当前 Runtime、Provider、Model 和受控分析测试套件匹配且通过实测认证时，动态委派才会启用。项目关联会话可使用 Codex 或 Jinggong Runtime。Claude Agent SDK 与 Grok Build ACP 当前不支持该受控子 Agent 流程。

若面板显示【受控子 Agent 未认证】，平台不会创建或启动受控子 Agent，主会话仍可继续处理任务。当前代码默认将缺少认证的能力保持关闭。面板中已有历史任务时，仍可查看其状态和结果。

已认证时，子 Agent 由主 Agent 根据任务需要决定是否委派。用户可在右侧【子 Agent】查看运行情况、展开任务目标与工程契约、核对结构化结果和证据，再按需要停止任务。本轮等待超时只返回状态，不会自动取消任务。

子 Agent 当前只做受控只读分析。代码实现、真实构建与测试由主会话完成。Agent 的文字结论不等于验证通过或人工验收。

09代码检查与真实验证

查看本次代码变更

打开右侧【Git】查看文件差异和逐文件 Diff。必要时使用文件右键菜单打开系统编辑器或资源管理器。选择【撤销此文件更改】会丢弃该文件的修改，操作前先核对文件内容。

运行构建和测试

  1. 打开右侧【执行监控】，展开【分级测试建议与真实证据】。
  2. 选择【按变更推荐测试】或【要求全量测试计划】，查看命令和适用范围。
  3. 建议状态为【未执行】。核对命令后点击对应的【确认并运行】。
  4. 查看真实运行结果和 Run ID。需要关联子任务工程契约时，在子 Agent 任务详情中填写 Run ID 并复核证据。

执行监控还会显示本轮耗时、Runtime、Provider、模型、工具事件和阶段时间线。不可采集的数据会标明状态。单次耗时不能代表稳定性能提升。

提交与同步 Git

  1. 确认当前项目、当前分支和 Diff 文件范围，完成必要构建、测试和业务核对。
  2. 在右侧【Git】填写中文提交说明。可点击【根据 Diff 生成提交说明】后自行检查。
  3. 点击【提交代码】或【提交并推送】。也可先提交，再使用【推送当前分支】。
  4. 需要拉取时使用【拉取当前分支】。仅接受远程同名分支的快进更新，分支分歧需人工处理。
项目会话使用当前项目分支。提交、推送和拉取均作用于所选项目仓库，请在操作前检查 Git 状态、远程地址和分支名称。

10记忆、插件与本地数据

  • 记忆在【全局设置 → 记忆】搜索、筛选、查看、新增、编辑、停用或删除本地记忆。长期记忆适合保存稳定偏好、工作方式和可复用经验。不要保存密钥或一次性任务全文。
  • 数据字典与开发要求按产品系统维护和启停资料。请确认资料适用系统和有效版本，避免把过期业务规则提供给会话。
  • 插件管理可查看和管理已接入的插件及 Skill。具体信任状态、授权和可用功能以插件管理界面为准。
  • 会话与数据可查看本地会话和项目数据并执行会话备份。重要代码请使用 Git 或组织认可的文件备份方式。
  • 外观与个人资料可调整风格、主题、完成提示音、显示名称、职业偏向和头像。

普通会话、项目代码和验证记录保存在本机应用数据范围内。执行监控中可复制脱敏诊断，排查问题时优先提供 Runtime、模型、错误信息和 Run ID。

11常见问题

无法发送任务
检查当前会话是否已选择中转站、模型和可用 Runtime，并确认中转站凭据有效。
Runtime 显示不可用
打开【全局设置 → 运行时】，检查该组件并查看具体错误信息。应用不会静默回退到其他 Runtime。
Jira 没有返回任务
核对账号权限、项目范围、日报日期和负责人过滤。切换查询条件后重新抓取。
子 Agent 面板显示未认证
当前 Runtime、Provider、Model 组合缺少对应的受控分析认证。主会话仍可正常处理任务。
Git 提交按钮不可用
确认当前会话关联了项目、有未提交变更、提交说明不为空，且当前没有运行中的任务。
验证结果仍为未执行
在执行监控的真实证据区域查看验证计划，并对适用命令点击【确认并运行】。Agent 回复中的“已通过”文字不产生平台验证记录。
项目已有修改
项目会话直接使用所选目录。先通过 Diff 和 Git 状态区分已有工作与本次改动，再决定是否暂存或提交。

12交付前检查

  • 项目、分支、系统类型和 Runtime 与任务相符。
  • 任务目标、改动边界和验收标准已核对。
  • 逐文件检查 Diff，确认没有超出任务范围的变更。
  • 必要的构建、类型检查和测试已实际运行，并查看真实结果。
  • 人工核对业务行为、接口影响、数据库变化和回归风险。
  • 提交说明、远程仓库、分支和待推送内容已确认。

平台运行记录、Agent 总结、真实验证结果和业务验收分别核对。未执行的检查保持未执行状态。
