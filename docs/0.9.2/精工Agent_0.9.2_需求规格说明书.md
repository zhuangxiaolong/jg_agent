# 精工 Agent 0.9.2 需求规格说明书

> 版本：0.9.2  
> 需求主题：MES5 / MES6 / WMS 操作手册知识库与项目级智能检索  
> 目标分支：`develop/desktop-poc`  
> 应用形态：Windows 桌面客户端  
> 文档状态：供 Codex 直接实施

### 补充需求：安装包内置手册与产品分类

- Windows 安装包内置四份随包操作手册。iMES 5.9 V1.1 归入 MES5，SRM、JMOM、PDA 分别作为独立产品分类；这三类不得归入 COMMON。
- 首次启动将内置手册复制到当前 Windows 用户的数据目录并自动建立索引。内置原件随安装包发布，清单使用 SHA-256 校验。
- 用户可以停用内置手册，也可以重新选择文件替换。替换先解析新文件，成功后再原子切换原文件元数据与索引；失败时继续使用旧版本。
- 内置手册不能直接删除。MES6 分类、筛选和会话知识范围必须保留，用户有 MES6 手册后可以正常上传。
- 批量导入允许逐份设置产品分类，MES5、MES6、WMS、SRM、JMOM、PDA 和 COMMON 互相独立。
- 当前文档解析器不执行 OCR。DOCX 中存在嵌入图片时，必须将状态标为部分可用并显示图片数量，避免把截图中的文字误报为已检索内容。

## 1. 版本目标

### 1.1 背景

精工 Agent 已经具备项目识别、会话附件、项目规范与数据字典、Memory Engine、上下文检索和多 Runtime 执行能力。但“项目规范/数据字典”和“产品操作手册”不是同一类知识：

- 项目规范用于约束智能体如何开发、修改和验证代码。
- 数据字典用于理解业务字段、表结构、编码及数据关系。
- 操作手册用于理解产品功能、菜单位置、操作步骤、业务前置条件、状态变化、异常处理和用户实际使用方式。
- 会话附件只服务于某个会话或当前任务，不应自动成为全局产品知识。
- Memory Engine 保存可复用偏好、约束、决策和经验，不应该承载整本操作手册。

因此，0.9.2 建设独立的“产品操作手册知识库”，将 MES5、MES6、WMS 的操作手册导入精工 Agent，由智能体在项目问答、实施支持、问题分析、操作指导和开发任务中按项目上下文检索使用。

### 1.2 核心目标

用户导入 MES5、MES6、WMS 的操作手册后，精工 Agent 能够：

1. 按产品类别管理手册：MES5、MES6、WMS，以及适用于多个产品的通用手册。
2. 解析文件内容并建立可检索知识索引。
3. 自动识别当前项目所属产品，优先检索对应产品手册。
4. 在回答中使用检索到的手册内容，并提供文件名、版本、章节、页码等来源信息。
5. 当手册没有明确答案时，明确说明资料未覆盖，不得编造菜单、字段、按钮或操作步骤。
6. 支持手册新增、更新、停用、删除、重新解析和检索测试。
7. 让 Codex、Claude Agent SDK、精工 Runtime、Grok Build 等 Runtime 通过统一知识检索接口使用相同手册知识，不在每个 Runtime 单独实现一套知识库。

### 1.3 一句话定义

**导入一次，按项目自动匹配；不同 Runtime 都能查；答案能追溯到具体手册。**

### 1.4 非目标

0.9.2 不做以下内容：

- 不重新开发 Agent Runtime，不替换 Codex / Claude Agent SDK / 精工 Runtime / Grok Build。
- 不建设云端知识库，不要求用户部署服务器。
- 不把操作手册全文拼接进每轮 Prompt。
- 不把手册原文自动写入 Memory Engine。
- 不默认把所有手册内容发送给第三方模型做预处理或摘要。
- 不自动执行手册中的 SQL、脚本、命令、宏或网页操作。
- 不把普通会话附件自动升级为全局知识资产。
- 不在 0.9.2 强制建设复杂知识图谱、Agent 自动训练或模型微调。
- 不要求用户改变现有项目目录和代码仓库结构。

## 2. 用户与典型场景

### 2.1 主要用户

- MES/WMS 项目经理、实施顾问：根据手册询问菜单功能、业务流程、参数配置、异常处理方法。
- MES/WMS 开发人员：通过手册理解功能行为、业务规则和操作入口，辅助定位需求。
- 交付负责人：快速核对不同产品版本的功能差异，减少重复询问产品熟悉人员。
- 精工 Agent 用户：在普通对话或 Jira 任务会话中直接使用产品知识。

### 2.2 核心场景

| 场景 | 用户提问示例 | 预期行为 |
|---|---|---|
| 功能说明 | MES6 的工单报工在哪里操作？ | 优先检索 MES6 操作手册，返回菜单路径、操作步骤和出处 |
| 实施指导 | WMS 做采购收货需要哪些前置配置？ | 整理手册中的前置条件、操作步骤和注意事项 |
| 异常排查 | 扫描后提示库存状态不允许出库，怎么排查？ | 检索对应异常/状态说明；区分手册明确结论与建议排查项 |
| 版本区分 | MES5 和 MES6 的报工操作是否一样？ | 分别检索两套产品知识，对比并引用各自来源 |
| Jira 任务辅助 | 按这个 Jira 缺陷分析 MES6 相关功能 | 识别项目产品类型，检索相关操作手册辅助理解任务 |
| 手册缺失 | 手册里有没有委外退料流程？ | 明确表示未检索到可靠内容，不臆造流程 |
| 手册更新 | MES6 新版手册替换旧版 | 新版本生效，旧版本可停用或保留历史；检索不混用失效版本 |

## 3. 产品与知识分类

### 3.1 产品分类

手册必须归属于以下分类之一：

- `MES5`：MES5 产品手册。
- `MES6`：MES6 产品手册。
- `WMS`：WMS 产品手册。
- `COMMON`：确实同时适用于多个产品的通用操作说明。

不允许把未确认产品范围的文件默认归到某一个产品。用户导入时必须选择产品类别；可以由文件名给出建议，但最终归类由用户确认。

### 3.2 知识类型

0.9.2 至少支持 `operation_manual`（操作手册）。数据字典、开发规范、项目资料继续沿用现有模块或类型，不要把它们强行迁移进新模块。

### 3.3 手册元数据

每本手册至少保存：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 名称 | 是 | 用户可读名称，默认取文件名 |
| 产品分类 | 是 | MES5 / MES6 / WMS / COMMON |
| 手册类型 | 是 | 当前固定为操作手册 |
| 产品版本 | 否 | 例如 MES6 具体版本；未知时留空 |
| 手册版本 | 否 | 文档自身版本号，如 V1.2 |
| 生效日期 | 否 | 用于版本优先级判断 |
| 适用范围/备注 | 否 | 用户补充适用模块、工厂或特殊范围 |
| 状态 | 是 | 处理中、可用、解析失败、停用 |
| 原始文件名 | 是 | 保留来源文件名 |
| 文件大小 | 是 | 用于展示和大小限制 |
| 文件哈希 | 是 | 用于识别重复导入 |
| 导入时间 | 是 | 本地时间 |
| 更新时间 | 是 | 最近一次变更时间 |
| 解析器版本 | 是 | 便于后续重新解析 |
| 页数/工作表数 | 否 | 按文件类型保存 |

### 3.4 生效与优先级规则

同一产品可能存在多份手册。检索时按以下规则确定优先级：

1. 状态为“可用”的手册才参与自动检索。
2. 对应产品分类优先于 `COMMON`。
3. 用户明确指定的手册优先于自动匹配结果。
4. 明确标注适用当前产品版本的手册优先于未标版本手册。
5. 有效期/生效日期更新的优先于更旧的手册。
6. 如果两份可用手册存在无法判断的新旧关系，不可静默拼接成一个确定结论；回答需要提示资料版本可能冲突，引用来源并让用户确认。
7. 停用手册仅可在知识库管理界面查看，不参与正常问答；用户显式要求对比历史版本时才允许检索。

## 4. 功能需求

### FR-01：产品操作手册知识库入口

在现有桌面端信息架构中增加“操作手册”或“产品知识库”入口。优先复用现有设置、项目规范/数据字典管理、资料库或文件管理的导航布局，不要大幅重构主界面。

页面至少包含：

- 产品分类切换：全部、MES5、MES6、WMS、通用。
- 手册列表。
- 导入手册入口。
- 搜索/筛选：名称、产品分类、版本、状态。
- 手册详情和解析状态。
- 重新解析、停用/启用、删除、修改元数据等操作。

### FR-02：导入操作手册

支持通过文件选择器导入一份或多份手册。

导入步骤：

1. 选择文件（支持多选）。
2. 选择产品分类（MES5 / MES6 / WMS / 通用）。
3. 填写可选信息：产品版本、手册版本、生效日期、适用范围/备注。
4. 确认导入。
5. 后台解析、切分、索引。
6. 显示处理进度与最终结果。

文件格式的最低目标：

- PDF：必须支持可搜索文本 PDF。
- DOCX：必须支持。
- XLSX：必须支持，保留工作表名称、表格行列关系。
- PPTX：必须支持，保留页/幻灯片编号和标题。
- Markdown、TXT、HTML：必须支持。
- DOC、XLS、PPT：若仓库已有稳定解析依赖则支持；否则提示用户另存为 DOCX/XLSX/PPTX/PDF，不允许静默丢弃。

扫描版 PDF：

- 如果现有文档解析能力已经支持 OCR，则复用。
- 如果没有 OCR，0.9.2 不强制引入大体积 OCR 运行时；必须检测文本抽取结果是否为空或明显过少，并告知用户该文件可能是扫描件、当前无法完整检索。
- 不能把解析为空的扫描 PDF 标记成“已成功建立知识库”。

导入限制：

- 单文件默认上限建议 100 MB，具体值应结合现有应用文件限制统一配置。
- 单次批量导入默认最多 20 个文件，避免一次性占满内存；如现有设置有统一限制，优先复用。
- 根据文件扩展名和实际内容校验文件类型，拒绝可执行文件、脚本、宏执行和未知二进制文件。
- 压缩包、加密/受密码保护文件、损坏文件需要给出清晰错误提示。
- 同一分类下相同 SHA-256 文件重复导入时提示“文件已存在”，允许用户取消或查看已有记录；不产生重复索引。

### FR-03：解析与处理状态

手册处理必须异步执行，不阻塞 Electron 主进程和主界面。

状态至少包括：

- `pending`：等待处理。
- `processing`：解析或建立索引中。
- `ready`：处理成功，可参与检索。
- `partial`：部分内容无法解析，但已有可用内容；界面明确告知。
- `failed`：处理失败。
- `disabled`：停用，不参与自动检索。

列表/详情页应展示：处理状态、进度阶段、文件大小、导入时间、解析页数/工作表数、提取文本量、错误摘要。

用户关闭窗口或应用异常退出后，启动时要能恢复或清理未完成任务，不能留下永久“处理中”的假状态。

### FR-04：内容解析与结构保留

解析结果至少保留：

- 原始文件标识。
- 产品分类和手册版本。
- 页码/幻灯片编号/工作表名称及行列范围等定位信息。
- 标题层级或章节路径（如文档中存在）。
- 段落顺序。
- 表格结构及表头与对应单元格关系。
- 列表、步骤序号。
- 内容类型（段落、表格、标题、列表等）。

对操作手册来说，表格不能简单压平成无结构字符串；例如“操作名称—操作说明—前置条件—结果”应尽量保留字段对应关系。

原始文件必须保留，解析文本和索引可以重新生成。删除手册时需同步处理其原始文件、解析产物和索引记录。

### FR-05：按章节切分与索引

- 优先以标题、章节、页面边界进行结构化切分。
- 不得把相邻章节完全混成一个知识块。
- 对较长内容再按长度切分，并保留必要上下文重叠。
- 每个知识块必须可以回溯到原始手册、页码/工作表/幻灯片、章节路径。
- 索引时保留手册版本和产品分类元数据。
- 相同内容块不应因重复导入产生重复结果。

建议初始切分参数：每块约 800–1,200 tokens，重叠约 100–150 tokens。此数值只是初始配置，必须结合现有检索实现和模型上下文预算调整，不得写死在多处代码中。

### FR-06：自动识别项目并匹配知识

复用当前项目创建时对 MES5、MES6、WMS 的仓库指纹识别能力。

匹配逻辑：

1. 当前会话关联项目时，读取项目已有的产品类型识别结果。
2. 如果项目类型明确为 MES5，则优先检索 MES5，再考虑 COMMON。
3. 如果项目类型明确为 MES6，则优先检索 MES6，再考虑 COMMON。
4. 如果项目类型明确为 WMS，则优先检索 WMS，再考虑 COMMON。
5. 如果项目类型未知或混合项目，不要猜测；允许用户在会话中指定产品知识范围。
6. 用户在当前会话显式指定某产品分类时，以显式指定为准。
7. 独立会话没有项目类型时，可以根据问题和用户明确指令建议分类；没有足够把握时询问或执行多分类检索，并标注各自来源。

项目产品类型不得仅因某轮 Prompt 里出现“MES6”字样就永久改变。

### FR-07：智能体自动检索手册

用户正常提问时，不要求用户先手动打开知识库或输入特殊命令。

当问题涉及以下内容时，系统自动触发产品手册检索：

- 菜单、按钮、页面、功能入口。
- 操作步骤、业务流程、单据流转。
- 参数配置、权限配置、基础资料配置。
- 异常提示、业务状态、操作限制。
- 产品功能说明、版本差异、功能是否支持。
- 项目/Jira 任务中需要理解产品既有行为的内容。

对于纯代码格式化、普通闲聊、与 MES/WMS 产品无关的任务，不应无条件检索整套手册。

检索流程：

1. 根据当前项目/会话确定产品知识范围。
2. 从用户最新问题提取关键词和语义意图。
3. 调用统一知识服务检索相关知识块。
4. 对候选结果做产品分类、版本、状态过滤和排序。
5. 去重并限制注入上下文的数量和 token 预算。
6. 将检索结果、出处、版本信息作为有来源的上下文注入当前 Runtime。
7. 记录本轮使用了哪些知识来源，便于问题排查；不得记录敏感文件正文到普通日志。

检索结果应支持明确的“无结果”状态，不得在无结果时返回看似相关但实际不匹配的内容。

### FR-08：回答引用与可信度

只要回答使用了操作手册内容，就应在相关段落附近给出出处，格式建议：

`来源：《MES6 操作手册 V2.1》— 第 32 页 — 生产管理 / 工单报工`

若为 Excel：

`来源：《WMS 操作手册.xlsx》— 工作表“采购收货” — A1:F18`

若为 PPT：

`来源：《MES5 操作手册.pptx》— 第 16 张幻灯片 — 领料操作`

要求：

- 来源必须来自真实检索结果，不可由模型自行编造页码和文件名。
- 如果引用内容为跨页内容，允许多个来源。
- 如果手册未明确说明某个前置条件或规则，要说“手册未明确说明”。
- 对检索内容的合理推断应明确标注“结合手册内容推断，需现场确认”。
- 当不同版本手册出现冲突时，要提示版本冲突，不得把旧版本结论作为当前确定规则。

### FR-09：手册管理

用户可以：

- 修改名称和元数据。
- 设为可用/停用。
- 删除手册。
- 对失败或部分成功的文件重新解析。
- 用新版本导入替换旧版本的生效状态。
- 查看解析错误和来源信息。

删除采用二次确认。停用不删除原始文件。重新解析必须使用当前解析器版本生成新的解析产物；失败时保留旧的有效索引，避免因重建失败导致现有问答突然不可用。

### FR-10：知识检索测试

管理界面提供“测试检索”输入框：

- 可指定产品分类。
- 输入一个操作问题。
- 显示命中的知识片段、产品分类、手册版本、章节/页码、相关度/排序分数（如已有分数）。
- 可以查看原始文本片段。
- 可以判断是否命中错误产品、旧版本或停用手册。

该功能用于上线前验证手册质量和检索准确性。

### FR-11：会话内知识范围提示

在会话信息区域或上下文详情位置显示当前知识范围，例如：

`产品知识：MES6 + 通用（自动匹配）`

用户可在会话中切换：

- 自动匹配（默认）。
- MES5。
- MES6。
- WMS。
- 关闭操作手册检索。

如果现有 UI 不适合新增常驻控件，可放在会话详情/上下文设置中，但用户必须能看见当前检索范围并能覆盖自动识别结果。

### FR-12：多 Runtime 一致性

检索必须发生在共享的 Agent 上下文组装层或统一会话消息构建层，不可只接入 Codex Runtime。

所有 Runtime 使用同一套知识过滤、检索、引用和 token 预算策略。Runtime 适配层只负责接收已经组装好的知识上下文。

如果某个 Runtime 的上下文注入方式与其他 Runtime 不同，必须通过统一接口适配，不能复制检索业务逻辑。

## 5. 界面与交互要求

### 5.1 知识库列表建议

| 产品 | 手册名称 | 手册版本 | 文档版本 | 状态 | 导入时间 | 操作 |
|---|---|---|---|---|---|---|
| MES6 | MES6 操作手册 | MES6.2 | V2.1 | 可用 | 2026-11-21 | 查看 / 编辑 / 重新解析 / 停用 |
| MES5 | MES5 生产操作手册 | MES5 | V1.5 | 可用 | 2026-11-21 | 查看 / 编辑 / 重新解析 / 停用 |
| WMS | WMS 仓储操作手册 | WMS 3.x | V3.0 | 处理中 | 2026-11-21 | 查看进度 / 取消 |

以上仅为交互示例，不代表仓库已存在这些手册。

### 5.2 导入弹窗

字段建议：

- 文件：支持拖放和文件选择，多文件列表。
- 产品分类：MES5 / MES6 / WMS / 通用，必选。
- 手册名称：默认文件名，可编辑。
- 产品版本：可空。
- 手册版本：可空。
- 生效日期：可空。
- 适用范围/备注：可空。
- 按钮：取消、导入并解析。

支持每个文件单独指定产品分类和版本，避免批量导入不同产品时误分类。可提供“应用到全部文件”快捷操作。

### 5.3 详情页

展示：文件信息、产品分类、版本信息、状态、解析摘要、页码/章节结构、最近一次解析时间、失败原因、索引状态。

不要展示未经验证的“知识准确率 99%”之类宣传指标。

### 5.4 视觉与交互约束

- 复用当前应用设计系统、字体、颜色、按钮、弹窗和列表组件。
- 适配 Windows 桌面窗口和现有左右侧栏布局。
- 长文件名、长章节名需要省略显示并支持悬浮/详情查看。
- 解析任务可取消；如果底层解析不能安全中断，至少支持停止后续排队任务并说明当前文件仍在处理。
- 错误提示必须给出文件名和可操作的修复建议。

## 6. 验收标准

### AC-01 文件导入

- 能导入 PDF、DOCX、XLSX、PPTX、MD、TXT、HTML。
- 能批量导入并分别设置 MES5、MES6、WMS 分类。
- 重复文件不会创建两份相同知识索引。
- 非支持文件、损坏文件、加密文件有明确失败原因。

### AC-02 解析准确性

- PDF 的来源页码可回溯。
- DOCX 标题层级和段落顺序基本保留。
- XLSX 保留工作表名称、表头和表格关系。
- PPTX 保留幻灯片编号和文本顺序。
- 扫描 PDF 不得在文本抽取为空时被标记为完全成功。

### AC-03 项目匹配

- MES5 项目只优先使用 MES5 + COMMON。
- MES6 项目只优先使用 MES6 + COMMON。
- WMS 项目只优先使用 WMS + COMMON。
- 未知项目不擅自归类。
- 用户显式切换类别后，自动匹配不覆盖用户选择。

### AC-04 问答效果

导入测试手册后，对手册中明确存在的问题，回答应能：

- 检索到正确章节。
- 返回关键操作步骤。
- 引用正确文件、版本和页码/章节。
- 不混入其他产品的错误知识。

对手册中不存在的问题，应明确提示未检索到依据。

### AC-05 版本管理

- 停用手册不参与正常自动检索。
- 新旧版本冲突能被识别或至少提示多来源冲突。
- 重新解析失败不破坏此前可用索引。

### AC-06 Runtime

同一问题在 Codex、Claude Agent SDK、精工 Runtime、Grok Build 中均能获得一致的知识范围和出处信息（在各 Runtime 支持相同会话上下文的前提下）。

### AC-07 性能和稳定性

- 导入/解析期间 UI 不冻结。
- 知识检索不进行全量原始文件扫描。
- 对普通短问题，自动检索不应明显拖慢首字输出；检索耗时需有日志或性能指标。
- 解析中关闭应用后，重启不会永久卡在处理中。
- 删除手册后，其知识块不再被检索到。

### AC-08 回归

现有会话附件、数据字典、开发规范、Memory Engine、项目识别、Jira 工作流和 Runtime 选择行为不回归。

## 7. 实施优先级

### P0：0.9.2 必须完成

- 手册知识库列表和导入 UI。
- 产品分类和手册元数据。
- PDF、DOCX、XLSX、PPTX、MD、TXT、HTML 文档解析（优先复用现有解析器）。
- 页码/章节/工作表等来源定位。
- 本地持久化、去重、状态管理。
- 与现有上下文检索整合。
- 按项目自动匹配 MES5 / MES6 / WMS。
- 多 Runtime 共用检索结果。
- 回答中展示真实引用来源。
- 检索测试界面和自动化测试。

### P1：有余力则完成

- 更完整的扫描 PDF OCR（必须是本地或明确征得用户同意的服务）。
- 图片型操作步骤的图像理解和页图引用。
- 手册章节树、版本差异预览。
- 从手册自动识别目录和业务流程标签。

### 明确推迟

- 云端知识同步和多人协作知识库。
- 自动微调模型。
- 复杂知识图谱。
- Agent 自动生成并写回产品操作手册。

## 8. 给 Codex 的交付要求

开发前先阅读当前仓库的 `AGENTS.md`、`README.md`、`docs/`、现有文档解析、项目规范/数据字典、会话附件、Memory Engine、上下文检索及会话 Prompt 组装实现。

必须先输出简短的现状分析，列明：

1. 现有可复用的文档解析模块、检索模块、索引存储和 Worker。
2. 当前项目类型识别结果存放位置及读取接口。
3. 会话上下文注入各 Runtime 的公共位置。
4. 当前设置/知识资料页面入口。
5. 需要新增和需要修改的文件清单。

随后直接按本文档开发，不要因为上述分析要求用户再次确认。

实施原则：

- 优先复用现有能力，禁止重复建设第二套附件解析器、Memory Engine 或 Runtime 检索流程。
- 先实现端到端可用闭环，再扩展 OCR、图像理解等增强能力。
- 新增逻辑必须有单元测试和集成测试。
- 不得删除、重写或弱化与 0.9.2 无关的既有功能。
- 保持 Windows 桌面端本地运行方式。
- 完成后运行仓库规定的构建和测试命令，并报告真实结果。
- 如发现本文档与现有架构冲突，优先遵守仓库现行架构和 `AGENTS.md`，采用最小改动适配，并在交付报告中说明。
