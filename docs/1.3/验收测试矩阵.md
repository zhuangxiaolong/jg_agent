# 精工 Agent P0–P1 验收测试矩阵（0.9.8）

> 基线：README 0.9.7 / Codex Runtime 0.156.1 / `develop/desktop-poc`。  
> 本矩阵用于开发完成后的功能、集成、安全、兼容和回归验收。真实模型端到端测试与 Mock 测试必须分别记录。

## 1. 测试结果状态定义

| 状态 | 定义 |
|---|---|
| PASS | 已执行，结果符合预期，并有日志/断言/证据 |
| FAIL | 已执行，结果不符合预期 |
| BLOCKED | 因环境、权限、Runtime、外部服务等客观条件无法执行 |
| NOT RUN | 尚未执行；不代表通过 |
| N/A | 经说明确认不适用于当前构建 |

严禁将 Mock 测试标记为真实 Codex / 模型中转站端到端测试。严禁将 `BLOCKED`、`NOT RUN` 写成通过。

## 8. 真实集成验证清单

下列测试依赖固定 Codex Runtime、实际 App Server 协议以及当前中转站/模型配置。只有确实执行才可以标 PASS：

- 实际 V2 子 Agent 创建、并行、wait、消息、取消、收尾。
- 实际 Codex 原生识别精工管理 Profile 中的 Skills。
- 实际 Codex 触发/加载 Skill，并拿到可信证据。
- 使用中转站模型进行多 Agent 协作时的兼容性和稳定性。

如果外部环境不可用，自动化协议/配置测试仍应完成；上述项标记 `BLOCKED` 或 `NOT RUN`，明确限制，不能以 Mock 代替。

## 9. 上线前阻断条件

任何下列问题未解决，禁止宣称 P0–P1 全部完成：

1. native/governed/off 模式出现重复拆分或工具混用。
2. Codex App Server 没有真实启用 V2，却显示可用。
3. 项目/系统/版本/Hash 过滤失效或发生跨项目上下文注入。
4. 资料内容可以覆盖 system/developer 规则或扩大执行权限。
5. Codex Skill 仅推荐/同步，却在界面和审计中被标为已加载/已使用。
6. 会话迁移丢失历史记录或现有 Runtime 回归。
7. 任何凭据泄露或路径越界读写。
8. 未运行的测试被报告为通过。
