# 精工 Agent 0.7.1 基线盘点与差异表

## 盘点范围

盘点基于 0.7.0 当前工作树，保留现有未提交改动，未执行 reset、clean、stash 或覆盖用户目录。当前应用是 Electron + React + TypeScript 桌面客户端，持久化使用单一 SQLite `LocalStore`。

## 差异结论

| 模块 | 当前基线 | 0.7.1 缺口 | 本轮扩展点 |
|---|---|---|---|
| F01 项目中心 | 已有本地 Git 项目、Workspace、多仓库、资料文档、记忆 | 客户/系统/阶段、资源关系、事实/决策确认、上下文快照、归档恢复 | `packages/domain/src/iteration-07.ts`、`LocalStore` 迭代表、项目上下文 IPC |
| F02 数据映射 | Knowledge 可安全读取 XLSX/CSV 文本 | 行列结构预览、前导零/公式/隐藏行提示、规则 DSL、确定性转换和问题定位 | `packages/second-iteration/src/index.ts`，规则执行不运行任意代码 |
| F03 任务计划 | AgentTask 有状态、审计、验证和中断恢复 | 可确认 Plan/Step、阶段检查点、恢复前 Git/文件指纹核验 | 复用 AgentTask、Git connector、verification evidence，新增计划表 |
| F04 影响/审查 | Git diff、验证记录 | Diff 指纹绑定、影响对象、Finding 状态和 stale 判断 | 只读确定性分析，AI 结果必须标记建议级证据 |
| F05 交付闭环 | Jira 查询、附件、状态流转 | 离线交付包、manifest/hash、预览确认和写回回执 | 复用 Jira/Git/verification，默认排除凭据和客户源文件 |
| F06 效率 | Telemetry 已明确缺少可靠 token/费用 | 按模型聚合只能在有真实来源时展示 | 保持 unavailable，不用 0 伪装未知 |

## 迁移与兼容设计

- SQLite schema 由当前版本 11 增量升级；新增表只追加，不重建既有历史表，不级联删除任务、验证证据和交付记录。
- 现有 `Project`、`Session`、`AgentTask`、Jira、知识文档接口保持兼容；新增项目中心记录通过 `projectId` 与旧项目关联。
- 项目归档使用状态字段；旧的物理删除 API 保留兼容，但新界面默认只提供归档/恢复。
- F02 原文件只读，输出写入应用受管结果目录；规则采用受限 JSON DSL，不执行模型生成的 JavaScript、Python 或 SQL。
- 旧数据库迁移失败时保持原文件和迁移前副本，不以空库启动。

## 实施记录

- 领域模型收敛至 `iteration-07.ts` 与独立的 `iteration-governance.ts`，避免与既有第二迭代映射引擎重复导出。
- 迁移在 v11 后追加第二迭代表；旧项目/会话/任务与旧表数据保持原样。

## 当前限制

- 没有客户真实模板和脱敏样本时，不能宣称系统标准字段映射准确；内置建议只依据字段名和样本统计。
- Runtime 原生 resume、真实 token/费用和 Jira 写回仍依赖外部运行时/账号，连接不可用时保留本地流程并标记未执行。
