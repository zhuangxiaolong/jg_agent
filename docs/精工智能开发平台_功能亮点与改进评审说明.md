# 精工Agent：功能亮点与改进评审说明

整理日期：2026-11-09  
产品版本基线：v0.6.8  
用途：提供给 GPT 等评审工具，了解当前产品并提出有证据、可排序的改进建议。

## 一句话介绍

精工Agent是一款面向 Windows 的本地研发工作台，当前以 Codex CLI 运行时为基础，把 MES/WMS 项目识别、企业开发规范、Jira 任务、代码修改、构建测试、Git 和 Jira 测试反馈组织到一条日常开发流程中。

## 目标用户与典型流程

目标用户是需要在 MES5、MES6、WMS 等企业代码库中处理 Jira 需求的开发人员。典型流程如下：

1. 选择本地项目和 Jira 任务，按任务日期、项目和经办人范围查询。
2. 平台读取任务概要、描述和图片附件，检查需求是否具备开发条件；有无法确认的条件时明确警示。
3. 创建会话后识别项目技术代际，加载匹配的数据字典和开发要求。
4. Agent 先给出逐文件代码修改方案，开发人员确认方案后再执行修改。
5. 查看代码差异，按文件执行撤销、暂存、提交等 Git 操作；会话运行时可继续补充要求。
6. 对目标项目构建并运行测试，输出 Markdown 测试结果。
7. 需要时将测试说明和图片随 Jira 状态/经办人流转提交，并可将会话或记忆导出分享。

## 当前功能与亮点

### 1. MES/WMS 项目上下文

- 根据仓库指纹自动判断 MES5、MES6 或 WMS，而非依赖项目目录名称。
- MES5、MES6、WMS 数据字典随安装包提供；按识别结果检索并注入相应资料。
- 开发要求支持首次拉取和后续在线同步，任务执行时带入开发上下文，并对机器可判定的规则执行写入前校验。
- 业务差异化主要来自制造业代码和交付流程，而不是泛化的聊天体验。

### 2. Jira 到开发的衔接

- 查询 Jira 任务时支持日报日期、项目范围和“仅本人”等筛选。
- 查看任务内容和附件后可以创建关联会话；图片会尽力缓存并随首轮任务上下文传入，下载失败会提示，但不阻断建会话。
- 创建会话前检查需求完整性；不完整内容以醒目的警告标出待确认项。
- 会话结束后可选择 Jira 状态和经办人，经办人可搜索；可附带测试结果、补充文字和测试图片。
- Git 提交说明可附加关联 Jira 地址。

### 3. 先有方案，再落代码，并要求留下测试证据

- 开发会话先生成目标、逐文件改法、风险和验证步骤；方案外文件需要先更新方案。
- 代码变更面板展示真实 Git 差异，支持文件级查看、暂存/取消暂存、撤销，以及明确选择文件提交。
- 会话可选择基准分支；每个开发会话使用独立的 Agent 分支/工作区，便于隔离并查看变更。
- 代码修改完成后，工作流要求对目标项目构建、运行测试，并生成 Markdown 测试结果，区分通过、失败和未执行项。
- 这能让“改了什么、怎么验证”更容易复核；实际验证仍受目标项目工具链、测试数据和环境可用性影响。

### 4. 桌面会话体验和任务协作

- Windows 桌面应用，项目、会话、消息和设置本地持久化；左侧、右侧和输入区可拖动调整。
- 深色为默认外观；支持 Markdown、代码块一键复制和路径展示。
- 阅读历史消息时不会被新输出强制滚到底部；可在任务运行期间继续发送补充对话。
- 隐藏低价值工具事件，保留更简洁的任务进展；完成后显示会话蓝点，支持可配置提示音和 Windows 任务栏提醒。
- 会话记忆可自动形成；会话和记忆可导入/导出，用于团队经验分享。

### 5. 本地数据、浏览器和交付能力

- 使用本地 SQLite 保存项目、会话、记忆和资料；模型与 Jira 凭据通过 Windows 安全存储保护。
- 内置浏览器工具可打开网页、读取页面、操作表单、切换标签、截图及处理部分网页交互，适用于辅助处理报表平台等网页任务。
- v0.6.8 提供 HTTPS 在线更新，并校验 `latest.yml` 中的 SHA512；自动或手动检查/下载，重启后应用更新。
- 已发布的 v0.6.8 Release 资产包含安装包、blockmap 和 `latest.yml`。

## 评审时必须知道的现状和边界

- **运行时定位**：已发布打包基线使用固定版本的官方 Codex CLI 0.156.1。当前工作区正在开发 Runtime 选择和适配层，但独立的精工运行时仍未完成；不能把平台描述成自研大模型或已经完成独立 Runtime。
- **执行权限**：当前开发执行配置是 `danger-full-access`、`approval_policy=never`，不是经过 Windows 原生沙箱验证的受限执行环境。独立 Worktree 有助于隔离代码分支，但不等同于操作系统级安全隔离。
- **外部系统验收**：Jira 流转有应用级和模拟接口测试，但测试通过本身不能证明用户 Jira 已完成真实写入验收。浏览器能力也需按目标报表平台逐站点验证。
- **项目测试差异**：构建、测试报告工作流已具备，但具体 MES 项目能否真实构建和测试，取决于该项目依赖、数据库、设备和测试数据是否可用。
- **Git 连接**：本地 Git、SSH 和本地 Bare 仓库操作已支持；HTTPS 凭据托管仍有完善空间。
- **更新签名**：更新走 HTTPS 并校验 SHA512，但安装包没有企业 Authenticode 代码签名证书；旧版升级到 v0.6.8 需要先手动安装一次。
- **协作形态**：当前以单机、本地数据为主，可通过文件导入/导出分享；尚不等同于带权限、审计和实时同步的团队云平台。
- **产品对比**：还没有与同版本 Codex Desktop 做同任务、同模型、同代码库的量化对比，因此“比 Codex 更好用”是目标，不是当前已经被数据证明的结论。
