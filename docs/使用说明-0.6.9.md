# 精工智能开发平台 0.6.9 开发人员使用说明

适用对象：战区 MES5、MES6、WMS、前端项目开发人员。适用环境：Windows x64。发布日期：2026-11-13。

## 1. 安装与首次配置

运行 `JinggongAgent-Setup-0.6.9-x64.exe`，按向导安装并打开“精工智能开发平台”。从 0.6.8 或更早版本升级时，请先从系统托盘右键选择【退出精工智能开发平台】，再运行 0.6.9 安装程序覆盖升级；这是一次性手动过渡，无需先卸载。升级后应用内更新可用。应用保留本机项目、会话和配置；重要代码仍应按团队要求纳入 Git 管理。

开发电脑需安装 Git for Windows，准备一个已有提交记录的本地 Git 仓库，并能访问获授权的模型中转站和 Jira。安装包已包含 Agent 引擎，使用人员不需要另装 Node.js、Python 或 Docker。

首次打开左下角【全局设置】，依次完成以下配置：

1. 【模型中转站】：填写中转站名称、HTTPS 地址、模型名称和密钥，点击【保存配置】。模型名称必须与中转站实际支持的名称一致。
2. 【Jira 连接】：填写 Jira 地址、账号、密码和默认项目。日报日期字段 ID 默认 11116，按实际 Jira 配置调整；保存后可点击【测试已保存连接】。
3. 【开发要求与规范】：上传或录入团队开发规范，选择适用系统并启用。项目专用规范须明确项目边界；不要把另一项目的规则当作通用要求。
4. 【数据字典】：导入 MES5、MES6、WMS、前端或通用资料，选择正确的适用系统并启用。
5. 【外观】：默认深色，可切换风格和主题，设置并试听会话完成提示音。

密钥、密码保存在本机 Windows 保护的凭据文件中。不要把凭据粘贴到任务描述、记忆、开发规范或提交说明里。更换中转站地址、Jira 地址或账号时，按界面要求重新填写相应凭据。

0.6.9 新增 Grok Build Runtime。Grok 与其他 Runtime 一样，在会话输入区选择运行时，并在会话设置中选择中转站和模型。Grok 直接使用【模型中转站】中已有的 HTTPS 地址、API Key 和模型列表；【设置 > 运行时】仅用于查看和刷新组件状态，无需单独启用 Grok、绑定中转站或模型，也没有额外的 Grok 模型协议设置。密钥由 Windows 保护的本地凭据存储统一管理，不会回显；模型 ID 必须按中转站实际支持的名称填写。

在【模型中转站】中可点击【从中转站获取模型】辅助读取模型列表。文本回复成功只说明文本与会话建立可用，不等同于工具调用、连续多轮工具或 Agent 开发兼容；仍需完成工具闭环和实际工作区操作验证。Grok 会话在首次建立运行时绑定后固定当前中转站与模型；要换配置请新建会话。工具操作会逐项请求允许或拒绝，任务执行期间可取消；0.6.9 暂不接入 Grok 插件、子 Agent、多仓库和图片输入。

## 2. 添加项目、创建会话与调整界面

点击左侧【本地项目】右侧的加号，选择本地 Git 仓库根目录。仓库必须至少有一次提交。项目默认收缩，点击项目名称展开，再点击项目下的【新建会话】。会话会创建独立工作区和 agent/* 分支，代码变更发生在该会话工作区。

新会话根据仓库代码指纹识别 MES5、MES6、WMS 或前端，并加载对应及通用的已启用资料。前端项目读取根目录 `package.json` 和根级构建配置中的 React、Vue、Angular、Next、Nuxt、Vite、Svelte 等指纹；如果仓库同时包含明确的 MES/WMS 后端指纹，以后端系统为准。请核对识别结果；代码无法明确识别时，在会话设置中选择正确系统。系统切换后，也要确认所需字典和开发规范已经启用。

在项目或会话名称上点击鼠标右键，选择【修改名称】或【删除项目／删除会话】；列表不再常驻显示修改和删除按钮。会话别名留空可恢复默认标题。右键不会切换当前会话。

删除前会显示确认提示。取消则保留；确认删除会话后，会话与消息记录被移除，代码文件保留。删除项目须先删除其全部会话，源代码目录保留。删除前请核对名称，重要修改应先检查或提交。

会话设置位于输入框下方【Enter 发送 · Shift + Enter 换行】旁，点击中转站／模型入口向上展开，可选择中转站、模型、适用系统、执行模式和推理强度，点击【应用设置】生效。

会话列表会在名称下显示所选模型和推理强度。新建会话尚未发送内容时，切换到其他会话、打开设置或新建会话会自动删除空会话及其记录；已有输入草稿、附件或消息的会话会保留。

会话输入框支持【添加附件】。可一次选择图片和普通文件；图片会作为本轮图片输入提供给模型，其他文件会复制到应用管理的会话附件目录，并在本轮消息中列出文件名、大小和读取路径。附件最多20个，本轮总量不超过32 MiB，单张图片不超过8 MiB。发送前可点击附件右侧的关闭按钮移除。

左右栏、底部输出栏和输入框均有拖动手柄。拖动可调大小，右侧面板在宽屏下最高可调整到 840px，以便查看 Git Diff；双击手柄或聚焦后按 Home 恢复默认；顶部面板按钮可隐藏或恢复面板。界面尺寸与收放状态会保存。

## 3. 从 Jira 查询任务并创建会话

保存 Jira 配置后，右侧面板按账号时区的当天、全部可访问项目、日报范围及仅本人条件自动抓取。查询只读取 Jira；在应用里创建会话不会向 Jira 新建任务或写入处理结果。

【日报日期】在右侧单独显示，可直接修改日期并点击【抓取任务】。【查询条件与历史】中可调整项目范围、查询范围、仅本人以及历史记录。没有查到任务时，先核对日期、范围和负责人条件，不代表账号没有其他任务。

打开任务详情，核对正文、附件和要关联的本地项目，点击【从此任务创建会话】。会话会保存该任务详情与来源地址，后续 Git 提交使用此会话关联的任务地址。

图片会尽量下载并缓存到会话。某张图片下载失败或超过15秒时，会明确提示，仍继续创建会话；已经成功的图片保留。可在会话的 Jira 详情中点击【重试图片】。缓存成功的图片会在发送任务时作为图片上下文提供给模型。

发送前请确认任务描述完整，必要时补充复现步骤、预期结果和验收标准。首轮会先审查开发条件；可从代码、数据字典和开发规范确认的内容由 AI 补充，无法确认的关键问题会列出并提示“需求不完整，暂不修改”。警告以红色标题、图标和侧线显示，正文没有整块红底。

看到警告后，在同一会话补充准确条件，再要求重新审查。涉及业务口径、数据变更、跨系统接口或无法从证据确定的事项，应由开发人员确认后继续。

## 4. 使用 Agent 分析与开发

输入任务，按 Enter 发送；Shift + Enter 换行。可以继续在同一会话中补充需求、纠正理解或要求核查。阅读历史消息时，新输出不会把当前位置顶回底部；需要跟随输出时点击【回到最新消息】。

新会话默认使用完整开发权限，可按规范读取和修改当前会话工作区，并执行构建、测试、命令、网络、数据库和内置浏览器操作。可在任务进行中继续补充对话，输入框有内容时发送按钮可用。代码变更仍需经过开发要求检查、Diff 复核和用户确认后再提交或推送。

涉及代码改动时，Agent 应先阅读仓库同类实现、数据字典及已启用规范，再围绕任务直接实施修改；方案可用于梳理复杂工作，但不是开始写代码的前置门槛。

开发规范会作为任务上下文，机器规则也会在受控写入和提交环节检查；自然语言规范仍需开发者逐项人工复核。任务不设固定30分钟的整轮时限，确需中止时点击【停止】。

完成后在右侧【代码变更】检查每个文件的 Diff，核对是否符合本项目的分层、事务、数据库方言与业务边界。Agent 的文字结论不等于构建或测试通过，应检查其提供的实际验证证据。

需要项目构建、接口联调、数据库验证或运行自动化测试时，直接在会话中提出任务；Agent 会在当前工作区调用命令、内置浏览器或受控数据库连接，并按目标项目实际技术栈执行。代码修改后必须运行目标项目固定构建，只有构建成功才可报告通过。构建、测试和接口验证的命令、退出码、未覆盖项及风险记录在本机数据目录 `%LOCALAPPDATA%\JinggongAgent\verification\<项目或独立会话>\<会话>\<运行>\`，不在目标项目中创建 `test-results` 临时目录。WMS/MES 接口测试需要当前有效的系统授权 Token；未提供时应明确标记为未执行。MES5 按项目要求构建 JZ.IMS.sln；MES6 按仓库实际解决方案与配置构建。

点击会话右上角“打开会话浏览器”，或让 AI 打开网页，浏览器会嵌入主窗口右侧，左侧保留聊天。可在面板内输入网址、前进后退、刷新和切换标签，网页的新窗口链接也会转为内置标签。用户登录后，AI 在同一页面继续操作。

点击“收起浏览器”会保留当前网页、标签和登录状态；再次打开即可继续。不同会话分别保留页面，切换会话时展示对应页面；打开设置或菜单时网页暂时隐藏，关闭后恢复。浏览器下载文件保存在本机数据目录的 `exports/browser` 下。

## 5. Git 提交说明自动附加 Jira 地址

进入右侧【Git】，查看当前分支与状态，点击【根据 Diff 生成提交说明】，或直接在【提交说明】中输入中文说明。关联 Jira 的会话会自动附加任务地址，示例：

```text
修复设备过站报错

Jira: https://jira.example.com/browse/CD-435
```

自动生成时，任务地址会直接显示在输入框中。手写说明时，即使未填写地址，点击提交后也会自动补齐；已包含同一完整任务地址时不重复添加。没有关联 Jira 的普通会话保持原提交说明。任务地址取自该会话的任务快照。

提交前点击【检查开发要求】。机器规则存在阻断项时先修复；需要人工审核的文字规范必须逐份核对并勾选。确认 Diff、构建与测试结果后，点击【审核并提交】，核对系统确认框里的最终提交说明、Jira 地址及文件范围，再选择【确认提交】。

最终提交说明、Git 提交正文与会话中的提交记录保持一致。包含自动追加的地址在内，提交说明上限4000字；超长会提示精简，不会截断后悄悄提交。

提交只写入当前 agent/* 分支。需要共享时选择远程并点击【推送分支】，再次确认；不会自动合并到主分支。拉取只接受远程同名分支的快进更新，存在未提交变更或分叉时先人工处理。远程认证需在开发电脑上提前配置。

## 6. 完成提醒、记忆与在线更新

会话成功完成后，界面显示完成消息，按【设置 > 外观】所选提示音播放，并在会话列表显示小蓝点。项目收缩时也会提示有已完成会话；点击查看相应会话后清除，未读标记在重启后保留。

窗口处于后台或最小化时，Windows 任务栏会闪烁提示；回到窗口后停止闪烁。窗口藏在系统托盘时，会显示任务栏入口进行提醒，不抢走输入焦点。提示音可选择默认的几种声音或关闭，并支持试听。

成功完成的任务会从有复用价值的偏好、约束、决策和经验中生成或更新记忆，不会把所有会话整体保存为记忆。可在【设置 > 记忆】查看或删除，也可手动补充已确认的信息。后续任务参考同项目近期自动记忆；自动摘录仍需结合代码和规范核实。

在【设置 > 更新】查看当前版本号、更新地址和更新方式。更新地址可填写 GitHub 仓库地址，或提供 `latest.yml` 所在目录的 HTTPS 地址，点击【保存更新地址】后生效。0.6.9 正式安装包具备在线更新配置时，即使没有企业 Authenticode 证书，也可通过 HTTPS 检查和下载更新，并校验更新清单中的 SHA512。

选择【自动更新】时，应用在启动后静默检查并后台下载；选择【手动更新】时，点击【检查更新】，发现新版本后再点击【下载更新】。下载完成后点击【重启并更新】，应用退出后完成安装并重新启动，保留本地数据。更新地址或网络不可用时，设置页会显示检查或下载失败状态，可恢复网络后重试。

安装包继续提供启动时开发规范首次拉取和 MES5、MES6、WMS 三套基础数据字典。首次启动会校验字典清单和 SHA256 后导入本地资料库；已有停用或本地修改的同标识资料不会覆盖。项目实际表结构和客户扩展字段仍以目标项目字典为准。这些能力在 0.6.7 已提供，并非 0.6.9 新增。

0.6.7 及更早版本仍受原来的签名门禁限制，不能通过应用内更新直接跨到 0.6.9，请手动安装一次 0.6.9。无企业 Authenticode 证书的 0.6.9 安装包不会显示 Windows 可信发布者身份；HTTPS 与 SHA512 校验更新传输和文件完整性，不等同于代码签名。请只使用正式发布渠道提供的安装包和更新地址。

## 7. 常见问题与团队交付建议

项目无法添加：确认选择仓库根目录，Git for Windows 可用，并且仓库已有提交。会话工作区不可用时，可新建会话；旧消息仍可查看，需要删除时从右键菜单操作。

Jira 没有结果：检查日报日期、账号时区、项目范围、仅本人和日报日期字段。抓取失败会保留本地历史，可恢复网络后重试；不要把历史结果误当成本次查询成功。

图片下载失败：会话仍可使用，查看哪些图片未带入并重试。模型无法看到的图片，应补充文字说明或恢复图片后再继续开发。

会话附件发送失败：检查文件是否仍存在、是否为符号链接、单文件是否超过32 MiB（图片8 MiB）或本轮是否超过20个附件；移除失败附件后重新选择即可。普通文件不会自动解析，Agent 会按消息中给出的应用管理路径读取。

运行报错或任务停滞：查看会话消息及底部【运行输出／工具活动】；需要时点击【停止】，保留错误信息与相关 Diff，再决定是否重试。不要仅依据“已完成”认定业务验收通过。

提交按钮不可用：检查是否有真实变更、填写提交说明、完成开发要求检查并勾选人工复核项；等待正在执行的任务或 Git 操作结束。远程拉取、推送失败时先在 IDE／终端确认仓库和认证状态。

本地数据默认位于 %LOCALAPPDATA%\JinggongAgent，包含会话数据库、工作区、配置和缓存。左下角【导出会话备份】只导出会话数据库，不包含密钥和代码；代码应另行通过 Git 或文件备份保存。凭据受当前 Windows 用户保护，不适合直接复制给其他开发者。

窗口右上角关闭会隐藏到系统托盘。需要彻底退出或升级时，右键托盘图标选择【退出精工智能开发平台】。执行任务期间退出会提示是否中断。

团队建议按“确认 Jira 范围与验收标准 → 选择正确项目和系统 → 启用规范与字典 → 开发与 Diff 复核 → 固定构建及所需测试 → 带 Jira 地址提交 → 人工评审合并”的流程使用。将本安装包与说明书一起发给开发人员，每人自行配置获授权的模型和 Jira 账号。
