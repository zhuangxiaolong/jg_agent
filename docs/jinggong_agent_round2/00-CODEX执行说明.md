# 给 Codex 的执行说明：第二轮工程化增强

请先阅读本目录：

1. `01-第二轮工程化增强-需求方案.md`
2. `02-第二轮工程化增强-技术方案.md`

## 执行原则

本轮是在已实现的精工 Agent 基础上做工程化增强，不是重新开发一套 Agent 平台。必须先检查仓库事实，识别已有能力并复用。

## 第一步：只做现状盘点，不改业务代码

输出《第二轮工程化增强-现状盘点与差距分析.md》，至少包含：

- 当前技术架构与关键模块。
- 当前数据库表、任务/会话/Agent 数据结构。
- Codex Runtime 与精工 Runtime 的能力矩阵。
- 现有功能与本需求逐项映射（REUSE / EXTEND / NEW / UNSUPPORTED）。
- 需要修改/新增的文件清单。
- 数据迁移方案和兼容风险。
- P0/P1 实施顺序及每阶段测试方式。

盘点完成后再开始编码，不需要等待用户再次确认；如发现关键技术能力不支持，必须先说明限制和可行替代路径。

## 第二步：按阶段实现

1. P0 任务契约、状态机、事件和真实证据链。
2. P0 权限、审批、预算、熔断和工具执行网关。
3. P0 Git Worktree 隔离、冲突检测和人工集成。
4. P0 持久化、异常恢复和故障注入。
5. P0 端到端验收。
6. P1 Agent 模板、质量指标、知识库版本、人工接管、诊断包、驾驶舱、四视图 UI 和通知。

每一阶段先更新差距分析和开发计划，再实际修改代码。不要把所有功能堆在一次大改中。

## 必须遵守

- 不得破坏现有 Codex Runtime 和精工 Runtime。
- 不得重复建设现有模型管理、Jira、知识库、Git、通知或日志模块。
- 不得用模拟状态或静态数据冒充真实执行。
- Agent 执行完成不等于测试通过；测试通过不等于人工验收。
- 不得绕过工具层权限校验。
- 不得在异常恢复时无条件重放可能有副作用的工具调用。
- 不得在没有可信 Usage 时显示精确 Token/费用。
- 不得自动删除 Agent 工作区中的未集成代码成果。
- 不得将密钥写入提示词、普通日志或诊断包。
- 对 Runtime 不支持的能力必须如实显示，不得用包装层伪装为原生支持。

## 最终交付

- 现状盘点与差距分析报告。
- 需求映射矩阵。
- 代码变更清单。
- 数据库迁移脚本与回滚说明。
- 单元、集成、故障注入和端到端测试结果。
- 实际运行截图。
- 未完成项、Runtime 限制和已知问题。
