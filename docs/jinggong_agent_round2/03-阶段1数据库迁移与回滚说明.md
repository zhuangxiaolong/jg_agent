# 阶段 1 数据库增量迁移与回滚说明

日期：2026-11-10。适用范围：第二轮任务契约、三维状态、结构化审计和证据索引。未调整主会话、模型配置或插件既有数据结构。

## 升级过程

`LocalStore.open` 在 SQLite 头、`quick_check` 和版本检查成功后，任何受支持旧版本迁移之前，先以原始字节生成同目录备份：

`<原数据库路径>.pre-v10-from-v<原版本>-<毫秒时间>-<随机后缀>.bak`

备份采用既有临时文件、fsync、rename 原子写入；备份失败时不开始迁移。不自动删除备份。空数据库首次创建不需要迁移备份；损坏、无版本信息或高于当前版本的数据库仍拒绝打开，保留原文件。

现有基线为 v8。本轮 v8→v9 增加四张表；v9→v10 增加八个更新、删除保护触发器。`03-阶段1数据库迁移.sql` 给出供审阅的 v8→v10 等价 SQL，正常应用启动使用代码中的迁移，不需要额外执行脚本。既有 v1→v8 迁移保留不变。

## 新表及保留规则

- `agent_task_contracts`：按 task_id、version 追加契约快照和 SHA-256。修订不会覆盖旧版本。
- `agent_task_lifecycle_events`：与展示用、可截断的 `agent_task_events` 分离。每条记录包含聚合版本、操作者、事件类型、载荷、前一条 Hash 和当前 Hash；读取时验证同任务链及版本递增。
- `agent_task_evidence`：不可变证据索引，记录真实执行来源、Manifest、日志、代码指纹、契约版本等。当前活动证据由任务快照的 `evidenceIds` 精确指向；历史失败证据保留，不混入后续通过结果。
- `verification_executions`：固定执行器实际完成后登记 runId、会话、项目和执行记录、Manifest Hash。仅有关联文件而没有不可变执行登记的历史运行，不补登记为真实通过来源。

四张表均禁止 SQL UPDATE/DELETE，不设置随任务或会话删除的级联外键，删除会话仍保留审计历史和证据索引。运行结果正文和日志文件仍使用现有验证目录；索引不是文件副本。真实文件、Manifest 和当前工作区指纹由主进程再次复核。

契约、任务状态和对应结构化事件在同一个既有 `LocalStore.transaction` 内提交；落盘失败同时恢复内存快照。证据归档和证据事件同样原子提交。真实验证执行索引单独不可变登记且同内容重复登记幂等，内容冲突拒绝覆盖。

## 旧任务兼容

保留原 `AgentTask.status`，新增可选 executionStatus、verificationStatus、acceptanceStatus、contractVersion、stateVersion 等字段。没有契约的历史任务不自动补造契约、证据、验证或验收通过；展示层可说明“历史任务未建立工程契约”。

上次退出时的 RUNNING 任务恢复为 executionStatus=INTERRUPTED、兼容 status=BLOCKED，不标记为执行失败，不自动重放、不伪造完成时间；验证仍 RUNNING 的任务恢复 INCONCLUSIVE。首次恢复追加事件，再次启动不重复追加。显式继续仍需用户触发并遵守预算。

阶段 2 工具审计继续复用生命周期事件表，不变更 schema。已写 tool.started 但没有对应终结事件的调用，重启时追加 tool.unknown_outcome，任务转为 INTERRUPTED/BLOCKED，不重放原调用；原通过/验收状态不继续作为安全结论。工具事件只保存工具名、调用标识和参数/结果 Hash 等摘要。审批只在当前契约有效，已发生的预算消耗跨契约版本保留。

## 回滚

回滚必须在应用和相关进程全部停止后操作。先将当前 v10 数据库完整复制到新的保留文件，再将升级前 `.bak` 原样恢复到原数据库路径，最后使用与该备份版本兼容的旧应用启动。恢复后运行 `PRAGMA quick_check`，确认项目、会话和原有事件可读。

不要只把 `user_version` 改回 8，不要对本轮表执行删表或去触发器来冒充回滚。升级前备份不包含升级后新增的任务、对话或证据索引；回滚前保存的 v10 文件和验证目录应保留供追溯，不自动合并到旧数据库。旧应用遇到 v10 会按已有版本保护拒绝打开。

## 边界

追加约束、Hash 链和不可变真实执行登记用于发现应用层覆盖和不一致，并不声称能防止拥有数据库文件写权限的本机管理员整体替换数据库。验收仍需授权用户以及当前代码、当前契约和真实证据版本一致。此阶段没有执行线上用户数据库迁移或现场回滚。
