# 既有桌面回归：剪贴板环境阻塞说明

日期：2026-11-10。诊断时间约23:00—23:03（Asia/Shanghai）。

## 结论与当前状态

`npm run test:desktop`在`scripts/desktop-smoke.mjs:319`的真实代码复制断言失败，应保留失败状态。本次独立复现将故障范围定位到当前Windows会话的剪贴板访问环境：Win32 `OpenClipboard(NULL)`连续5次失败，`GetLastError=5`（拒绝访问）。具体权限或策略原因未进一步确定。

现有证据不支持把故障归因于本轮任务工程模块、页面焦点或并行smoke竞争；也不能据此认定某个进程锁住了剪贴板。未调整系统安全策略、未结束系统/用户进程、未删除或放宽原测试断言，未修改产品复制逻辑。

## Win32只读定位

`.tmp/round2-clipboard-lock-probe.ps1`没有读取剪贴板正文，也没有清空或写入内容；仅尝试打开后立即关闭，并查询状态。实际连续5次采样：

- `OpenClipboard(NULL)=false`。
- `GetLastError=5`。
- `GetClipboardSequenceNumber=217`，五次均不变。
- `GetOpenClipboardWindow=0`，没有可识别的持锁窗口。
- 剪贴板owner属于Explorer；owner不等于当前持锁者，不能据此要求重启或终止Explorer。

上述实际输出的汇总记录为`.tmp/round2-clipboard-lock-probe-observed.json`。采样进程在Windows会话1；此证据仍不足以确定是窗口站/桌面权限、终端环境还是具体安全策略造成拒绝访问。

## 最小处理建议与限制

1. 保留这项既有回归失败并在最终结果中明确列出环境阻塞；本轮其他工程检查不能代替真实系统剪贴板验收。
2. 在确认当前Windows交互会话可正常访问系统剪贴板后，原样重跑`npm run test:desktop`；不能删断言、只验证按钮文字或把空串当成功。
3. 本次不扩大范围修改系统策略或复制产品逻辑。后续若单独改进复制可靠性，应考虑对原生API静默返回但内容未写入的情形显示失败；这属于既有行为的独立改进，不应包装成本轮功能回归修复。

两个诊断Electron应用均已执行`app.close()`，诊断进程均已退出。之后停止所有UI/剪贴板实验，留给主任务执行最终round2 smoke截图。
