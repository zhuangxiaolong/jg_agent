# 第二轮工程化增强：现状盘点与差距分析

盘点日期：2026-11-10。代码基线：`develop/desktop-poc` / `1855625` 加当前工作区。工作区已有大量未提交修改，本报告不将已有功能归因为本轮新增，不清理、不提交这些修改。

## 1. 盘点结论与实施边界

这是 Electron + React + TypeScript 桌面项目，无 MES5/MES6 后端解决方案；MES 版本识别约定适用于后续目标业务仓库。已有会话、模型、Jira、需求准入、知识库、Git、测试证据、通知和日志必须复用。

当前子 Agent 只支持 Codex/Jinggong 只读分析，并不是已具备隔离写入和安全集成的开发 Agent。已有真实测试执行器可以复用，但没有任务级证据关联、三维状态或人工验收。第二轮先补工程基础，不以新增 UI 代替可靠性验收。

关键限制：原生 shell/apply_patch 并非每次都会进入平台审批回调；Windows unelevated sandbox 不是已验证的严格 OS 禁网。不能把新增平台策略宣称为 Runtime 内部全量强制。硬路径、逐工具调用数、网络和费用限制不能执行时，必须拒绝对应受限任务或明确禁用能力，不能仅向 Prompt 写规则。

- `packages/agent-orchestrator/src/index.ts`、`main/agent-tasks.ts`：任务图、依赖、只读子任务调度，固定全局并发 3。
- `packages/storage/src/index.ts`：SQLite/sql.js、本地 JSON 实体、版本迁移、事务快照原子落盘。

## 3. 存储与兼容基线

现有 schema 已由 v8 增量升级到 v10。除原有表外，v9 增加任务契约修订、工程事件、证据索引和真实执行登记四类追加表，v10 增加不可变触发器；迁移前保留原始数据库字节备份。

默认数据根为 `%LOCALAPPDATA%/JinggongAgent`；数据库在 `database/jinggong-agent.db`，验证制品在 `verification/<project>/<session>/<run>`。测试可使用独立 `JINGGONG_TEST_DATA`。

`Session` 已有 Runtime/thread/session ID、workspace、项目、模型、Jira 和准入字段。`AgentTask` 已有父任务、依赖、角色、输入、单一 status、尝试次数、可选超时、workspacePath 和结果摘要。没有结构化契约版本、正交验证/验收状态、任务级审批/预算记录。

`LocalStore.open` 做 quick_check，拒绝未来版本；迁移按 user_version 递增。事务成功后以临时文件 + fsync + rename 原子落盘，失败可恢复内存快照；已有 backup()，尚无每次迁移自动备份。当前 RUNNING 子任务重启改 FAILED；主会话才改 interrupted。任务 UI 日志只保留最新 5000 条且有删除级联，不能当长期审计链。documents 覆盖更新/删除，digest 不是历史版本库。

## 4. Runtime 能力矩阵（当前代码事实）

标记说明：runtime=原生；platform=平台实现；partial=部分；none=当前不支持。该矩阵不是供应商产品能力承诺。

| 能力 | Codex | 精工 Runtime | Claude SDK |
|---|---|---|---|
| event_stream | runtime，app-server 事件 | runtime，同协议 | runtime，SDK 流 |
| session_recovery | runtime，thread/resume；不保证内部推理恢复 | runtime，同左 | partial，nativeSessionId + resume |
| independent_agent_context | platform，独立 home/thread | platform，独立 home/thread | platform，独立会话；子任务未接入 |
| native_subagents | none，当前关闭 multi_agent | none，当前关闭 multi_agent | none，当前未接 |
| pause_resume | none，只有 interrupt/cancel；续接是新执行 | none，同左 | none，AbortController 取消 |
| token_usage / cost_usage | none，当前未采集可信字段 | none，同左 | none，当前未采集可信字段 |
| tool_permission_interception | partial，平台动态工具/必要时审批；非全部原生调用 | partial，同左 | partial，canUseTool 非已验证逐调用 Hook |
| worktree_support | platform，会话级 GitConnector；子任务未接入 | platform，同左 | platform，已有 cwd 校验但不创建 |
| structured_result | partial，文本事件 | partial，文本事件 | partial，规范化文本/result |

代码依据：`RuntimeAdapter`、`CodexRuntime.handleReadTool/handleApprovalRequest`、`ClaudeAgentSdkRuntimeAdapter`、`AgentTaskRunner.buildRuntime`；禁网限制已有 `scripts/probes/runtime-probe.mjs` 与 `docs/runtime-migration/windows-sandbox-test.md` 记录。

## 7. 迁移与回滚设计

从 v8 增量升级到 v10，优先在现有 AgentTask JSON 加可选字段；旧 status 保留兼容读取。新增长期不可变契约、结构化状态事件、任务证据索引，禁止迁移时给旧任务补造 PASSED/ACCEPTED。

升级前保留数据库备份。新迁移需要事务、唯一键和版本检查；验证磁盘失败能回退内存状态。审计链不能沿用5000条UI截断。不得通过删除会话静默销毁任务工程证据。

旧程序会拒绝更高 user_version，不能简单降版本号。回滚前先导出/保留升级后数据与所有 Worktree；在关闭程序后恢复升级前备份，或使用兼容新schema的修复版本。绝不删除新表或未集成代码以“回滚”。

## 8. 分阶段顺序与质量门禁

阶段0已完成只读代码盘点，本文件先于业务代码落盘。

1. P0-1：契约、三维状态、不可变事件/证据索引；契约缺项、非法状态、并发版本、历史兼容、事件不可覆盖测试。
2. P0-2：能力声明、权限/审批、预算、退避/熔断；参数改变、过期、路径、未知usage、并发/超时硬上限测试。
3. P0-3：任务Worktree与集成预检；Windows真实Git双工作区、同文件冲突、dirty、基准漂移、保留成果测试。
4. P0-4：重启中断与安全恢复；真实数据库重开、未决副作用、重复事件和磁盘失败测试。
5. P0-5：类型检查、构建、完整测试、Electron smoke与实际截图；隔离样本可作工程集成证据，不冒充真实MES/WMS业务验收。
6. P1：仅在所有P0通过含非生产MES/WMS真实任务端到端验收后依顺序建设。缺少目标任务/环境或Runtime能力时保留门禁，列明未验收事项。
