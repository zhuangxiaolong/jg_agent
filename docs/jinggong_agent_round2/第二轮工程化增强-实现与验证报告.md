# 第二轮工程化增强：实现与验证报告

日期：2026-11-10。仓库为 Electron + React + TypeScript 桌面项目，不包含 MES5/MES6 后端或可供本轮调用的非生产 MES/WMS 环境。本报告区分代码实现、构建、自动化测试、工程集成样本和人工业务验收，不把其中任一项替代另一项。

## 已实现

- 任务契约、版本修订、三维状态、验收条件、预算继承、能力声明、审批摘要、退避/熔断和不可变审计事件。
- SQLite v8→v10 增量迁移：契约/事件/证据/真实执行登记追加表、不可变触发器、迁移前原始字节备份、恢复中的未知副作用标记。
- 任务级真实执行登记、Manifest/日志/JUnit/代码指纹复核和历史详情完整性检查；证据被改写、删除或当前代码漂移时不显示为当前通过。
- 任务专属 Git Worktree、冻结 baseCommit、已提交/暂存/未暂存/未跟踪变更检查、路径和隐藏索引标记检查；集成入口只生成需人工审批的计划，不执行 merge、commit、push 或 cleanup。
- Codex 与 Jinggong Runtime 的严格能力门禁、动态工具网关、一次性审批、取消/中断/恢复状态和受控 IPC/UI。原生 Runtime 不支持全部模型/工具硬限额及可信 Usage 时，新工程任务在读取凭据、启动 Runtime 和消耗 attempt 前保持 `BLOCKED`；旧会话路径保持兼容。
- Agent Tasks、工程详情、工作区预检、预算与恢复状态的桌面展示，并完成 1600×900 与 1366×768 截图检查。

## 未通过或未完成的验收门禁

1. `npm run test:desktop` 在既有代码复制断言处失败。独立 Electron、preload、页面按钮和 Windows Forms STA 均无法从当前 Windows 会话读回剪贴板；Win32 `OpenClipboard(NULL)` 连续采样返回拒绝访问。产品复制链和断言未因本轮而放宽，证据见《既有桌面回归-剪贴板环境阻塞说明.md》。需在剪贴板可正常访问的交互会话中原样重跑。
2. 没有用户提供的非生产 MES/WMS 项目、凭据和可执行验收任务，因此不存在真实业务构建、测试、运行、人工验收或上线证据。P0 业务验收不能标记通过，P1 模板、指标、知识冻结、诊断包、驾驶舱、四视图和通知扩展保持关闭。
3. 当前 Runtime 能力矩阵仍明确记录：原生逐次模型/工具硬上限、完整工具拦截和可信 token/cost usage 不可证明。为避免虚假合规，严格工程任务保持阻断；UI 将 Usage 显示为未知，不填估算值。
