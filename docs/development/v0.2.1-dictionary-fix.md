## 来源事实与失败链路

用户明确选择的两份本地工作簿用于只读快照导入，工作簿及其业务正文未复制进仓库。

- `IWMS5数据字典.xlsx`：357,484 字节，`nlink=1`，3 个工作表，7,556 行、80,995 个单元格，完整提取 738,960 字符。ZIP 共 18 个条目，解压总量 3,240,217 字节，最大 XML 条目 2,958,173 字节。首个解析错误来自 41,595 个带样式的空共享字符串单元格：`t="s"` 但没有 `<v>` 是合法空值，旧实现将其误判为无效共享字符串索引。
- `iMES5数据表.xlsx`：661,652 字节，`nlink=2`，2 个工作表，13,905 行、109,747 个单元格，完整提取 1,141,087 字符。ZIP 共 11 个条目，解压总量 4,424,236 字节，最大 XML 条目 3,913,643 字节。首个错误来自把用户选择的只读资料硬链接当作可写 Agent 工作区链接拒绝；相同字节的单链接临时副本继续触发旧版 40,000 单元格限制。
- 两份工作簿还超过旧版 80,000 字符正文限制；结构定义中的 `Password` 等字段名称被旧版凭据列名检查误报。两份文件均未超过旧版单 XML 4 MiB、解压总量 16 MiB、512 个条目和 100 个工作表限制，但字典容量现在统一采用下述独立边界。
- 截图中的主进程 `EPIPE` 属于错误输出通道问题，不能与工作簿解析错误混为一项。预期导入失败需要返回可显示的业务错误，不能使桌面进程退出。

## 修复与边界

### 只读快照与解析

- 允许用户明确选择的普通硬链接文件作为只读来源，仍拒绝符号链接；此放行不改变 Agent 可写工作区的链接防护。
- 打开前、打开后及读取完成后检查文件的 inode、设备、大小、修改时间和变更时间，并复核原路径身份。读取不一致则拒绝保存，不静默接收部分内容。整个导入过程不写入来源文件。
- 样式空单元格保持空值并保留原坐标；共享字符串索引通过文本值解析，真实无效索引继续报错。工作表标题继续采用 `[工作表：名称]`，单元格坐标和正文完整保存。
- 字典独立上限：单文件 32 MiB、单 XML/ZIP 条目 32 MiB、解压总量 128 MiB、4,096 个 ZIP 条目、256 个工作表、250,000 个单元格、2,000,000 字符正文。仍检查压缩比例、ZIP 路径、宏、嵌入对象、XML 实体及 DTD，超限明确拒绝，不截断。
- SQLite 保存和重新启停资料使用相同的按类型容量检查，避免导入成功但存储失败。

### 开发要求与凭据

- 开发要求保持原边界：单份 80,000 字符、8 MiB 来源文件、单条目 4 MiB、解压总量 16 MiB、512 个 ZIP 条目、100 个工作表、40,000 个单元格。完整要求仍注入开发上下文；超过整体上下文预算时拒绝启动，不删减要求。
- 仅字典允许明确的 SQL/CLR 结构定义，例如 `Password` 字段及其 `String` 类型。凭据数据表、带真实值的密码/Token 赋值、密钥标记、私钥、认证头和带凭据 URL 仍拒绝；主进程继续检查已配置的已知密钥。
- 此检查用于防止资料误存凭据，不代表能识别所有业务自定义秘密。测试数据只使用合成值。

### 完整分页与按需读取

- 本地保存完整字典。界面按工作表、页和检索结果展示，分页只限制当前渲染量；应能够到达末页并查看完整尾部内容。
- 开发上下文只包含适用字典的目录、来源摘要和工具使用说明，字典正文不再全量灌入上下文。
- `search_dictionary` 用于检索，`read_dictionary` 通过偏移分块读取完整正文；每块返回继续读取的位置和完成状态，允许逐块读至末尾。启用状态和 MES5/MES6/WMS/通用范围在工具边界执行，不能读取其他系统或已禁用字典。
- 动态工具统一使用固定版接受的 function Schema，真实 Windows Runtime 的 thread/start 与 resume 协议测试通过。工具调用必须绑定当前项目和活动 turn；长行命中返回实际片段偏移。旧能力版本的会话下一轮会创建支持字典工具的新 Runtime 线程，SQLite 中原会话与消息仍可查看，但该新线程的模型上下文重新建立；界面会明确提示。没有用本地工具测试冒充真实模型调用。

### 桌面错误通道

- 主进程以结构化 IPC 返回成功值或已脱敏业务错误，preload 统一解包，预期导入错误由界面显示。
- GUI 标准输出与标准错误增加断管防护，避免桌面脱离启动终端后，向已关闭通道写日志引发未处理的 `EPIPE`。
- 安装版实测关闭父端 stdout/stderr 后，console.error、标准错误写回调与 renderer IPC 均正常；随后导入不支持的文件仅显示准确中文提示，主进程存活且 Win32 原生异常对话框数为 0。未安装吞掉任意 uncaughtException 的全局处理器。
