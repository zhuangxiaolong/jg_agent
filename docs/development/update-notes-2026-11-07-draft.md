# 精工智能开发平台更新说明（2026-11-07 草稿）

适用版本：0.6.8（旧版需手工安装一次，线上发布由 `v0.6.8` 标签触发）
适用对象：战区 MES5、MES6、WMS 开发人员

## 一、2026-11-06 已完成事项

### 会话与界面

- 项目和会话的修改、删除入口统一放到右键菜单，也支持 `Shift + F10` 和键盘操作；删除前需要确认，取消不会改变数据。
- 会话名称使用 Jira 概要，不再重复带项目名称；界面默认深色，右侧 Jira、代码变更、Git 和上下文面板可分别切换。
- 会话完成后显示完成消息、播放可配置提示音、会话列表显示蓝点，并在应用处于后台时触发 Windows 任务栏提示。
- 会话输入框允许在任务运行后继续发送补充说明；工具事件压缩为有意义的简短信息，减少无效输出对消息阅读的干扰。
- 左侧项目、会话栏和右侧面板支持拖动调整大小；本地项目默认收缩，状态会持久化。

### Jira 与资料

- Jira 图片下载失败或超时只提示具体附件问题，会话仍然可以创建；成功缓存的图片继续进入会话上下文。
- Jira 查询的日报日期单独显示，可作为直接查询条件；创建会话前会检查任务是否具备开发条件，不完整时显示警告并列出待确认项。
- “生产字典”统一更名为“数据字典”；根据仓库指纹自动识别 MES5、MES6 或 WMS，并加载对应数据字典。
- 开发要求与规范支持在线同步；会话会先发布代码修改方案，范围变化时必须更新方案。
- 支持会话和记忆导出、导入，便于团队共享疑难问题的处理记录。

### 运行、更新和交付

- 会话运行不再设置固定的 30 分钟限制；仍可通过停止操作主动中断。
- 更新设置显示当前版本号，支持修改更新地址和自动/手动更新方式；无企业证书时使用 HTTPS + `latest.yml` SHA512 校验，正式签名配置存在时仍使用 Authenticode 校验。
- 提交说明自动附加关联 Jira 地址；提交、推送和拉取都只针对当前 `agent/<会话 ID>` 分支。
- 已提供 Windows x64 安装包和开发人员使用说明。

## 二、2026-11-07 已完成事项

### 启动同步与内置数据字典

- 开发规范首次启动默认在后台拉取；已有同步记录时按【自动更新开发规范】设置在每次启动后台检查，手动关闭后不再自动检查。
- 安装包内置 MES5、MES6、WMS 三套基础数据字典，首次启动校验清单和 SHA256 后写入本地资料库；已存在、停用或用户修改的同标识资料不会被覆盖。
- 内置字典是基础检索索引，项目真实表结构、客户扩展字段和接口口径仍以目标项目字典为准，可在设置中继续导入项目资料。

### 无证书在线更新引导

- 0.6.8 发布包即使没有企业代码签名证书，也会启用 GitHub HTTPS 更新；electron-updater 继续校验 `latest.yml` 的 SHA512 和下载文件完整性。
- 0.6.7 及更早版本包含旧的签名门禁，不能直接自升级；需先手工安装 0.6.8。之后版本可按设置自动下载，重启时完成替换。
- 无 Authenticode 不能提供 Windows 可信发布者身份，必须保护 GitHub 账号、分支和版本标签；正式长期方案仍建议接入企业签名或内置公钥清单签名。

### 会话修改后的构建、测试与报告

- 只要会话实际写入或删除项目代码、配置、SQL、测试或构建文件，Agent 就必须在修改完成后执行项目真实构建和相关测试。
- 构建和测试命令需依据目标仓库的解决方案、项目文件、脚本和开发规范确定，不能用静态阅读、生成测试用例或未执行的命令代替验证。
- 目标项目必须生成 Markdown 报告：

  `test-results/agent-test-results-YYYYMMDD-HHmmss.md`

- 报告至少记录会话/Jira、变更文件、实际完整命令、每条命令退出码、构建结果、测试结果、未覆盖项和剩余风险，并区分：

  - 已执行通过
  - 已执行失败
  - 未执行
  - 环境受阻
  - 仅生成未验证

- 会话完成时会读取真实工作区差异、命令事件和报告文件；缺少任一构建、测试或报告证据时，界面明确显示“验证未完成”，不会把文字描述当成通过结果。

### 会话图片和文件附件

- 输入区新增【添加附件】，可一次选择图片和普通文件，并在发送前逐个移除。
- 图片作为本轮原生图片输入发送；普通文件复制到应用管理的会话附件目录，并在用户消息中提供文件名、大小和读取路径，便于 Agent 按需读取。
- 主进程校验附件来源为普通文件，拒绝符号链接和异常硬链接；最多 20 个附件，本轮总量 32 MiB，单张图片 8 MiB。
- 附件选择失败不会启动任务；移除失败项后可重新选择。会话删除时清理附件索引，应用数据仍由本机管理。

### 代码变更与 Git 文件级操作

- 右侧【代码变更】文件列表支持右键菜单，当前文件可执行：

  - 查看该文件的真实 Diff
  - 暂存或取消暂存该文件
  - 撤销该文件在当前会话工作区的修改
  - 在文件管理器中定位文件

- 文件级操作继续使用应用管理的 Agent 工作区和路径校验，不允许越界访问主仓库、其他目录、目录联接、符号链接或敏感文件。
- “撤销该文件修改”会显示确认提示；确认后才恢复到当前会话基准提交，未跟踪文件会被删除，取消则保留现状。
- Git 面板仍用于批量检查开发要求、生成提交说明、提交、推送和快进拉取；右键操作完成后可刷新代码变更和 Git 状态。

### 分支与历史会话修复

- 输入区原先显示的 `agent/<ID>` 改为可切换的本地基准分支选择器；切换只改变当前会话工作区基准，仍保留会话自己的 `agent/<会话 ID>` 分支。
- 有未提交修改时禁止切换基准分支，避免覆盖当前代码。
- 旧版本曾将会话工作区记录在 Electron 缓存目录；启动和 Git 操作会自动迁移到当前应用管理的工作区，修复历史会话代码变更和 Git 面板显示为空的问题。
- 会话完成后立即刷新代码变更，确保 Agent 报告的文件与 Git 面板实际内容一致。

## 三、推荐使用流程

1. 在项目下创建会话，确认 Jira 概要、基准分支、系统类型、数据字典和开发要求。
2. 先让 Agent 发布代码修改方案，再确认待改文件和验证计划。
3. 修改完成后检查会话中的构建/测试/报告核验结果。
4. 打开【代码变更】，逐文件查看 Diff；需要单文件处理时右键选择对应 Git 操作。
5. 在【Git】面板逐项检查开发要求，确认提交说明已包含 Jira 地址，再提交到当前 Agent 分支。
6. 经人工评审后，再推送到远程仓库或由团队流程合并。

## 四、验证说明

- 精工智能开发平台自身构建和测试只证明客户端功能可用，不替代目标项目的构建、测试和业务验收。
- 目标项目的最终结论以 `test-results/agent-test-results-*.md` 中的真实命令退出码、测试输出和未覆盖项为准。
- 真实 Jira 写入、生产数据库和硬件联调仍需在获授权的测试环境执行。
