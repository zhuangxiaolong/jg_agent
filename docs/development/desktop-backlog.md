# 后续任务与退出条件

V0.1 基础链路已建立；V0.2 新增设置/主题/记忆管理/Jira 配置/资料导入/规则/多中转站和受控文件开发/Git 操作。实际范围及限制见 v0.2-acceptance.md。

下一批按下列顺序推进，每项均要求真实服务/资料验证，不使用模拟核心数据。

- 原生沙箱与命令执行：受控文件写入已独立开放，任意构建/测试命令仍需 Windows 普通账户和沙箱边界验收；样本仓库真实模型完成修复、构建测试、Diff，原始分支不变。
- 独立模型接入与兼容：多中转站/模型配置已实现；用户输入独立密钥后逐项验证每个模型的真实流式、工具调用、取消、恢复和用量，不以配置保存代替兼容通过。
- 安装加固：干净 Windows 账户无开发工具安装启动；Git 缺失的可信引导；签名/哈希；卸载数据保留、升级和恢复演练。
- Jira：提供测试实例与只读凭据，验证 cf[11116] 类型/时区/分页，对 10 个日期与人工结果核对；附件格式逐项解析并保留来源。
- 知识库：导入/预览/系统分类已实现；下一步以各一份当前 MES5/MES6/WMS 字典验证业务准确性，再做版本审批、字段检索、附件保留。
- 规范：正文上下文和 JSON 字面规则门禁已实现；下一步沉淀实际仓库规则包及构建/测试检查，至少 10 条真实违规样本阻断交付。
- 记忆：用户记忆管理已实现；下一步项目分层、自动提炼待审核、纠错/过期/跨项目访问与删除传播测试。
- 稳定性：强杀父进程子树回收、重启恢复、长会话写放大、1–3 并发资源统计、全量备份恢复与 ACL。

需要外部条件：模型配置由用户在新应用中单独完成；测试 Jira/仓库/字典稍后提供。只在临时样本仓库验证 Git 提交/本地 Bare 推送；本开发仓库和任何生产项目不自动提交、推送、合并或发布。HTTPS Git 凭据集成仍待补充。
