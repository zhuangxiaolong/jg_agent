# 精工智能开发平台当前构建操作手册

适用对象：MES5、MES6、WMS、前端项目开发人员。适用环境：Windows x64。

更新日期：2026-11-12　|　仓库版本号：0.6.8　|　当前代码基线：`7a0ce48`

> 本手册按 2026-11-12 当前工作区代码整理。应用版本号仍为 0.6.8，因此安装包是否包含本手册所列的后续能力，须以实际安装包和应用内【设置 > 更新】显示为准。历史发布说明保留在 [0.6.8 使用说明](使用说明-0.6.8.md)。

## 1. 五分钟开始

1. 启动精工 Agent，点击【新建会话】。
2. 需要修改代码时，在【本地项目】右侧点击加号，选择已有提交记录的 Git 仓库根目录；然后在项目下点击【新建会话】。只需要问答或分析时，可以继续使用不关联项目的独立会话。
3. 在输入框下方的会话设置中选择模型中转站、模型、适用系统、Runtime 和推理强度，点击【应用设置】。
4. 在输入框描述目标、范围、验收标准和需要执行的验证命令，按 Enter 发送；Shift + Enter 换行。
5. 任务完成后先看【运行输出／工具活动】和右侧【代码变更】；需要提交时进入【Git】，执行真实构建或测试，再检查 Diff 和开发要求。

正式提交前必须由开发者确认变更范围、构建结果、测试结果和业务验收结论。Agent 的文字总结不等于构建、测试或业务验收证据。

## 2. 安装与首次配置

运行正式安装包并打开应用。开发电脑需要 Git for Windows；模型中转站、Jira、企业微信等服务需要使用组织授权的地址和凭据。安装包自带 Agent 引擎，普通使用不需要另装 Node.js、Python 或 Docker。

打开左下角【全局设置】，按需要完成以下配置：

1. 【模型中转站】：填写名称、HTTPS 地址、模型名称和密钥，保存后可在会话中选择。模型名称必须与中转站实际支持的名称一致。
2. 【Jira 连接】：填写 Jira 地址、账号、密码和默认项目，保存后可测试连接。
3. 【运行时】：查看 Jinggong Runtime、Codex Runtime、Claude Agent SDK Runtime 的版本、兼容性和凭据状态。运行时不会静默回退；未就绪时先处理设置页提示。
4. 【数据字典】：导入并启用 MES5、MES6、WMS、前端或通用资料。
5. 【开发要求与规范】：导入或录入团队规则，设置适用系统并启用。
6. 【外观】：设置主题、界面风格和会话完成提示音，可试听。
7. 【会话与数据】：查看会话、项目、本地数据目录，并按需要导出或导入会话备份。
8. 【企业微信通知】：配置群机器人目标和事件范围；Webhook 不会回显，通知失败不会改变会话结果。

密钥、密码和 Webhook 由本机 Windows 保护存储。不要把它们粘贴到任务描述、记忆、开发规范或提交说明中。

## 3. 项目、会话与工作区

### 添加项目

点击【本地项目】右侧的加号，选择 Git 仓库根目录。仓库必须已有至少一次提交。应用会为项目建立识别信息，项目源代码目录保持不变。

### 创建会话

- 从欢迎页或左上角【新建会话】创建不关联项目的独立会话。
- 展开项目后点击项目下的【新建会话】，创建关联项目的会话和独立 Git Worktree。
- 项目下的会话使用独立目录和 `agent/*` 分支；变更不会直接写入项目源目录。
- 创建 Jira 会话时，先在 Jira 面板选择任务和本地项目，再创建关联会话。

### 切换和解绑项目

在输入区的项目选择中选择其他项目，可将当前会话切换到新的项目。原项目目录及其改动会保留，应用会在会话消息中提示恢复路径；切换不会复制或覆盖原目录中的改动。

选择【不关联项目】并应用，会话变为独立会话，原项目目录仍保留。切换项目或解绑前，先在【代码变更】和【Git】中确认未提交内容。

### 识别系统

创建或调整会话时，应用按仓库根目录识别 MES5、MES6、WMS 或前端：前端读取根目录 `package.json` 和 Vite、React、Vue、Angular、Next、Nuxt、Svelte 等根级配置；如果同一仓库有明确 MES/WMS 后端指纹，以后端系统为准。识别结果不准确时，在会话设置中选择正确系统，并确认对应规范和数据字典已启用。

右键项目或会话可修改名称、删除项目或删除会话。删除会话会移除会话和消息记录，但保留代码文件；删除项目须先删除其全部会话，项目源目录仍保留。删除前请核对名称并保存重要改动。

## 4. Runtime、模型和任务设置

会话设置在输入框下方。每个会话可以独立选择：

- 模型中转站和模型；
- 适用系统；
- Jinggong Runtime、Codex Runtime 或 Claude Agent SDK Runtime；
- 推理强度。

运行时选择是会话级设置，不是全局切换。运行中不能切换 Runtime；先停止任务，再应用新的会话设置。设置页显示的“沙箱待验收”“需要认证”“版本不兼容”等状态应在发送任务前处理。

输入任务时，建议同时写清：目标、涉及目录或文件、禁止修改的范围、数据库或网络边界、验收标准、构建和测试命令。输入框支持图片及普通文件附件：最多 20 个，本轮总量不超过 32 MiB，单张图片不超过 8 MiB；发送前可移除附件。

## 5. Jira、需求提示与开发要求

在右侧【Jira】面板可以按日期、项目范围、负责人和历史条件查询任务，打开任务详情查看正文、附件、工作流和任务快照。查询只读取 Jira；在应用中创建会话不会向 Jira 新建任务。

关联 Jira 任务后，应用会显示需求准入提示、需求记录和可能缺失的确认项。需求准入是实施参考，不阻断开发；需求有变化或 Jira 暂时不可用时，刷新快照并把未确认项写入任务说明。

在右侧【Git】面板点击【检查开发要求】可执行机器规则检查，并逐份核对需要人工审核的规范。需求准入提示和 Git 提交前的开发要求检查是两件事：前者不阻断开发，后者出现机器阻断项或未完成的人工复核时会阻止提交。

## 6. 项目外资料和浏览器

### 项目外资料读取

输入框上方会显示当前会话的项目外资料范围。当前默认是全量只读，并自动跳过系统、凭据和链接；也可以点击【选择目录】改为指定目录只读。

- 选择目录后，Runtime 会重新建立会话并显示已授权路径。
- 对不再需要的路径点击撤销目录授权。
- 需要恢复默认范围时点击【恢复全量读取】。
- 运行中的会话不能修改目录授权；先停止任务。

只读授权允许分析资料，不代表允许修改这些目录。代码修改仍发生在当前会话工作区。

### 会话浏览器

点击右上角【打开会话浏览器】，或在任务中要求 Agent 打开网页。浏览器与当前会话共享，支持地址栏、后退、前进、刷新和标签切换。

1. 输入网址并打开；没有协议时按 HTTPS 访问。
2. 需要登录时由用户在浏览器中完成登录，再让 Agent 继续操作。
3. 点击【收起浏览器】只隐藏面板，页面、标签和登录状态会保留；不同会话分别保留页面。
4. 下载文件会显示在浏览器面板中，并保存到本机数据目录下的 `exports/browser`。

设置、菜单或对话框打开时，网页会暂时隐藏；关闭上层界面后恢复。

## 7. 运行输出、子 Agent 和性能

底部【运行输出／工具活动】显示当前会话的模型输出、工具活动、重试和停止状态。运行中的会话会显示运行指示；需要中止时点击【停止】，并保留错误消息、工作区路径和相关 Diff。

有适合拆分的任务时，右侧会出现【子 Agent】面板并按任务需要自动分工。可查看任务目标、运行状态、结果和工程契约，必要时点击【停止】或【终止并保留成果】。当前 Codex/Jinggong 子 Agent 用于受控只读分析；Claude 子 Agent 尚未接入。子 Agent 的结论只作为主 Agent 的输入，不等于测试通过或人工验收。

右侧【执行监控】显示已采集的本轮状态、总耗时、Runtime、Provider、模型、端点标识、工具事件、重试次数、上下文估算和阶段时间线。缺少的指标会明确显示“不可采集”；性能基线需要同任务、代码版本、模型和环境的重复对照，单次耗时不能作为提速结论。

【执行监控 > 分级测试建议与真实证据】中的建议默认是“未执行”。只有点击确认并运行，或在【Git】面板启动真实验证后，才会产生验证记录。

## 8. Git、构建和测试

### 查看变更

右侧【代码变更】查看会话目录相对基准提交的真实 Diff，可展开文件树并打开 Diff 预览。右侧【上下文】查看项目目录、会话目录、适用系统、已启用资料、本机 Git 版本和本地数据目录。

### 运行真实验证

进入【Git】面板的【真实验证证据】，按项目已登记的命令选择【运行构建】、【运行类型检查】或【运行测试】。平台主进程执行实际命令并保存 Run ID、退出码、耗时和报告；Agent 文本不作为验证证据。验证中可以点击【取消验证】，但应等待进程退出并保存报告。

### 提交、推送和拉取

1. 检查 Diff，填写中文提交说明；关联 Jira 的会话会自动补齐任务地址，重复地址不会再次追加。
2. 点击【检查开发要求】，修复阻断项并逐项勾选人工审核内容。
3. 确认真实构建、测试和业务结果后点击【审核并提交】，在系统确认框中再次核对提交说明、Jira 地址和文件范围。
4. 提交只写入当前 `agent/*` 分支。工作区干净后，在【推送当前分支】选择远程并点击【推送分支】。
5. 拉取只接受远程同名 Agent 分支的快进更新；存在未提交改动或分叉时会停止，需人工处理。

提交和推送都需要系统确认。推送不会自动合并到主分支，远程认证需提前在开发电脑配置。

## 9. 设置、插件、记忆和数据

- 【插件管理】：导入和审阅 Codex 插件，查看信任状态、脱敏配置和 Runtime 绑定。当前版本尚未接入 MCP Server 实际连接、健康检查和工具发现；即使保存了 MCP 凭据，也不能视为 MCP 已可运行。
- 【记忆】：查看、导出、导入、手动新增或删除本地记忆。记忆只保留可复用的偏好、约束、决策和经验；不要保存密码、Token 或整段普通对话。
- 【会话与数据】：查看本地数据目录并导出会话备份。备份不包含密钥和代码；代码请通过 Git 或文件备份保存。
- 【更新】：查看版本和更新状态，配置 GitHub 仓库地址或 `latest.yml` 的 HTTPS 目录，选择自动或手动更新。更新地址或网络不可用时，按设置页提示重试。

本机数据默认位于 `%LOCALAPPDATA%\\JinggongAgent`。构建、测试和接口验证报告位于该目录下的 `verification` 子目录，不写入目标项目工作区。

## 10. 常见问题

**项目无法添加**：确认选择的是仓库根目录、Git for Windows 可用且仓库已有提交。

**会话不能发送**：先在当前会话设置选择已配置密钥的中转站；如果项目或会话设置有未应用的修改，先点击【应用设置】。

**识别为错误的系统**：在会话设置中手动选择系统，并确认通用资料和该系统的规范、数据字典已启用。

**项目切换后找不到旧改动**：旧改动仍在原会话工作区；查看会话消息中的恢复路径，或切回原项目会话。

**运行停滞或报错**：查看运行输出和工具活动，记录 Runtime、模型、错误信息、工作区路径和 Run ID，再决定停止或重试。

**Git 提交按钮不可用**：确认存在真实变更、提交说明非空、已完成开发要求检查、人工审核项已勾选，且没有正在运行的任务或验证。

**浏览器页面消失**：检查是否打开了设置、菜单或对话框；关闭后页面会恢复。切换回原会话可找回对应标签和登录状态。

**验证结果显示未执行或证据过期**：按当前代码版本重新运行平台验证，不能把旧报告或 Agent 文本总结当作本次通过。

## 11. 交付前检查清单

- Jira 任务、范围和验收标准已核对。
- 项目、会话、系统识别和 Runtime 选择正确。
- 规范、数据字典和项目外资料范围符合本次任务。
- Diff 已逐文件检查，没有未授权的改动。
- 构建、类型检查和必要测试有真实 Run ID 与报告。
- Jira 地址、提交说明、分支和推送远程已复核。
- 业务负责人已完成最终验收；未把“开发完成”直接当作“生产可用”。
