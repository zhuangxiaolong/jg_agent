# 精工 Agent

Windows 桌面研发 Agent。正式依据为 docs 内三份 V1.1，运行时固定 Codex CLI 0.156.1。无应用服务器、无 localhost API、无 Docker/PostgreSQL/Python 依赖。

V0.6.6 为代码变更文件提供右键 Diff、暂存、取消暂存、撤销和系统编辑器操作，输入区支持图片和普通文件附件，并要求代码修改后的目标项目真实构建、测试和 Markdown 报告。更新说明见 [2026-11-07 更新说明](docs/development/update-notes-2026-11-07-draft.md)，开发人员手册见 [精工 Agent 0.6.6 使用说明](docs/使用说明-0.6.6.md)。

V0.6.5 为关联 Jira 的提交自动附加任务地址，自动生成、手写说明、提交确认框及最终 Git 正文保持一致；已有同一地址不重复添加。包含紧凑布局、右键项目/会话操作、任务栏完成提醒、独立日报日期与图片下载失败仍可创建会话。

V0.6.4 为会话删除增加确认，取消保留、确认后删除会话与消息，代码文件保留。普通与 Jira 开发会话先发布代码修改方案，再允许修改本轮方案中的文件；方案包含目标、逐文件改法、影响风险和验证步骤，只读模式仅提出方案。

V0.6.3 修复删除会话：点击即删除会话与消息记录，不再依赖工作区校验，保留代码文件；旧路径、工作区丢失及存在未提交代码均可删除。

V0.6.2 新增项目折叠、真实版本号及可编辑更新地址、自动会话记忆、完成蓝点与更易拖动的面板/输入框，日常消息隐藏内部兼容通知。104 项模块测试与 16 类真实 Electron 桌面检查通过。

V0.6.1 在 V0.6.0 基础上取消 Agent 整轮 30 分钟硬超时，新增设置内自动/手动更新及手动检查/下载入口，项目和会话支持删除并按项目分组展示。Jira 关联会话创建时会缓存图片，首轮 `turn/start` 将图片作为原生 `localImage` 上下文；Jira 任务首轮先执行开发条件审查，无法确认的内容会明确警示。101 项模块测试和真实 Electron 桌面回归已通过。旧会话与本地 SQLite/DPAPI 凭据继续保留。更新发布流程见 [.github/workflows/release.yml](.github/workflows/release.yml)：将 `v0.6.2` 或后续版本标签推送到仓库后，GitHub Actions 会构建 Windows 安装包并发布 Electron 更新清单。

实际用户 Jira 也已验证：按 `Asia/Shanghai` 的 2026-11-05 自动查询成功返回 0 条，并保存真实本地记录；中央会话、右侧 Jira 和底部面板同时可见，原2项目、4会话及配置/事件保留。该结果只对应当天默认筛选，不代表账号没有其他任务；无会话创建、模型请求或 Jira 写入，见 [real-workspace-v050.json](test-results/real-workspace-v050.json)。隔离合成接口的35类验收与此次真实只读验证分别记录。

## 开发运行

开发机需要 Windows x64、Node 24、npm 和 Git for Windows。最终安装用户不需 Node。

```powershell
npm ci
node node_modules/electron/install.js
node scripts/stage-runtime.mjs
npm run build
npm test
npm run test:desktop
npm start
```

本机 npm 策略如跳过 Electron 安装脚本，第二条命令会从官方源准备 Electron。没有全局环境变量或软件升级。

## 安装包

```powershell
npm run dist
```

安装后即使精工 Agent 主窗口和托盘进程已经退出，也可以直接调用 `resources\runtime\jinggong-agent.cmd` 使用随包 Codex CLI。命令包装器会读取精工 Agent 已保存的第一个模型配置和 DPAPI 密钥，不会启动主界面；例如：

```powershell
& "$env:LOCALAPPDATA\Programs\jinggong-agent\resources\runtime\jinggong-agent.cmd" exec --full-auto "检查当前目录并给出修改方案"
```

开发环境可使用 `npm run cli -- --version` 验证无窗口 CLI 入口。主程序退出后，CLI 仍是独立进程；关闭 CLI 命令不会重新打开精工 Agent。

本次安装包使用独立输出目录生成于 `release-v066/JinggongAgent-Setup-0.6.6-x64.exe`。在线更新可在设置中选择自动或手动；自动模式启动后静默检查并后台下载，手动模式由“检查更新/下载更新”触发，下载完成后“重启并更新”会安静退出、覆盖安装并重新启动，不需要手动卸载或运行安装包。自动检查/安装要求通过签名检查的发布包；本地未签名包会在设置中显示未配置更新签名。

V0.4 支持项目显示名称、会话别名与推理强度、新主题、Jira 本地记录与图片、Git 快进拉取及系统托盘。V0.4.1 兼容真实 JPEG 被错标 PNG 的附件，按结构去除 EOI 后有界尾内容，仅规范化本地缓存，不改源附件；真实安装版五图已显示并在重启后保持缓存 SHA256 一致。生产菜单经 Menu.popup 弹出后的原生鼠标打开/退出已通过，未直接点击系统托盘图标。推理档位实际支持由模型和中转站决定，本地 Runtime 协议通过不代表真实视觉模型已执行。

## 使用

全局设置可管理外观、多个模型中转站与模型列表、Jira 域名/账号/密码、本地记忆、按 MES5/MES6/WMS 分类的数据字典。每个会话在会话标题下的模型栏或输入框模型标签中单独设置中转站、模型、系统、开发/只读模式和推理强度。外观默认深色；完成声音可选清脆、明亮、柔和或关闭，也可试听。独立“开发要求与规范”入口支持上传文件、直接输入与编辑标题和完整正文、查看、启停及删除。模型需要兼容 HTTPS Responses API 与流式工具调用；凭据由用户独立配置，应用不读取现有 Codex 登录。

Jira 连接支持 HTTP/HTTPS 和项目页地址自动归一，项目 Key、日报日期字段可设置。V0.3.2 增加项目范围选择，默认“全部可访问项目 + 日报日期 + 仅我的任务”，也可选择具体 Jira 项目、取消本人筛选或查询不限日报日期的最近任务。“全部可访问项目”仍受当前账号权限和其余筛选条件约束。查看需求与附件清单后可关联本地项目创建会话，任务快照带入 Agent 上下文，由用户点击发送。V0.4 增加图片的受控下载、缓存预览与会话原生输入；非图片附件当前仍仅展示来源元数据，通用下载解析另行验收。

旧查询固定在 `NEWDEVGROUP`，此前该项目的一条任务诊断不能代表全账号情况。V0.3.2 真实安装版使用原保存凭据读取到 171 个可访问项目；在 2026-11-04、仅本人条件下，全部项目和 `CD` 均返回截图中的 2 条目标任务，`NEWDEVGROUP` 返回 0，切回全部项目仍为 2。两条任务详情概要与 API 一致，分别显示 2/3 条附件元数据，旧查询条件改变后禁止继续操作旧结果。证据 `test-results/real-jira-installed-v032.json`；未新增用户会话或写入设置，模型请求和 Jira 写入均为 0。会话创建与重启持久化使用隔离的合成 Jira/真实 Git/SQLite 验证，不代表用户生产仓库或模型开发已验收；十个工作日人工核对仍未完成。详见 [V0.3 Jira 联调记录](docs/development/v0.3-jira-requirements.md)。

选择有提交的本地 Git 仓库并创建会话，应用建立独立 Worktree，默认“隔离开发”；旧只读会话保持原模式。新会话会根据仓库代码指纹自动识别 MES5、MES6 或 WMS，并加载对应已启用数据字典。项目与会话按项目分组，项目可改名/删除，会话可改别名/删除；点击删除会话先弹出确认，取消则保留；确认后移除会话与消息记录，保留代码文件，不受旧路径或工作区丢失影响。开发任务先在会话中发布“代码修改方案”，列明目标、逐文件修改方式、影响风险和验证计划，才允许修改方案中的文件；扩大修改范围时先更新完整方案。阅读历史消息时滚动位置会保持；停在底部时才自动跟随新输出，可用“回到最新消息”恢复跟随。Agent 输出支持标题、列表、引用、代码块、表格和路径高亮。右侧 Jira 按账号时区当天自动读取本人任务，与中央会话同时使用；左侧、右侧和底部面板支持拖动调节尺寸，也可通过顶部按钮隐藏恢复，布局保存在本机。开发要求会完整注入每轮上下文、写入前运行机器规则；提交自然语言要求需开发者逐份人工复核。Runtime 不设置整轮运行时限，只有协议终态或人工停止结束任务。Jira 关联会话创建时缓存图片，发送首轮会把图片作为原生模型上下文；Jira 任务会先做开发条件审查，无法从任务、代码、字典和规范确认的内容会列出明确问题并停止修改。

右侧 Git 页可查看最近 50 条记录、按真实 Diff 生成中文提交说明、检查开发要求、提交和推送当前 agent 分支。提交和推送由用户点击并确认，不自动操作主分支；推送支持已可无交互认证的 SSH 与本地 Bare 仓库，HTTPS 凭据接入尚待完善。

资料支持 UTF-8 MD/TXT/JSON/CSV/SQL、DOCX 和 XLSX。V0.2.1 修复大型数据字典导入：允许用户选择的普通硬链接文件作为只读快照来源，支持合法的样式空单元格；字典上限为 200 万字符、25 万单元格、256 个工作表和 32 MiB 文件。来源不写入，正文完整保存至 SQLite；分页和关键词检索用于查看全文。SQL/CLR 结构中的 Password 等字段名可作为字典元数据，真实凭据赋值和密钥仍拒绝。

字典通过 `search_dictionary` 检索和 `read_dictionary` 偏移分块工具按需读取，只开放当前适用系统和已启用资料；上下文保留目录与来源说明。开发要求仍保持单份 8 万字符及完整注入，JSON 机器规则会阻断违规写入与提交，自然语言要求提交前需人工逐份复核。动态工具协议、桌面断管错误处理及安装版实际导入复测已通过，结果见 [V0.2.1 字典修复记录](docs/development/v0.2.1-dictionary-fix.md)。一般使用方式见 [设置和受控开发说明](docs/architecture/settings-and-development.md)，本次版本的完整操作步骤见 [精工 Agent 0.6.5 使用说明](docs/使用说明-0.6.5.md)，容量变更以 V0.2.1 记录为准。
